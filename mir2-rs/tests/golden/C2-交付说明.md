## 2. 做法（不动客户端、不动 oracle）

```
tools/capture/clienthook/
  Mir2ClientHook.dpr   注入客户端的 DLL（Delphi/Win32）
  Inject.dpr           注入器（OpenProcess→VirtualAllocEx→WriteProcessMemory→CreateRemoteThread(LoadLibraryA)）
  build.ps1            dcc32 构建（Delphi 10.4，与 E:\MirServer\build-client-104.ps1 同一套 BDS）
```

- DLL 在**主模块（MirClinet.exe）的导入表**里就地改写 `wsock32.dll` 的
  `send` / `recv` / `connect` / `closesocket` 四个 IAT 槽位为其 detour，记录原始字节后转调原函数。
  不 inline hook（不改指令、不拷贝 prologue），风险面最小。
- 客户端二进制**未被修改**：`D:\MirClient-run\MirClinet.exe` sha256
  `c3cb8f73d8872c5ad3e53f0f55a96d03139fb49397ebcacb4b3573c3e1c07996`、mtime 2026-10-10 0:55（早于本批）。
- oracle 二进制/配置未动：网关 2026-10-09 01:18、`M2GameSvr\M2Server.dll` 2026-10-10 00:10（与 §13.1 复核一致）。
- 探活全部被动（`IPGlobalProperties.GetActiveTcpListeners()`），**全程没有 TCP 连过网关**（避免幻影用户 → GameSvr NRE）。
- 输出目录由环境变量 `MIR2_HOOK_OUT` 传入（DLL 启动时读取），产物与 `mir2_proxy.py` **同构**
  （`chunks.ndjson` + `conn-*.bin`），因此 `segment_frames.py` / `GoldenExport` / `verify_golden.py` 一行未改即可复用。
- 就绪标记 `hook-ready.flag`：拿不到就**直接失败**（`mir_flow.ps1` 会 throw），不让空 dump 混过去。

**结论**：小退这一阶段在当前授权边界内（不改 oracle 配置、不改客户端、不给 GM 权限）拿不到。
它是**唯一缺的一格**，不是抓包工具的问题：同一轮抓包里其余七阶段齐全，①②（逐字节/字段）在 A 线 replay 下仍然可验。
解除判据（任一即可，均属 oracle/owner 侧）：a) 开放 `AutoLogin.txt` 之类的自动登录以做出"真人点确认"的时序；
b) 给测试账号 GM 权限以触发换服/踢线；c) 把客户端确认框的坐标/时序做成可注入的自动化钩子（等于允许改客户端，本批禁止）。

### 本轮新踩到的三个坑（都已修进工具，供后续复现时避让）

1. **角色状态有"两份真相"**：建角失败报 `SM_NEWCHR_FAIL` 且 `Recog=3` = 账号角色数 ≥2
   （`DBSrv/Services/Impl/UserService.cs:622`），而计数来自 **`characters_indexes`**（启动时载入内存的快速索引，
   `Storeages/DBSvr.Storage.MySQL/PlayRecordStorage.cs:210`）。只删 `characters` 行（DB 看是 0 个角色）
   不会改这个计数 ⇒ 必须**同时清 `characters_indexes` 并按 oracle 的方式整栈重启**，否则建角恒失败。
   （这也是 §5.1 那句"`characters_indexes` 的列名像索引、实际兼作状态标记"的现场版。）
2. **注入时机**：窗口一出现就注入会把客户端搞崩（WinSock/渲染还没起全）；固定等 14s 的节奏稳。
   另外"脚本里设 env 再 Start-Process"偶发继承不到（DLL 读到 `env=[]`）⇒ 现在 DLL 支持
   **同目录 `hook.conf`** 作为第二来源（流程会写），彻底不依赖进程环境。
3. **窗口句柄会换**：客户端切场景/重建渲染设备后主窗口句柄失效，旧句柄下 `GetWindowRect` 给无效矩形、
   `New-Object Bitmap` 直接抛 `Parameter is not valid` ⇒ `Shot()` 现在每次都重取句柄。

### 附：A-8（① 的 33 条）取证结论（C 线，2026-10-10）

A 线请我核两件事，结论如下（工具：`tools/capture/probe_frame_boundaries.py`，可直接复跑）：

1. **帧边界是真的，不是抓包切帧产物** ✓：382 帧里**没有任何一帧包含多余的 `!`**；
   把切帧规则换成更严的"`!` 之后必须是 `#`/`$`/EOF 才算帧尾"后，**8 条流上的帧数与长度分布逐条一致**
   （含 game 跳 329 帧）⇒ 差异只能在协议/编码侧。
2. **多段体候选 40 帧（全部 s2c）**，分两类：
   - **9 帧 ident=10**，编码体 41/49 字符 —— 即 A 线已建表的 `SM_TURN` 族（`StructThenRest{8}`）；
   - **31 帧"短帧"**：形态固定为 `#+GD/<9~10 位数字>!`，**周期 ≈1.75s**，用 C# oracle 解码得 **9 字节**明文，
     前 6 字节恒定（`1F 83 64 41 58 51`）、后 3 字节随数字变化 ⇒ **完全没有 12B `CommandMessage` 头**。
     它走的是网关的"小包直发"路径（`src/GameGate/Services/ClientSession.cs:898` 的 `bufferLen < 0` 分支：
     `'#' + message.Buffer + '!'`），发送侧用 `ServerSessionMessage` 的**负 `BuffLen`** 约定表达"小包"。
     **发送点我没能定位到具体行**（GameSvr 侧的取负处没 grep 到），这条交回 A 线按 ident/周期去 GameSvr 找。
     按 A 线的线索（客户端对解码后 < 16B 的帧直接忽略）它属于客户端**不会处理**的帧 ⇒ 归"无头短帧/忽略"即可。
3. **给 A 线模型的一个提醒**：判"多段体"用 `编码体长度 ≡1 (mod 4)` 时，**c2s 帧要先剥掉字面量 `#1` 前缀再量**
   （12B 头无体的 c2s 帧编码体正好 16 字符 ≡0）。本次若把 `#1` 计进去，会把 38 条 c2s 单段帧误判成多段体。
