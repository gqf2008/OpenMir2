# C2 交付说明：客户端进程内 dump（关键路径）

> 批次任务见设计文档 §13.5（C2：客户端侧 dump 实现 + 重抓金标准，补齐 8/8 阶段）。
> 上游背景：上批金标准只覆盖 5/8，根因是**影子网关把 oracle 网关挪到 17xxx**，
> 而 GameSvr 按网关端口对齐进世界路由 ⇒ 世界数据下不来。本批改走**客户端进程内 dump**：
> 客户端直连真实 7000/7100/7200，拓扑不变、不碰 oracle。

## 2. 做法（不动客户端、不动 oracle）

```
tools/capture/clienthook/
  Mir2ClientHook.dpr   注入客户端的 DLL（Delphi/Win32）
  Inject.dpr           注入器（OpenProcess→VirtualAllocEx→WriteProcessMemory→CreateRemoteThread(LoadLibraryA)）
  build.ps1            dcc32 构建（Delphi 10.4，与 E:\MirServer\build-client-104.ps1 同一套 BDS）
```

- DLL 在**主模块（MirClinet.exe）的导入表**里就地改写 `wsock32.dll` 的
  `send` / `recv` / `connect` / `closesocket` 四个 IAT 槽位为其 detour，记录原始字节后转调原函数。
  不 inline hook（不改指令、不拷贝 prologue），风险面最小。
- 客户端二进制**未被修改**：`D:\MirClient-run\MirClinet.exe` sha256
  `c3cb8f73d8872c5ad3e53f0f55a96d03139fb49397ebcacb4b3573c3e1c07996`、mtime 2026-10-10 0:55（早于本批）。
- oracle 二进制/配置未动：网关 2026-10-09 01:18、`M2GameSvr\M2Server.dll` 2026-10-10 00:10（与 §13.1 复核一致）。
- 探活全部被动（`IPGlobalProperties.GetActiveTcpListeners()`），**全程没有 TCP 连过网关**（避免幻影用户 → GameSvr NRE）。
- 输出目录由环境变量 `MIR2_HOOK_OUT` 传入（DLL 启动时读取），产物与 `mir2_proxy.py` **同构**
  （`chunks.ndjson` + `conn-*.bin`），因此 `segment_frames.py` / `GoldenExport` / `verify_golden.py` 一行未改即可复用。
- 就绪标记 `hook-ready.flag`：拿不到就**直接失败**（`mir_flow.ps1` 会 throw），不让空 dump 混过去。

## 4. 小退（1009 / 528 / 802）没拿到：三条路都试过、都被堵住

| 路 | 结果 | 证据 |
| --- | --- | --- |
| ① 客户端 Alt+X → 确认框 → `CM_SOFTCLOSE(1009)` | **堵住**：合成按键打不开确认框。`keybd_event` 与 `SendInput`（虚拟键版，`wVk=0x12`/`0x58`）各试多轮，截图里确认框从未出现；按键本身能到达客户端（早前一轮 X 曾落进聊天框发出 `CM_SAY(3030)`），但 Alt 状态没被客户端读到、且输入框聚焦时会吃掉字符 | `07_logout_altx*.png`、`07_logout_try*.png`、`07_logoutdlg.png` 三轮截图；抓包里始终无 1009 |
| ② 同账号再登录（顶号）→ `SM_OUTOFCONNECTION(528)` | **堵住**：顶号确实发生（BotSrv 用同账号 `loadbot0` 登进世界，同角色），客户端也弹了"当前账号已在其他地方登录，该机已被强行踢下线"，但服务端**只发了系统提示文本、没有 528 帧**，随后直接断链 | `tests/botload/bots-*.log`（`选择角色 lb0b`/`进入游戏`）+ 该轮抓包 `06b_after_kick.png` + 抓包里无 528 |
| ③ `SM_RECONNECT(802)` | **堵住**：只在多服务器"换服"时发（`src/GameSrv/Word/WorldServer.cs:1065 SendChangeServer` → `GetMultiServerAddrPort`），本部署单服，触发需要 GM/脚本动作 | 源码行 + 抓包里无 802 |

**结论**：小退这一阶段在当前授权边界内（不改 oracle 配置、不改客户端、不给 GM 权限）拿不到。
它是**唯一缺的一格**，不是抓包工具的问题：同一轮抓包里其余七阶段齐全，①②（逐字节/字段）在 A 线 replay 下仍然可验。
解除判据（任一即可，均属 oracle/owner 侧）：a) 开放 `AutoLogin.txt` 之类的自动登录以做出"真人点确认"的时序；
b) 给测试账号 GM 权限以触发换服/踢线；c) 把客户端确认框的坐标/时序做成可注入的自动化钩子（等于允许改客户端，本批禁止）。

## 5. A 线 replay 在本抓包上的判读（我在本机跑过一次）

```
frames: 222（其中纯字符串帧 1）
byte mismatches (①): 56        ← 见下，**新发现**，不是抓包问题
field mismatches (②): 0
unknown idents: 4（84 / 1200 / 10431 / 10433）
stage coverage (③): 8 阶段命中 7，缺 小退
RESULT: RED
```

- ① 的 56 条集中在 **s2c、game 跳**的 `ident=10`（9 条样例）与 `ident=811`（1 条样例），
  `body_len` 14~62；**②（字段对拍）全过** ⇒ 解码侧一致，差异出在**编码侧**（C# 服务端对这批
  payload 的编码与 Rust 侧 re-encode 不等价）。上批金标准 game 跳只有 445B 公告，没暴露这条；
  本批 210 帧 game 跳把它打出来了 —— 这正是"金标准当判官"的价值。建议 A 线按 seq 30（ident=10、
  body_len 24、raw 51B）复现，看 C# `EncryptUtil.Encode` 在特定数据上是否有 Rust 侧未复刻的细节。
- 4 个 unknown idents（84 / 1200 / 10431 / 10433）是客户端侧发/收的号（同 3501 一类的 `client_only` 处理）；
  `84` 与 `81` 一样出现在进世界后的自动查询序列里。
