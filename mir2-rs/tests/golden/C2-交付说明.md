## 2. 做法（不动客户端、不动 oracle）

```
tools/capture/clienthook/
  Mir2ClientHook.dpr   注入客户端的 DLL（Delphi/Win32）
  Inject.dpr           注入器（OpenProcess→VirtualAllocEx→WriteProcessMemory→CreateRemoteThread(LoadLibraryA)）
  build.ps1            dcc32 构建（Delphi 10.4，与 E:\MirServer\build-client-104.ps1 同一套 BDS）
```

- DLL 在**主模块（MirClinet.exe）的导入表**里就地改写 `wsock32.dll` 的
  `send` / `recv` / `connect` / `closesocket` 四个 IAT 槽位为其 detour，记录原始字节后转调原函数。
  不 inline hook（不改指令、不拷贝 prologue），风险面最小。
- 客户端二进制**未被修改**：`D:\MirClient-run\MirClinet.exe` sha256
  `c3cb8f73d8872c5ad3e53f0f55a96d03139fb49397ebcacb4b3573c3e1c07996`、mtime 2026-10-10 0:55（早于本批）。
- oracle 二进制/配置未动：网关 2026-10-09 01:18、`M2GameSvr\M2Server.dll` 2026-10-10 00:10（与 §13.1 复核一致）。
- 探活全部被动（`IPGlobalProperties.GetActiveTcpListeners()`），**全程没有 TCP 连过网关**（避免幻影用户 → GameSvr NRE）。
- 输出目录由环境变量 `MIR2_HOOK_OUT` 传入（DLL 启动时读取），产物与 `mir2_proxy.py` **同构**
  （`chunks.ndjson` + `conn-*.bin`），因此 `segment_frames.py` / `GoldenExport` / `verify_golden.py` 一行未改即可复用。
- 就绪标记 `hook-ready.flag`：拿不到就**直接失败**（`mir_flow.ps1` 会 throw），不让空 dump 混过去。

### C4 补记（同批自查发现并修）：入库的 C2 曾是 C4 之前的旧 schema

- **现象**：用当前导出器重导 C2，结果与**入库的** `c-line-baseline-c2-20261010.jsonl` 不同 —— 入库件缺
  `frame_form` / `layout` / `body_segments` 三个 C4 新字段（它是 C2 批的旧导出，C4 只重导了上批与 C3）。
  登记 sha256 当时是对的（= 那个旧 blob），所以**登记与 artifact 自洽、但 artifact 与文档口径不自洽**。
- **为什么必须修**：拿旧件跑当前 `replay` 会给出**假红** —— ② 21 条（分段体按旧口径解）+ act 帧
  "body 口径与导出器不符 66 条"（旧件没标 `frame_form:"act"`）。② 21 条正是本批声称"已归零"的那批，
  于是"同一份金标准，文献说 0、实测 21"。
- **纠偏**：按当前导出器重导并覆盖入库件，重登记 sha256：
  `bcb9e483…` → **`012a2aa5…`**；重跑 replay ⇒ ② **21→0**、act 口径假红 **66→0**、① 仍 2（= C3 同源）。
  裸 dump 未动（`verify_golden.py` 对 C2 会话仍 GREEN：222 帧 / 6 流全对账）。
- **教训（已沉淀）**：**改了导出器口径就必须重导并重登记**，只改登记行/只重导一部分抓包，
  会让下游对新口径产生假红或假绿 —— 这次是"旧 artifact + 新 replay"。

### C4 续（2026-10-10）：第三种布局 `Segmented` 按 A 线冻结契约实现（表项待 A4 落地）

- **契约**（A 线冻结）：`BodyLayout::Segmented { seg_len, sep, trailing_sep, count: SegCount::Fixed(n) | HeaderSeries }`；
  体 = 各段明文按序拼接、不含分隔符。派生 JSON 键：`{"layout":"segmented","seg_len":N,"sep":47,
  "trailing_sep":bool,"count_kind":"fixed"|"header_series","count":N}`。
- **派生侧**（`dump_body_layout.py`）：新增 `Segmented` 分支解析；**见到该变体却解析不出来就报错**
  （不许静默少一档，免得导出一张缺项的错表）。
- **导出器侧**（`BodyLayoutTable.cs`）：`segmented` 切法**按表算长度逐段取**（`enc(seg_len)` 步进 + 校验分隔符/尾分隔符/总长），
  **不按分隔符盲切**（编码字表里也有 `/`，盲切会切错且悄无声息）；`count_kind=header_series` 时段数取该帧头的 `series`。
  任一处对不上 ⇒ `layout="segmented(mismatch:…)"` 且**导出器退出码 4**（改错段边界必红，不许静默出表）。
  另加 `--verify-roundtrip`：把切出的段各自**再编码**拼回去，必须逐字节等于线上原体（退出码 5 若不符）。
- **实测**（`python tools/capture/segmented_check.py`，用 C3 裸 dump 的真实帧 + 冻结契约）：
  `811 → body_len 60 / 段 [20,20,20]`、`201 → body_len 496 / 段 [124,124,124,124]` —— 与 A 线给的期望值一致；
  `--verify-roundtrip` 全过（段边界可证：拼回 = 原字节）；`seg_len 20→19` ⇒ rc=4 + `segmented(mismatch:sep@0)`；
  同 dump 两次导出逐字节相同。**表项落地后**重跑派生即可，预期 ① 2→0。
