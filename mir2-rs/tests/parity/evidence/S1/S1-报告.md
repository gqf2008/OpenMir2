## 1. 缺陷① 复现与根因

### 1.1 触发序列（改前实测）

```
16:45:49 [ERR] 游戏网关[127.0.0.1:52510]已关闭...      ← GameGate 连接断开（抖动注入：只重启 GameGate）
16:45:51 [INF] 游戏网关[127.0.0.1:54096]已打开...      ← 新连接：SocketId 由 1 变成 2
16:46:09 [INF] 新用户链接...                            ← 客户端进世界
16:46:10 [ERR] [Exception] WorldServer::ProcessHumans -> Ready, Save, Load...
        at M2Server.Net.ChannelMessageHandler.SetGateUserList(...) ChannelMessageHandler.cs:line 472
        at GameSrv.Word.WorldServer.ProcessHumans() WorldServer.cs:line 564
16:46:10.586 [ERR] ...（每 ~200ms 一条，直到客户端被踢）    ← 死循环
```

原始摘录：`before/gamesvr-nre-excerpt.txt`（`SetGateUserList` 在该段日志里出现 **156** 次）。

### 1.2 两条独立故障链（同根因）

- **世界→网关下发被静默丢弃**：`PlayObject.Socket` → `AddGateBuffer(playObject.GateIdx, …)` 打到
  已断开的旧槽位；`ChannelMessageHandler.ProcessBufferSend` 见 `!BoUsed && Socket == null` 直接
  `return` ⇒ 客户端收不到世界数据 ⇒ **黑屏**（截图非黑占比 **0%**）。
- **进世界 NRE 死循环**：`WorldServer.ProcessHumans`（每 200ms）把 `NewHumanList` 里的玩家
  `SetGateUserList(playObject.GateIdx, …)` ⇒ 旧槽位的 `GateInfo.UserList == null` ⇒ NRE。
  该异常被 `ProcessHumans` 的 catch 吞掉并打日志，`NewHumanList` 又没被清掉 ⇒ 每 tick 重来，
  玩家永远进不去；而世界侧仍认为这个 session 存在 ⇒ **之后每次登录都失败**，直到重启 GameSvr。

### 1.3 根因

槽位下标有两个互不相干的来源：

| 用途 | 来源 | 抖动后 |
| --- | --- | --- |
| 收包路由（`Received`）与槽位分配（`Connecting`） | `int.Parse(socketClient.Id) - 1` = **第几条 accepted 连接** | 变成 1（原为 0） |
| 世界侧寻址（`AddGateBuffer`/`SetGateUserList`/`CloseUser`） | 客户端认证串里网关自报的 `sGateId`（GameGate 的 `ServiceId`，本部署恒为 0） | 不变，仍是 0 |

两者只在"冷启动、单网关、从不重连"时重合。`CloseGate` 又把旧槽位的 `UserList/Socket` 置 null
却不释放槽位 ⇒ 槽位 0 变成一颗"地雷"：世界侧所有寻址都踩它。

## 2. 固定方案（`src/**` 改动，见 T-2）

1. **`TCPNetChannel` 新增 `_gateSlotByConnection`（连接 SocketId → 槽位）**：
   - `Connecting`：按**最小空闲槽**分配（不是 accept 序），并登记映射；
   - `Received`：按连接查槽位（查不到直接丢弃），不再 `int.Parse(SocketId)`；
   - `CloseGate`：清完用户后**释放槽位**（`_gameGates[i] = null`）并摘掉映射；
   - 收包线程取到空槽改为丢弃 —— 释放槽位后**不能让收包线程抛异常**（那会让所有网关一起哑掉）。
2. **世界侧入口加守卫**：`SetGateUserList` / `AddGateBuffer` / `CloseUser` 统一走 `GetGate(gateIdx)`
   （越界或已释放 → 安全丢弃）。`gateIdx` 来自客户端认证串、可被脏数据置成任意值，原实现
   `_gameGates[gateIdx]` 对越界值会抛 `IndexOutOfRangeException` —— 这条顺手一起堵掉（同一根因面）。
3. **`ChannelMessageHandler.SetGateUserList` 加 `GateInfo/UserList` 前置守卫**（与 `CloseUser` 对称），
   作为纵深防御：即使将来又出现指向已释放槽位的调用，也不会在世界线程里炸。

### 2.1 行为等价性论证（为什么它不是"顺手改行为"）

- 槽位分配在**不抖动、单网关**时给出与改前完全相同的结果（连接 1 → 槽位 0）。
- `CloseGate` 的可观测差异只有两处日志：多网关时不再因越界/空槽抛异常；`Socket == null`
  的重复关闭分支不再提前 `return`（该分支在改动后不可达：释放槽位后第二次关闭找不到映射）。
- 世界侧入口从"抛异常/静默丢弃"变成"静默丢弃"——异常那侧本来就是缺陷。
- **残留边界（诚实登记）**：多网关配置下若各网关**不按自己声明的编号顺序**重连，
  "最小空闲槽"仍可能错配。改前同场景是**必错且必 NRE**，所以不是回归；本部署只配一个
  GameGate，不构成实际差异。真正的通解要把"网关声明的编号"绑定到槽位（需在认证串里
  多带一层信息），属协议层改动，不在 S1 范围。

| 目录 | apphost | 宿主 | runtimeTarget |
| --- | --- | --- | --- |
| `Mir200` | `GameSvr` | **Mach-O** | `.NETCoreApp,Version=v6.0` |

### 5.3 改后（`after/reconcile.md`）
