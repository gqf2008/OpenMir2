### 4.2 原始输出 + 路径 + hash

**hash 口径（评审 N-1）**：`SHA-256(文件字节，先把 CRLF 归一为 LF)` ==

裸 `sha256sum` 会得另一个值。清单是唯一权威：

## 5. 残留物清单（诚实登记）

1. **② 商店 / 修理 / 仓库 3 条用例：两条路线都不可跑（已机判登记，不是已完成）**。
   本片在 2026-10-12 窗口轮到 m4cases 时**实跑复现并机判**（`tests/parity/M4/npc_window_readiness.py`，
   证据 `evidence/M4/npc-window-readiness.txt`，`selftest 5/5`）：
   - **port-free 路线**：C# 夹具 `tools/script-parity-cs` 的 NPC 代理是 `INormNpc` 的 DispatchProxy，
     而脚本首行含商人头 `(@buy/@sell/@storage …)` ⇒ 参照 `ScriptParsers.cs:713/733/763` 的
     `((IMerchant)NPC)` 实跑必抛 `InvalidCastException`（门复现三例；`@changeGold` 定位 line 713、
     `@zum_bind1` line 733、`@StdModeFunc26` line 763）。
   - **两侧真栈路线**：Rust `bins/game-svr` **没有** NPC/商人脚本派发——源码内无
     `CM_CLICKNPC`/`CM_MERCHANTDLGSELECT`，`Cargo.toml` 无 `mir2-script` 依赖，
     `main.rs` 只派发 `CM_SAY`/`CM_PICKUP`/`CM_DROPITEM` ⇒ 同一输入在 Rust 栈上**不产生脚本副作用**，
     拿不到「两侧 diff = 0」。
   - **Rust 脚本引擎本身能跑这三条**（`script-tool flow-run` 实测：`@changeGold` →
     `gold -1002000 / additem 金条 1`；`@zum_bind1` → `delitem 地牢逃脱卷 6 / additem 地牢逃脱卷包 1`；
     `@StdModeFunc26` → 无副作用）⇒ 缺的是**夹具 / 接线**，不是引擎。
   - 承接（二选一，均需 owner 裁）：① 授权改 `mir2-rs/tools/script-parity-cs/**`（给 NPC 代理补
     `IMerchant`；写集外）；② 另开卡给 `bins/game-svr` 接 NPC 脚本派发 + `mir2-script`（M2/M3 接线面）。
   两条前置都满足前，`npc-cases.txt` 的这 3 条**保持 PENDING WINDOW，不许标绿**；门会把「未满足」
   判成 `BLOCKED`（退出码 3），只有两路都齐才 `READY`（退出码 0）。
2. **宏展开 C# 侧无计数器**：C# 参照实现不暴露常量替换次数，① 表中 C# 列取语料事实值 0
   （`corpus-directives.txt`：语料无 `#DEFINE`/`#INCLUDE`/`#SETHOME`）；展开**效果**由结构摘要
   逐字节比对代偿（边界语料已钉住）。这是 harness 观测面限制，非两侧行为差异。
3. **`tools/script-parity-cs` 的 `IMerchant` 缺口**（写集外，未改）：若后续要让商店/修理/仓库
   走 port-free 对拍，需要给该夹具补 `IMerchant`（本卡按 ⑤ 不扩写集，交由 owner 决定另开）。
