## 本轮判据抓到的真问题：客户端独有号 3501

第 1 帧（c2s，login 跳）ident = **3501**，服务端消息号表（`Messages.cs`）里没有这个号 ⇒ 触发"未实现包号"判据。
追查（两侧源码）：

- 客户端：`CM_QUERYDYNCODE = 3501`（`MirClient/Source/Common/Grobal2.pas:1264`），
  在 `g_ConnectionStep = cnsIntro` 发送，体 = `EncodeString(g_LoginKey)`
  （`ClMain.pas:16542`）；`g_LoginKey` 默认值是字面量 `"password"`
  （`MirClient/Source/MirClient/MShare.pas:1407`）⇒ 抓包里该帧体 8 字节、sha256 = `5e884898…`（= ASCII `password`）**完全对应，证明抓包确为真客户端流量**。
- 服务端：`src/OpenMir2/Messages.cs` 止于 `CM_SPEEDHACKMSG = 3500`，无 3501；
  LoginSrv 的 `ProcessUserMsg` switch 无此 case ⇒ **静默忽略、不回包**（LoginGate 原样转发）。

处置：新增 `crates/protocol/src/client_only.rs`（登记客户端独有号 + 服务端"忽略"语义），
replay 与集成测试的"未实现包号"判定改为"服务端表 ∪ 客户端独有号"，并加单测钉住
「3501 在服务端表里必须不存在」（若 C# 源将来长出该号，该测试会红，提示走 msgcodegen 重新生成）。
登记后 ③ 的"未实现 = 0"成立。**待 M1 实现网关/LoginSrv 时按 C# 行为忽略该号**。

## 阶段缺口（③ 未满足的部分）与归宿

缺 **移动 / 攻击 / 小退** 三阶段。归因见 C 线交付说明：
**同客户端同栈、不经抓包插桩时进世界是成功的**（`tools/e2e/run_e2e.ps1`，截图非黑像素 98.82%）；
插桩时影子网关被挪到 17000/17100/17200，而 GameSvr 的进世界路由按网关端口对齐
（`!servertable.txt` 给客户端的是 7200）⇒ 端口一挪世界数据下不来。
交付说明给出三条解除判据（均属 oracle/服务端侧，非 C 线工具可自决）：

1. oracle 网关监听端口即对外端口（并把 `!servertable.txt` 与 `AddrTable.txt` 一并指向新端口）；
2. 给 GameGate 另两个 Gate 条目补 `GateAddress2/3`，使 `127.0.0.2` 方案成立（需实测复核）；
3. 或改走"不需插桩"的 dump 方案（oracle 侧支持把客户端协议 dump 到文件）。

**归宿**：解除后同一复现命令重抓 → A 线重跑本判据 → ③ 补齐后 M0 全绿。
在此之前 M0 的状态应记为「①② 已验收、③ 待抓包补齐」，**不得**把本报告读成全绿。
