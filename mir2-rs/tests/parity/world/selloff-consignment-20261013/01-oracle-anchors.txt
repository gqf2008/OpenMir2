## 3.1 F-1 返工（reviewer-5 `request_changes`，Important）：成交成功支**不得**有负重守卫

oracle `ClientBuySellOffItme`（`src/M2Server/Player/PlayObject.Sale.cs:333-361`）的成功支形状：

```
if (IsEnoughBag()) {
    if (this.AddItemToBag(userItem)) { this.SendAddItem(userItem); ... }
} else {
    DropItemDown(userItem, false);
}
```

- `IsEnoughBag()`（`src/M2Server/Player/PlayObject.Base.cs:183-186`）= `ItemList.Count < Grobal2.MaxBagItem`（**只判背包格数**）；
- `AddItemToBag()`（`src/M2Server/Actor/BaseObject.cs:1241-1251`）只判 `ItemList.Count >= MaxBagItem`（**同样不判负重**）；
- `IsAddWeightAvailable` 在 oracle 只出现在：拾取（`PlayObject.Base.cs:103`）、`ClientCancelSellOffIng`（`PlayObject.Sale.cs:217`）、
  `PlayObject.Operate.cs:1680`；**买/卖成交路径没有**。

⇒ Rust `client_buy_sell_off_item`（本仓 `selloff.rs:800` 区域）的 `Some(_)` 支**不得**有负重守卫；
旧 head `438fbd163` 多出的 `if weight_available(me, i32::from(tpl.weight))` 已按 F-1 删除。
**`client_cancel_sell_off_ing`（`selloff.rs:685`）的 `weight_available` 是正确的**（对应 `Sale.cs:217`），不动。

## 4. 队列/出队口径（帧序判据的依据）

`SendAddItem`（`PlayObject.Base.cs:198`）是**立即**帧（`SendSocket(SM_ADDITEM)`，`Series=1`）；
其余 `SendMsg`/`SendUpdateMsg` 入 `MsgQueue`，同一 `Run()` 内按 `(byte)wIdent` **升序**出队（`BaseObject.Message.cs:94`、
`BaseObject.Base.cs:28`），出队时 `RM_*` → `SM_*`。优先级字节：

`RM_SELLOFFADDITEM_OK(23004)=220` / `RM_SellOffADDITEM_FAIL(23006)=222` / `RM_SELLOFFDELITEM_OK(23009)=225` /
`RM_SELLOFFDELITEM_FAIL(23011)=227` / `RM_SELLOFFCANCEL(23013)=229` / `RM_SELLOFFEND_OK(23017)=233` /
`RM_SELLOFFEND_FAIL(23019)=235` / `RM_SELLOFFBUY_OK(23028)=244` / `RM_MENU_OK(10309)=69` /
`RM_GAMEGOLDCHANGED(8084)=148` / `RM_WEIGHTCHANGED(10115)=131` / `RM_SYSMESSAGE(11004)=252` /
`RM_SENDDEALOFFFORM(23000)=152`。

## 6. 未建模 / 残差（登记，不假造）

1. `CustomItemMgr.GetCustomItemName`（`Desc[13]==1` 自定义物品名）：与 `T-24` 同源，本仓
   `bag::item_display_name` 对 `Desc[13]==1` 返回空串 ⇒ 自定义名物品的名字比对走空串。
2. `GameGoldChanged()` → `SendGoldInfo(false)` 的 `SoftVersionDateEx == 0` 门（`BaseObject.Base.cs:930`）：
   本仓由 `SellOffSide::send_game_gold_info` 表示。
3. `WeightChanged()` 的 `WAbil.Weight` 重算仍归 `crate::bag`（本模块只回帧，帧值可能与 oracle 不同）
   —— 与 ⑦-3 `crate::trade` 同口径。
4. `DropItemDown`（`PlayObject.Base.cs:529`）：oracle 因 `MapItem.ItemId` 恒 0 而**恒落地失败**（`T-19`/`T-25`）
   ⇒ `drop_item_down` 只「消耗」、不产帧。
5. `select_sell_date` 无活调用点 ⇒ 实现纯逻辑但不接线；`dSellDateTime` 的本地时区
   `ToString("yyyy年mm月dd日 hh时ss分")` 格式化为占位（`format_sell_date` 返回空串）。
6. `GetSellOffGlod()` 的登录调用点（`PlayObject.cs:1486`）：`SaleDeal` 的 setter 来自脚本
   `OPENYBDEAL`/`ActionOfOpenSaleDeal`（`crates/script` 未移植，`handlers.rs:250`）⇒ 恒 `false` ⇒
   该函数恒 no-op，登录路径**不接线**（行为等价：都不动）。
7. 触发点「脚本 label `@dealybme`/`sDealYBme` → 开窗」（`Merchant.cs:930-934`）：脚本层在
   `crates/script`（不在本卡写集）⇒ `open_deal_off_form` 只落纯逻辑 + 帧，待 ⑩-2/脚本层接线。
