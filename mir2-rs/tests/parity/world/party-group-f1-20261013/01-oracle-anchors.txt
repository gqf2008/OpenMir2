== F-1：oracle `Die()` 的「人物死亡立即退组」==

  :1966-1968         if (SuperMan) return;           // Rust 未建模 SuperMan（本片不动，见「残差登记」）

                     }
  :1979+             掉落的 LastHiter / DieDropItems 等（本片不动）

关键语义（reviewer F-1 原文）：
  * 死亡写入点（Rust = `hp == 0` ⇒ `World::tick()` 的 `settle_deaths`）**立即**调团长 `DelMember(死者)`；
  * 死亡者**仍在线**（与断线 `Disappear` 不同）⇒ 它自己的回帧必须照发，不能复用「已摘 online ⇒ 丢自身帧」口径。

DelMember(死者) 由团长侧执行（`PlayObject.cs:5126-5156`，第①片锚点 §C）：
  * 非团长自己：从成员表找到死者 ⇒ 死者.LeaveGroup() + RemoveAt；
  * 团长自己死亡：从尾到头逐成员 LeaveGroup() + RemoveAt（整组散）；
  * 之后：`if (!CancelGroup()) SendDefMessage(SM_GROUPCANCEL,0,0,0,0); else SendGroupMembers();`
    - `CancelGroup()`（`PlayObject.Base.cs:1339-1352`）：`Count <= 1` ⇒ SendGroupText("你的小组被解散了.")
      + Clear() + GroupOwner=0 + return **false**（⇒ 发 `SM_GROUPCANCEL`）；否则 return true（⇒ 发成员表）。
    - `LeaveGroup()`（`PlayObject.cs:5177-5183`）：SendGroupText("{0} 已经退出了本组.") → 自己 GroupOwner=0
      → SendMsg(RM_GROUPCANCEL(10140))。
  ⇒ 2 人组、成员死亡：`Count==1` ⇒ CancelGroup false ⇒ 团长收 `SM_GROUPCANCEL`；死者收 `SM_GROUPCANCEL`（自身 LeaveGroup）
     + 说词；组散。3 人组、成员死亡：Count>1 ⇒ 组不散、只摘死者，其余成员收成员表 + 死者说词。

与断线的差别（`PlayObject.Message.cs:2138-2142` Disappear 同样调 DelMember）：
  断线路径宿主已把该连接从 `online` 摘掉（Rust `GateEvent::Closed`，main.rs 原 `Disappear→DelMember`），
  死亡路径连接**仍在** `online` 中 ⇒ `drain_party_death_events` 对死者自身也投递。

tick 内相对次序：
  `PlayObject.Run()` 的组队清理段在 `PlayObject.Message.cs:704-719`（消息处理内，`base.Run()` 在 :765）；
  `Die()` 由伤害结算触发、早于该段。Rust：`settle_deaths`（world.tick 内）→ `drain_party_death_events`
  → `party_run_tick`（等价于 oracle 组队清理段），次序一致。

== M-1：`WorldEngine.GetPlayObject(name)` 只扫 `PlayObjectList`（仅玩家）==

Rust 第①片实现（旧 head `party.rs::party_play_object_by_name`）扫的是 `self.entities`（含怪物/NPC，且都带 `name`）
⇒ 用怪物/NPC 名当 `CM_CREATEGROUP`/`CM_ADDGROUPMEMBER` 目标时 oracle 判 `playObject==null` 回 `-2`，
Rust 会误命中并走到 `-3/-4`。本片按 reviewer 建议**至少**加 `Race == Play`（`ACTOR_RACE_PLAY == 0`）过滤。
