# World → bevy_ecs 迁移 · S1 报告（实体存储 + tick 骨架）

卡片：`openmir2-world-bevy-migration`（owner `openmir2-worker-12`，分支 `worktree-world-bevy`）。
本轮只做 **S1**：把 `crates/world` 的**实体存储**与 **tick 骨架**迁入 `bevy_ecs`，
保留既有实体索引 API（薄适配层），**不改语义、不越界到 aoi/combat/session**。

四条硬约束 = 设计文档 §4.2.2；口径 = `D3试验田报告.md` / `P99复测报告.md`。

---

## 0. 结论摘要

- 实体存储：`crates/world` 的 `EntityStore` 改为 **bevy_ecs 内核的薄适配层**；
  内核 `mir2_world_bevy::EcsStore<T>` 用 `bevy_ecs::World` 存组件，用**自己的槽位索引**
  （`slots`/`free`/代际号）决定遍历顺序。
- tick 骨架：`World::tick` 的**时钟推进 + 线程断言**改由单线程 `TickRunner`
  （`Schedule` + `SingleThreadedExecutor`）里的系统完成。
- 依赖方向：`mir2-world` → `mir2-world-bevy`（原 `snapshot_from_world` 适配层已迁到
  `crates/world/src/bevy_bridge.rs`，行为不变，保证无环）。
- 判据不降级：`basic/session/combat` 三份 golden **逐行 diff = 0**（对拍全绿）。
- **P99 已劣化并登记**（见 §4）：P50 中位数 ≈ +67%~+68%、P99 中位数 ≈ +73%~+114%；
  根因是 bevy `World::get` 的「entity→location→table row」间接层落在 AOI 的逐对象
  `store.get` 热路径上。绝对值 P99 ≤ 5.0ms ≈ 200ms 预算的 **2.5%**，M5 目标（≤100ms）仍 GREEN。

## 2. 四条硬约束怎么落实 + 怎么证伪（都实测）

| 约束 | 落实 | 证伪方式 |
| --- | --- | --- |
| ① 单线程 executor | `TickRunner::new` 显式 `set_executor(SingleThreadedExecutor::default())`；`no_parallel.rs` 正面断言 `tick.rs` 出现 `SingleThreadedExecutor` | 见 §5 阳性对照（注入 `thread::spawn` ⇒ 门禁红） |
| ② 遍历顺序显式化 | `EcsStore::iter/iter_mut/order_index/ids_sorted` 全走 `slots`（槽位顺序 = 插入序 + 空闲槽 LIFO）；`Query` 只用于「按句柄取互斥引用」，之后仍按槽位排序；AOI 顺序用 `EcsStore::iter()` | `ecs_migration::entity_order_follows_slots_not_query_order`（删 1 再补 4 ⇒ `[4,2,3]`，Query 序是 `[3,2,4]`）；§5 阳性对照把它改回 Query ⇒ 红 |
| ③ 守卫升级 | `no_parallel.rs` 白名单放宽为「内部 crate + `bevy_ecs`/`bevy_app`」，仍禁 `tokio/rayon/crossbeam/.../bevy_tasks`；源码扫描**剥注释与字符串**；保留 tick 线程断言（facade + 系统双重） | `redcheck_scanner_detects_injected_parallel_code`（自动红检） + §5 手动阳性对照 |
| ④ 原判据不降级 | 三份 golden `diff = 0`；`tick` 时钟/线程/顺序语义不变；P99 见 §4（**劣化已登记**） | golden 对拍（§3）、P99 复测（§4） |

覆盖边界（诚实声明）：源码扫描拦的是「依赖/代码引入并行」；若有人以单线程方式在别处驱动
world，world 内部仍串行，符合 §4.2。

## 4. P99 复测（④：**劣化，登记并说明**）

命令（口径写死于 `crates/world/src/bin/tick_bench.rs` 头注释；`P99复测报告.md §2/§5`）：

```bash
cargo run -p mir2-world --release --bin tick_bench -- 500 2000 1000 2000 2000 1000
```

| 实体数 | 基线 P50 | 本轮 P50（三轮 / 中位数） | P50 中位数劣化 | 基线 P99 中位数 | 本轮 P99（三轮 / 中位数） | P99 中位数劣化 |
| --- | --- | --- | --- | --- | --- | --- |
| 500 | 377 | 630 / 628 / 616 · **628** | **+66.6%** | 576 | 1182 / 994 / 891 · **994** | **+72.6%** |
| 1000 | 840 | 1427 / 1408 / 1390 · **1408** | **+67.6%** | 1195 | 2536 / 2231 / 2182 · **2231** | **+86.7%** |
| 2000 | 1783 | 3051 / 2966 / 2969 · **2969** | **+66.5%** | 2301 | 4932 / 4287 / 4959 · **4932** | **+114.3%** |

判定口径（`P99复测报告.md §5`：P50 劣化 >10% 或 P99 中位数劣化 >30% ⇒ 判回归）：
**本轮判劣化/回归**。绝对值：三档 P99 均 < 5.0ms（200ms 预算的 2.5%），`tick_bench` 退出码 GREEN
（M5 目标 ≤100ms 仍满足）。

**根因（可解释）**：S1 把实体存储从「`Vec<Slot>` 直接索引」换成 bevy `World` 后，热路径的每次
`EntityStore::get/get_mut` 多了一层 `entity → location → table row` 间接；`tick_bench` 的时间
主要花在 AOI（`search_view_range` 对视野内每个对象调用 `store.get`），因此回归与「每 tick 的
`get` 次数」成正比。已做的降本：把额外的「顺序收集 Schedule」从每 tick 热路径移除（只用
`EcsStore::iter` 的显式槽位索引，见 §1），P50 从 ~648 降到 ~620（约 -4%，不足以抵消）。

**处置（请 owner 裁决，同 D3 先例）**：
(a) 接受：绝对代价 ≈ +2.5ms/tick（2000 实体），业务预算 200ms，且这是「内核换 ECS」的既定成本；
(b) S2/S3 再做存储层调优（例如内核缓存 `ComponentId`、或对 AOI 热路径提供批量化读取）；
(c) 若要字面守住「不劣化」，则回退到 §4.2 既有手搓实现（放弃 S1 的 ECS 内核）。

原始输出：`E:\tmp\openmir2-wbevy-s1\p99-s1.txt`。
