## 0. 结论摘要

- S1 的热路径回归根因是两条，且都在 `crates/world-bevy/src/ecs.rs`（写集内）：
  1. 每次 `get`/`iter` 都走 `World::get::<T>`（`TypeId → ComponentId` 查表 + `entity → archetype

  `id → 槽位` 换成 O(1) 稠密数组 [`IdIndex`]（有界兜底 HashMap），`iter_mut` 的 `order_map` 只在
  槽位表变动时重建一次。

  ΔP50 = **−9.0% / +2.3% / −13.2%**，ΔP99 = **−5.4% / +1.2% / −6.0%**（tiers 500/1000/2000）
  ⇒ **GREEN**（P50 ≤ 10%、P99 中位数 ≤ 30%）。
- 三份 golden 逐字节不变（sha256 见 §5）；四门禁全绿（§6）；`no_parallel` 守卫仍绿（§7）。
- **身份交接（已解决，见 §9 / §10）**：`openmir2-worker-12` 的私钥随 13:48 被清理的旧 worktree

## 2. 改了什么（只动 `crates/world-bevy/**`）

`crates/world-bevy/src/ecs.rs`（相对 S1 的 `e6d25d23`）：

1. **缓存查询状态**：新增 `read_state: QueryState<&'static T>` / `write_state: QueryState<&'static mut T>`
   / `pairs_state: QueryState<(Entity, &'static mut T)>`，`get`/`get_mut`/`iter`/`iter_mut` 走
   `get_manual`/`get_mut`；`insert`/`remove` 后 `update_archetypes` 兜底。
2. **O(1) id 索引**：`HashMap<i32, usize>` → `IdIndex { dense: Vec<u32>, sparse: HashMap }`；
   `id ∈ [1, 2^20)` 走数组、范围外（含非正 id）走 HashMap 兜底（内存上界 4MiB）。
3. **`iter_mut` 复用**：`order_map` 只在 `order_dirty`（槽位表变动）时重建；`pairs_state` 缓存后
   不再每次 `world.query`。
4. `Cargo.toml` 注释 Minor 修正（§1）。

**顺序契约不变**：`iter`/`iter_mut`/`order_index` 的顺序仍来自 `slots`（槽位顺序 = 插入顺序 +
空闲槽 LIFO 复用）；`Query` 只用于「按显式句柄安全取组件」，不定序。
**未引并行**：无 `bevy_tasks`/`rayon`/`crossbeam`/`thread::spawn`，tick 骨架仍
`SingleThreadedExecutor`。
