「真机窗口由 root 开；判据/capture 工具你准备」）
本片零起栈、零占游戏端口（仅共享 MySQL 3306 可 UP，只读本份）；零 .rs/.toml/.ps1；只在自身 worktree 写。
====================================================================================================
一句话：窗口手册/规划器里的**站位 SQL 用了不存在的列**（`SET x=…, y=…`），真机执行会
`ERROR 1054 (42S22) Unknown column 'x' in 'SET'`、**角色不移动** ⇒ ③b/③a 两趟都停在旧点位
⇒ 一次性窗口白烧（且很容易被误读成「③ 仍未闭环」）。已订正为真实列
`SET MapName='0', CX=…, CY=…`，并加 G4 机判牙钉死（改回 `x/y` ⇒ 必红）。

A. 根因：`characters` 表没有 `x/y` 列（oracle / 同族夹具口径）
====================================================================================================
[A1] 部署库实测（只读；命令行见 §B）：
     `SHOW COLUMNS FROM mir2_db.characters WHERE Field IN ('MapName','CX','CY','x','y')`
     ⇒ 只有三行：`MapName varchar(10)` / `CX int(11)` / `CY int(11)`；`x`、`y` 不存在。
[A2] 同族夹具早就按真实列写 SQL（本片只是把窗口侧对齐）：
     `mir2-rs/tests/parity/m3/run_pair.ps1:547-554` 用 `MapName='{1}' AND CX={2} AND CY={3}`；
     `mir2-rs/bins/db-srv/src/playdata.rs:93-95` 读 `MapName`/`CX`/`CY`；
     `mir2-rs/bins/db-srv/tests/live_data.rs:249/498/516-517` 插入/读取同一组列名。
[A3] 旧写法在窗口里的后果：MySQL 直接报错、语句原子失败 ⇒ 角色**不会**被移动。
     此后两趟都从旧坐标进世界；若旧坐标不在 MonGen 生成框内（root verify1 就是这种情况），
     ③b 客户端 `pairs=0` ⇒ 极易被误判为「AOI 仍不下发/怪仍未闭环」，就是烧窗口。

B. 硬证据（真机 MySQL，只读/失败语句；ct 2026-10-14）
====================================================================================================
命令（cwd 任意；`--password=` = 空口令，与 `run_pair.ps1:127/372` 同源）：

```
$ D:/mysql/mariadb-10.11.19-winx64/bin/mysql.exe -h 127.0.0.1 -P 3306 -u root --password= \
    --batch --skip-column-names -e "SHOW COLUMNS FROM mir2_db.characters WHERE Field IN ('MapName','CX','CY','x','y');"
MapName	varchar(10)	YES		NULL
CX	int(11)	YES		0
CY	int(11)	YES		0
```
⇒ 无 `x`/`y` 列。

```
$ ... -e "UPDATE mir2_db.characters SET x=605, y=578 WHERE ChrName='aaa';"
--------------
UPDATE mir2_db.characters SET x=605, y=578 WHERE ChrName='aaa'
--------------

ERROR 1054 (42S22) at line 1: Unknown column 'x' in 'SET'
old_rc=1

$ ... -e "SELECT MapName,CX,CY FROM mir2_db.characters WHERE ChrName='aaa';"
0	297	629          # 角色未被移动（语句整体失败）
```
⇒ **真实列**的写法（本片计划现在打印的形态）：
`UPDATE mir2_db.characters SET MapName='0', CX=605, CY=578 WHERE ChrName='aaa';`
（`MapName='0'` 必须一起钉：否则两侧可能进不同图，坐标相同也不可比。）
