A. 结论（先看这三条）
----------------------------------------------------------------------------------------------------------------
1) **真机配对证明「跑」由帧 52 的能力布局决定，与 SM_SERVERCONFIG(11029) / TClientConf 无关。**
   同一棵交付树上、同一角色 `aaa@(256,584)`（比奇省开阔地）、同一客户端动作（目标点按住 8 方向 ×2 圈），
   只换 52 尾布局（`MIR2_CLIENT_ABILITY_LAYOUT`）：

     运行    52 尾布局     11029 body_len/body_sha256        52 body_len  客户端 HUD      c2s CM_WALK  c2s CM_RUN(3013)
     BEFORE  oracle-40     23 / bc2a1f661a5d…（17 bool 双编码）  40          0/0（血球黑）      32           0
     AFTER   client-58     23 / bc2a1f661a5d…（**逐字节相同**）   58          19/19（血球满红）  25           3

   两行的 11029 帧（`SendServerConfig` 的 `EncodeString(EncodeMessage(ClientConf))`）body 逐字节相同 ⇒
   **ClientConf 一字未动，`CM_RUN(3013)` 却从 0 → 3**。⇒ brief 指定的「按冻结客户端布局编码 ClientConf
   （17B → 52/58B）」**不可能**影响 `CM_RUN`；做了也无法满足 brief 自己的判据「改回 17B ⇒ CM_RUN 回归 0」。

2) **机制**：客户端唯一发跑支 `Source/MirClient/ClMain.pas:2190 caRun` 先取 `crun := g_MySelf.CanRun`；
   `Actor.pas:2162 CanRun` = `HP >= RUN_MINHEALTH`（`Actor.pas:22` = 10）。客户端 `TAbility` 在
   `HIGHHP=True`（`Source/Common/Grobal2.pas:39`）下是 **58B**，`HP@22`(DWORD)。oracle 的 40B
   `EncodeMessage(WAbil)` 让客户端从 offset 22 读到 `Exp`（本部署 = 0）⇒ `crun = -1` ⇒ 走 `:2244 else`
   （发 `CM_TURN` + `goto LB_WALK` 走）——正是 BEFORE 的 32 walk / 0 run。改用 58B 后 `HP@22 = 19 ≥ 10`
   ⇒ 发 `CM_RUN`。**「跑」的门从来不是 `boCanStartRun`，而是 `CanRun(HP)`。**

3) **片⑧（`cef8726a3`，`60-client-run-blocker-finding.txt`）的复核仍是本片依据，且被本片实测坐实**：
   冻结客户端 `SM_SERVERCONFIG = 20002`（`Grobal2.pas:1300`，自首提交 `3dbba7d2` 起未变；`git log -S` 可复跑），
   客户端全仓无 `11029`（`grep -rn 11029 Source/` 零命中）⇒ `ClientGetServerConfig` 永不执行 ⇒
   `g_boCanStartRun` 停在**缺省 True**（`MShare.pas:1998`）；`grep -rn g_boCanStartRun` 全仓只有该缺省与
   `:15034` 的赋值点。片⑥「11029 体布局把 `boCanStartRun` 读成栈垃圾 ⇒ 恒假」据此推翻。

B. 第二个真机必要件：跑键探针必须在**目标点**按下
----------------------------------------------------------------------------------------------------------------
冻结客户端 `FormMouseMove`（`ClMain.pas:4648`）只把移动喂 UI（`g_DWinMan.MouseMove`），**不**调
`_DXDrawMouseDown`；而 `g_ChrAction := caRun` + `g_nTargetX` 只在 `_DXDrawMouseDown` 的「点 >1 格」支
（`ClMain.pas:5446-5463`）置。⇒ 旧探针 `Send-HoldRun` 从屏幕中心按下、再靠 `WM_MOUSEMOVE` 挪到远点
**永远设不上远目标**（片⑥ R5..R7 的 0 条 3013 有一部分是这个）⇒ 本片把探针改成在**目标点**
`PostMessage WM_LBUTTONDOWN`（每 150ms 重按，越过 `FormMouseDown` 的 120ms 重入门）。BEFORE/AFTER 都用修好的探针。

另：`g_PlayScene.CanRun`（`PlayScn.pas:3101`）要求**下一格 + 目标格**都 `CanWalkEx`；城墙走道/房区会恒假 ⇒
真机判据必须在**开阔地**上取（本片 `aaa@(256,584)`；同角色同探针在 `(291,666)` 城墙走道上 `CM_RUN=0`，如实登记）。
