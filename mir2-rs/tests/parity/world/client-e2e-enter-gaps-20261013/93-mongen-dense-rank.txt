一句话：给既有 `check_mongen_dense_points.py` 增补「**窗口内期望出生怪数** E」的确定性几何读数
（`--rank`/`--best-point`/`--min-expected`/`--max-expected`），把 root ③① 的「换怪密点」从
「凭记忆挑一个框内点」变成**可复跑、可机判、可排行**的选点；并把 ③a「该点确实无怪」升级为
`E == 0` 的定量判据（而非只判「框内/框外」）。

口径（oracle 锚点，逐行）：
  * 出生框 = 正方形：`src/GameSrv/Word/WorldServer.MonGen.cs:825-826`
      nX = monGen.X - monGen.Range + Random(monGen.Range*2+1);
      nY = monGen.Y - monGen.Range + Random(monGen.Range*2+1);
    ⇒ 出生点在 `[X-R, X+R] x [Y-R, Y+R]` 上**均匀**；框维持 `Count` 只。
  * 观察窗口 = 以玩家为中心、半径 `view_range` 的方格（Chebyshev；`PlayObject.cs:904` = 12）。
  * E = Σ_box `Count * |窗口 ∩ 框| / |框|`（整数格点；纯几何、无 RNG、确定性）。
    **只算出生**：游走怪可能把实机 `nearest` 压得更小 ⇒ `E==0` 只断言「窗口内不会有**新出生**的怪」，
    不排除游走怪（`70-…txt` §C 已登记）。
  * 退出码 0 GREEN / 1 RED / 2 PREREQ_RED（缺 `--view-range`、缺框、格式错均 fail-closed）。

结论（本次测算）：
  * root verify1 点 `(291,666)`：E = **0.000**（窗口半径 12 不碰任何生成框）⇒ ③「该点确实无怪」**定量成立**；
    同点若改判「期望有怪」(`--min-expected 1`) ⇒ **RED**（不存在假绿放行）。
  * 框内点 `(289,618)`（oracle `StartPoint.txt` 出生点）= **6.754**；`(287,620)` = **5.617**（片⑦ 已证客户端实收 13 对）。
  * **最密点 = `(605,578)`：E = 12.681**（5 个重叠框中心：`鹿/稻草人` r=50 count=50 ×2 + `半兽人/多钩猫/钉耙猫` r=30 count=10 ×3）。
    次密 `(211,629)` / `(256,572)` = 12.225。⇒ 窗口若想一次拿到最多同屏怪，用 `(605,578)`；
    若想复用「新角色默认体验」的既有证据，用 `(289,618)`。两者 E 都 ≥ 1，满足 ③b `--min-expected 1`。
