一句话：DoD③「能攻击造成伤害」在真客户端上**此前不可能观测到** —— `bins/game-svr` 把受击帧
`SM_STRUCK` 只发给**受击者本人**，而 oracle 是 `SendRefMsg(RM_STRUCK)` **广播给受击者视野内全体
`Play`**（怪物目标也一样）。本片按 oracle 修好（+2 条构造级用例 + 改坏必红），并把「攻击/伤害」
做成窗口步 + 机判（`check_attack_observability.py`，接入 `window_handoff.py` G2/`--plan`/`--judge`）。

A. 缺陷（oracle 逐行锚点 vs Rust 旧实现）
----------------------------------------------------------------------------------------------
oracle 命中一次（目标 = 怪 or 人）：
1) `src/M2Server/Actor/BaseObject.Attack.cs:57`
   `targetObject.SendStruckDelayMsg(Messages.RM_REFMESSAGE, nPower, targetObject.WAbil.HP,
    targetObject.WAbil.MaxHP, ActorId, "", 200);`
2) `src/M2Server/Actor/BaseObject.Message.cs:211-232`：把这条入到**受击者**的 `MsgQueue`：
   `wIdent = RM_REFMESSAGE`、`ActorId = Messages.RM_STRUCK`、`DeliveryTime = now+200`、
   `LateDelivery = true`、优先级 `Lowest`。
3) `src/M2Server/Actor/BaseObject.Base.cs:699-705`（受击者 `Run()` 处理 `RM_REFMESSAGE`）：
   `SendRefMsg(processMsg.ActorId /*=RM_STRUCK*/, processMsg.wParam /*damage*/,
    processMsg.nParam1 /*HP*/, processMsg.nParam2 /*MaxHP*/, processMsg.nParam3 /*hitter*/, Msg);`
4) `src/M2Server/Actor/BaseObject.Message.cs:383-470` `SendRefMsg`：对**同图、切比雪夫 ≤
   SystemShare.Config.SendRefMsgRange(=12)、`Race==Play`、非 Ghost** 的每个对象
   `SendMsg(this /*=受击者*/, RM_STRUCK, …)`；对 `Race!=Play` 且 `WantRefMsg` 的对象同发
   （仅 `RM_STRUCK`/`RM_HEAR`/`RM_DEATH` 三个 ident）。
5) `src/M2Server/Player/PlayObject.Message.cs:1562-1628`（观察者处理的 `RM_STRUCK` 支）：
   `ClientMsg = MakeMessage(SM_STRUCK, processMsg.ActorId /*=受击者*/, baseObject.WAbil.HP,
    baseObject.WAbil.MaxHP, processMsg.wParam /*damage*/)` + 16B `MessageBodyWL`
   （`Tag1 = 命中者 ActorId`、`Tag2 = 0/1(MAG)`）⇒ 发给**观察者自己的客户端**。
⇒ 玩家打怪时，**攻击者客户端收到 `SM_STRUCK`**（怪掉血/伤害可见）。这正是 DoD③ 第三半要证的。

Rust 旧实现（`mir2-rs/bins/game-svr/src/main.rs` 的 `drain_combat_downlink` ①）：
    let Some(entry) = online.iter().find(|e| e.actor_id == *target) else { continue; };
⇒ 只查**受击者自己**有没有在线会话；怪物不在 `online` ⇒ **一帧不发**；玩家受击时也只发受害者、
不发同屏其他人。旧注释自称「（oracle 同）」，经上面 5 条锚点复核**不成立**：只看了
`BaseObject.Attack.cs:61-64` 的 `SendMsg(targetObject, RM_STRUCK, …)`，漏了 :57 的
`SendStruckDelayMsg` → `RM_REFMESSAGE` → `SendRefMsg` 广播链。

B. 修法（行为等价优先：1:1 照搬 oracle 的广播面）
----------------------------------------------------------------------------------------------
`drain_combat_downlink` ①：
- **保留**：受击者是**在线玩家**时，世界权威 HP 同步回会话 `WAbil.HP` + `stamina.on_struck()` +
  `PerHealth/PerSpell -= 1`（`PlayObject.Message.cs:1587-1590`）；
- **改为**：帧体 `smframe::sm_struck(...)` 只构造一次，发给
  `chat::hear_targets(world, *target, chat::SEND_REF_MSG_RANGE)` 里的**每个在线玩家**
  （与 ② 死亡广播同一函数、同一常量 `SEND_REF_MSG_RANGE = 12`，
  `bins/game-svr/src/chat.rs:30/56-78`：同图 + `Race==Play` + 非 ghost + 切比雪夫 ≤ range）；
- `outcome.damage == 0` 仍跳过（`PlayObject.Message.cs:1563` 的 `wParam > 0` 门）。
⇒ 怪物目标也广播（怪物无连接，但视野内玩家收到）。**T- 级白名单无需新增**：这是 parity 修正，
不是故意偏离。

登记（未 1:1，本次不动，交 owner）：
- oracle 该帧经受击者 `MsgQueue` 以 `LateDelivery = 200ms` + `MessagePriority.Lowest` **延时**投递；
  本实现**即时**发（旧实现也即时；本片不引入时序改动，避免把 R 级时序差异混进本片）。
- 广播范围口径沿 ② 死亡广播：`(dx,dy) ≤ 12`。oracle `SendRefMsg` 有两条分支（缓存命中时
  `abs < 11`、重扫时 `abs ≤ 12`），本片与既有死帧同口径；边界差（恰 11/12）未单独钉。
