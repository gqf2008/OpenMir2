A. 缺口：修复的几何根因**无 oracle 侧离线判据**
----------------------------------------------------------------------------------------------------
- ③ 的几何根因（`30-oracle-anchors-viewrange.txt` §A/§B）：玩家 `PlayObject` 构造器把 `ViewRange`
  置 12（`src/M2Server/Player/PlayObject.cs:904`），Rust 生产宿主 `new_player_entity` 改前未置它
  ⇒ 窗口只有缺省 5（`src/M2Server/Actor/BaseObject.cs:383`）= **11×11**；Chebyshev **6..12** 的怪/玩家
  不进 `visible_actors` ⇒ `drain_aoi_downlink` 不发出现帧 ⇒ 客户端同屏少怪。
- 现有离线判据只到**构造层 + Rust 内部**：`bins/game-svr/src/main.rs` 的
  `player_aoi_window_covers_view_range_12`（钉 (22,10)=12 可见 / (23,10)=13 不可见）与
  `new_player_entity_sets_want_ref_msg`。它们**没有 oracle 参照**（断言值由人写死）。
- **缺口**：`tests/parity/world/scenarios/*.json` 的 5 个 golden 场景**全部是 `view_range: 5`**
  （`grep -n view_range *.json` 逐行可验）⇒ 25×25 窗口、12/13 环形边界、扫描序、自己是否入集、
  观察者过滤器在 vr=12 下的整集，都**没有 C# 金标准钉住**。修复的几何根因目前只有真机窗口能判。

C. 金标准读数（`golden/aoi_viewrange12.txt`，oracle 桩产出；**这是「同一位置、同一 viewrange」的 C# 侧证据**）
----------------------------------------------------------------------------------------------------
```
tick 1 clock 200
ent 1 0 32 32 100 1 0 vis 8:2 1:2 2:2 3:2 10:2 4:2 6:2
ent 2 0 32 33 100 1 0 vis 1:2
ent 3 0 32 39 100 1 0 vis
...
ent 11 0 32 45 100 1 0 vis 11:2
tick 2 clock 400
ent 1 0 33 32 100 1 0 vis 8:1 1:1 2:1 3:1 10:1 4:1 6:1 5:2
...
```
* **玩家 1 号**首 tick 可见集 = `8(32,20) 1(self) 2(32,33) 3(32,39) 10(44,20) 4(44,32) 6(44,44)`：
  全部 Chebyshev ≤ **12**；**5(45,32)/7(45,45)/9(32,19) 三个 Chebyshev=13 的怪不在集内** —— 25×25 窗口
  的上界被钉住（不是「越大越好」）。序 = 扫描序（X 外升 / Y 内升）。
* **自证 self 入集**（`1:2`）：与 `whitelist.md` D-8（oracle AOI 不排除观察者自己）一致，vr=12 下同样成立。
* **tick 2 走一格后** `5:2` 出现（`(45,32)` 距 `(33,32)` = 12）⇒ 钉住「新进窗口对象发 `Show`」的增量语义。
* **怪 2 号**（观察者 race 80、无 master、`WantRefMsg=false`）只见 `1:2`（玩家）⇒ 钉住观察者过滤器：
  怪不把怪纳入自己的可见集，但把玩家纳入（`BaseObject.ViewRange.cs:112` 同构）。
