# 2) 真凶：53 `SM_HEALTHSPELLCHANGED` 的布局（冻结客户端 `HIGHHP=True`）

冻结客户端 `~ == /e/Users/gxh/Documents/GitHub/MirClient @ c61d912d`（= `D:/MirClient-run/MirClinet.exe`）：

* `Source/Common/Grobal2.pas:39`  → `HIGHHP = True;`
* `Source/MirClient/ClMain.pas:10220-10231`（`{$IF HIGHHP}` 支）：
    DecodeBuffer(body, @desc, SizeOf(TCharDesc));
    Actor.m_Abil.HP    := DWORD(desc.Feature);
    Actor.m_Abil.MP    := DWORD(desc.Status);
    Actor.m_Abil.MaxHP := DWORD(desc.StatusEx);
* `Source/Common/Grobal2.pas:3515` → `TCharDesc = packed record Feature: Integer; Status: Integer; StatusEx: Integer; end;`（12B）

即：**HIGHHP 客户端不读 12B 命令头的 `param/tag/series`，只从「尾」解 12B `TCharDesc`**。
而 oracle 的 53 是 `SendSocket(ClientMsg)` = **header-only**（`src/M2Server/Player/PlayObject.Socket.cs:77-96`，
`PackLength = CommandMessage.Size` = 12，无尾）⇒ 客户端 `body` 为空 ⇒ `desc` 全 0 ⇒ `HP=0 / MP=0 / MaxHP=0`
⇒ HUD `0/0`、`m_Abil.MaxMP` 仍保留（HUD `0/15`，与 root 截图逐像素一致）、`CanRun`（`HP>=10`）拒绝跑。

这与 52 的既定裁决同源：客户端冻结 ⇒ 52 用客户端 58B `TAbility`（`bdd3a2ae9`，默认开），
**53 的 `TCharDesc` 尾是同一客户端布局的漏项**（`SM_ABILITY` 走 `DecodeBuffer(body, @m_Abil, SizeOf(TAbility))`，
`SM_HEALTHSPELLCHANGED` 走 `DecodeBuffer(body, @desc, SizeOf(TCharDesc))` —— 同一文件同一区块）。

## 2.1 为什么 00:40（verify1）好、15:0x（verify2）坏

# 4) ③「同屏没怪」判定（root 2026-10-14 00:4x 项）

**判定：该点位确实（几乎）没怪 —— `AF`/`AOI` 有算也有发，不是「没算/没发」。**

* verify2 诊断行 `[aaa(17886) map=26 vr=12 vis=0 new=0 af=2 same_map=1726 nearest=14→34]`：
  `vr=12` ⇒ AOI 窗口 25×25；Diagnostic 的 `nearest` = 同图最近实体的 **Chebyshev** 距离。
  首条诊断 `nearest=14` 已 > `vr=12`，随后 19/20/23/34/25/32/30 ⇒ 全程**没有实体进入 12 格** ⇒ `vis=0` 几何自洽。
* `af=2` = 恰好**一对** `SM_TURN(10)+SM_FEATURECHANGED(41)`（`drain_aoi_downlink` 只在 `VisibleFlag::Show` 发）
  ⇒ 出现帧管线**有实发**（累计计数），不是恒 0。
* 待窗口补的 R 级项（本片不据此收口）：**C# 侧同点位（同 `view_range=12`）对照**——
