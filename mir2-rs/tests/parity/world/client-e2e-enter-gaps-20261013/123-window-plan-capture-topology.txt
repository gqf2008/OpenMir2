A. 缺陷（before，源码实读 + 湿测；不是散文）
----------------------------------------------------------------------------------------------------
[A1] `tools/m2-acceptance/start_rust_stack.ps1:323` 起 **Rust** `game-gate`：
       `Start-One -Name 'game-gate' -Exe $ggExe -ExeArgs @($ggConf) ... -Ports @(7200, 7201, 7202)`
     其中 `$ggConf = <MirServer>\RunGate\config.conf`（`:194`），即布局 `GatePort1/2/3 = 7200/7201/7202`。
     ⇒ 通过 `start_rust_stack.ps1` 起的栈**必然**占着 7200。
[A2] `tools/capture/mir2_proxy.py:137-145` 对每个 `--map` 调 `asyncio.start_server(handler, bind, listen_port)`，
     全部成功后才写 `<out>/ready.flag`。端口被占 ⇒ `OSError(10048)` 未捕获 ⇒ 进程非零退出、**无 ready.flag**。
[A3] 计划（片㉓ 后的 before）里，Rust 段是「起栈 → 直接代理」，中间只有一行 C# 注释
     `# 影子 game-gate(7600) + 代理占 7200；`——**没有任何「让出 7200 / 起影子 7600」的可执行步骤**。
     照抄计划 ⇒ 第 2 步代理必在 7200 上失败。已证可跑的步骤在
     `tools/m2-acceptance/evidence/m2svr-whitelist-rerun-20261012/README.md` §4
     （「先停标准 game-gate 让出 7200」+ `game-gate.exe <rungate-proxy.conf>` + `mir2_proxy.py --map 7200=127.0.0.1:7600`），
     但计划本身没引用它。

[A4] burn-mode 湿测（代理监听端口被占 ⇒ 必失败；让出后 ⇒ 起得来）。为不占任何游戏端口，
     用**环回非游戏端口** 57999（占用方）/ 57997（上游，可不存在）复现同一机制：
```
=== phase1: standard gate holds 57999 (proxy must fail) ===
rc=1 ready.flag=False
  File ".../asyncio/base_events.py", line 1584, in create_server
    raise OSError(err.errno, msg) from None
OSError: [Errno 10048] error while attempting to bind on address ('127.0.0.1', 57999): ... 只允许使用一次。
=== phase2: port freed (proxy must start) ===
rc='RUNNING' ready.flag=True
LISTEN 127.0.0.1:57999 -> 127.0.0.1:57997
READY
```
     ⇒ 「先让出 7200、再起代理」不是可选项；标准 game-gate 还在 ⇒ 代理必死。
