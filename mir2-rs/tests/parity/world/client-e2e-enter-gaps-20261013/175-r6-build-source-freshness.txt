一句话：R1 只做单向 `--is-ancestor`（「源含片⑪+片㉜」），**不能**发现「源含两片但停在更早 master」；
本轮实测到该盲区真的发生 —— 专用源 `E:/tmp/m2svr-window-origin @9edfc745d`（片㉟ 在 10:30 刷到
当时的 `origin/master`）在 `origin/master` 前进到 `3db79cae0` 后，`bins/game-svr` 有 **3 个生产文件**
已变（+335 行），而 `check_rust_window_preflight.py` 与聚合门 **仍判 GREEN** ⇒ 开窗会跑旧 `game-svr.exe`。
本片给前置门加 **R6 fail-closed 门**（构建源 == 基线，或为基线的后继，或与基线在生产路径上零差异），
把专用源刷到 `origin/master=3db79cae0` 并重编译 `game-svr.exe`，聚合门复跑 GREEN。

A. 缺陷（实测，非推断）
----------------------------------------------------------------------------------------------------
口令（cwd = 本卡片录）：
```
$ git -C E:/tmp/m2svr-window-origin rev-parse HEAD
9edfc745d48ec7edafcbcb9da3d9a6a0c19073ad
$ git -C E:/tmp/m2svr-window-origin rev-parse origin/master

$ git -C E:/tmp/m2svr-window-origin merge-base --is-ancestor 3db79cae0 HEAD ; echo $?

    mir2-rs/bins mir2-rs/crates mir2-rs/Cargo.toml mir2-rs/Cargo.lock src sql

 mir2-rs/bins/game-svr/src/smframe.rs |  27 ++++++

```
* 即：`game-svr` 的**宿主源**（③ 判据的唯一宿主）已落后 master 3 件/335 行；`bins/game-svr`
  正是窗口六件 exe 里唯一承载 ③ 判据的件。
* 为什么 R1/R2/R3/R4/R5 全绿仍会漏：R1 是 `--is-ancestor <修复提交> <ref>` 的**单向**门 ——
  只要源**曾经**含片⑪+片㉜（`9edfc745d` 含），无论之后 master 前进多少，它都 GREEN。
  片㉟ 的「刷到 `origin/master`」是一次性动作，master 再前进就重新过期，**门不会提醒**。

B. 修法（只加门，不改任何 ③ 判据语义）
----------------------------------------------------------------------------------------------------
`check_rust_window_preflight.py` 新增 **R6 构建源必须是当前基线**（`--baseline-ref`，默认 `origin/master`）：
1. `--ref` == 基线 ⇒ OK；
2. `--ref` 是基线的后继（`git merge-base --is-ancestor <base> <ref>`）⇒ OK（源**领先**基线不算旧）；
3. 否则比 `git diff --name-only <base> <ref> -- <生产路径>`：空 ⇒ OK（非生产面差异可接受）；
   非空 ⇒ **RED** 列件数与前 5 件，并给修法（`fetch` + `checkout --detach <基线>` + 重编译）。
生产路径与合并门禁同口径：`mir2-rs/bins` / `mir2-rs/crates` / `mir2-rs/Cargo.toml` /
`mir2-rs/Cargo.lock` / `src` / `sql`。基线解析不到 ⇒ `PREREQ_RED`（fail-closed，不静默放行）。
`--baseline-ref ''` 可显式跳过（**仅**供无 remote 的离线自测，**不是**窗口口径，帮助串已写明）。

* R6 的已知界限（下次动该门时收）：它比的是**生产路径的 git 差异**，不是「exe 与源一一对应」——
  若有人在源刷后手工替换 exe 或复用暖 target 的旧件，R6 不会发现（那属于 `--disk-bytes`/exe-hash 门的范畴，
