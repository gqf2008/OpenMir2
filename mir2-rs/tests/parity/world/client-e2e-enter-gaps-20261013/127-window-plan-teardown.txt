A. 缺陷（源码实读；可复算的锚点）
====================================================================================================
[A1] `{mirserver}/stop-all.ps1` **不存在**（计划第 53 行 C# 收栈写的就是它）：
```
$ test -f E:/MirServer/stop-all.ps1 && echo YES || echo NO
NO
$ ls E:/MirServer/*.ps1
E:/MirServer/build-client-104.ps1
E:/MirServer/port-status.ps1
E:/MirServer/restart-gamesvr.ps1
E:/MirServer/start-all.ps1
```
并且**不能**用 `start-all.ps1 -Stop` 顶替：它的 `Stop-Stack` 目标表含 `mysqld`
（`E:/MirServer/start-all.ps1:117` = `$order = @('LoginGate','SelGate','GameGate','GameSrv','LoginSrv','DBSrv','mysqld')`）
⇒ 连**共享 MySQL 3306** 一起停，与开工前『仅 3306 UP』不一致。

[A2] 手工起的**影子 game-gate(7600)** 不在 pid 文件里 ⇒ `start_rust_stack.ps1 -Stop` 收不走：
`tools/m2-acceptance/start_rust_stack.ps1:150-157` 只遍历 pid 文件里的 `entries` 停进程
（`if (-not (Test-Path $PidFile)) { 'NOTHING_TO_STOP' }`；`$saved = Get-Content $PidFile`）。
影子 gate 是计划 §2a 用 `Start-Process` 手工起的，**未登记** ⇒ 留占 7600 ⇒ C# 影子 gate 绑不上。

[A3] 代理 `mir2_proxy.py` 常驻、不自停：
`tools/capture/mir2_proxy.py:145` 只把 pid 写进 `<out>/ready.flag`；`:148` `serve_forever()`
无限服务（仅 Ctrl-C/KeyboardInterrupt 才退）。计划未收它 ⇒ 占 7200 ⇒ 下一趟 §0 预检
`tools/m2-acceptance/start_rust_stack.ps1:171-177`（`$wanted = @(6000,5100,5700,5500,5600,5000,7000,7100,7200)`）
直接 `RED: 目标端口已被监听 7200 … exit 1`。

[A4] 计划里 §2a 的两条命令还把 `'<bin_dir>\\game-gate.exe'` 写成**字面占位**（虽然同一计划的
`(本计划 <bin_dir> = …)` 注里已经知道实际目录）⇒ 粘贴后要人工替换，易错。

B. 本片改动（`window_handoff.py`，只读规划器；不新造第二份判据）
====================================================================================================
[B1] **§2b 清端口段（Rust 趟跑完 · 进 C# 趟/③a 前必做）**：a. 用 `ready.flag` 里的 pid 停代理；
     b. 按绝对路径停影子 game-gate（标准 gate 已由 §2a.a 让出）；c. `start_rust_stack.ps1 -Stop`
     停 pid 文件里其余；d. `port-status.ps1` 断言 7200/7600 都 DOWN。
[B2] **§2b 清端口段（C# 趟跑完必做）**：a. 停代理；b. 按绝对路径停 C# 影子 gate
     （`{mirserver}/RunGate/GameGate.exe`）；c. `Get-Process GameSvr,DBSrv,LoginSrv,LoginGate,SelGate,GameGate | Stop-Process -Force`
     —— **保留 MySQL 3306**（同 `tools/m2-acceptance/evidence/session-lifecycle-rerun-20261012` 的收工口径）；
     d. 断言 7200/7600 都 DOWN。并**删掉不存在的 `{mirserver}/stop-all.ps1`**，写明**不要**用
     `start-all.ps1 -Stop`（会停 3306）的理由。
[B3] **占位替换**：§2a 两条命令里的 `<bin_dir>` 代入实际 `-RustBinDir`（`bin_dir_w`），
     并把 §2a.c 的 `E:/MirServer/port-status.ps1` 改为 `{mirserver}/port-status.ps1`（随部署根走）。
[B4] **G4 机判 `plan_conformance(plan, repo_root, check_dir, mirserver)`**（静态、零起栈/零端口）：
     ① 计划里每个被调 `.ps1/.py` 必须存在（绝对路径 / 仓根 / 判据目录 / 部署根 / `tools/*` 五处解析）；
     ② 每个命令里出现在脚本路径**之后**的 `-Flag`/`--flag` 必须在该脚本的声明集合里
        （`.ps1` 取 `param(...)` 的 `$name`；`.py` 取 `add_argument('--x')`）；宿主 powershell 开关
        （`-ExecutionPolicy/-File/-NoProfile/-Command/-EA/-ErrorAction`）排除；
     ③ 计划必须含 6 条 teardown/清端口标记（§2b 段、`proxy/ready.flag`、两个影子 gate 精确停、
        `断言 7200/7600 都 DOWN`、`保留 MySQL 3306`）；
     ④ 不得出现 `stop-all.ps1`；⑤ 不得残留 `<bin_dir>`。
     `--plan`/`--plan-only` 打印 `PLAN_CONFORMANCE=GREEN|RED`，RED 时逐条打 `RED <问题>` 并把 rc 抬红
     （fail-closed；`--plan-only` RED ⇒ rc=1）。
