A. 背景：三条已复现的假绿 / 未接线
====================================================================================================
1. **跨图站位 SQL 假绿（本片复现）**：旧实现
   `window_handoff.py --plan-only --best-site --map-name D10071` 选到 D10071 的 `(17,21)`，却在 §1b
   写死 `UPDATE … SET MapName='0', CX=17, CY=21 …`，而 `PLAN_CONFORMANCE=GREEN` ⇒ root 照抄会把
   角色放到 **0 号图 (17,21)**（不是 D10071 的密点）= 白烧窗口。G4 的旧站位牙只查「有没有
   `MapName`/`CX`/`CY`」，**不查图名是否与选点同图**。
2. **选点未过「可站立 / 客户端带图」过滤（片㉚ 已登记未接线）**：`resolve_best_site` 调
   `check_mongen_dense_points.py --best-point` 时**不传** `--map-dir/--client-map-dir`，即使片㉚ 已给
   checker 加了这两层过滤 ⇒ 「未过滤最密点」可能落在墙上（真机 6 张图的站点在 §C）。
3. **跨图 BEST 形态解析不到**：`check_mongen_dense_points.py --all-maps --best-point` 打的是
   `BEST (D10071) (17,21) E=…`，而旧 `_BEST_RE` 只认 `BEST (x,y) E=…` ⇒ 跨图选点
   `parse_best_point` 恒 `None`（fail-soft 静默跳过，root ① 的「密度高的图」用不上）。

B. 本片改动（唯一代码文件 `window_handoff.py`；只读规划器，不复制第二份几何/判据）
====================================================================================================
1. `_BEST_RE` 支持跨图形态：`^BEST\s+(?:\((?P<map>[^()\s]+)\)\s+)?\((?P<x>-?\d+),(?P<y>-?\d+)\)\s+E=…`；
   `parse_best_point` 返回值加 `"map"`（单图形态 ⇒ `None`）。
2. `resolve_best_site` 返回三元组 `(site, site_map, note)`，新增 `all_maps`/`map_dir`/`client_map_dir`：
   有目录就传 `--map-dir + --require-walkable`、`--client-map-dir + --require-client-map`；缺目录
   **不静默**（note 里登记「未做该层过滤」）。`--all-maps` 时用跨图排行并回传**选点所在图名**。
3. `plan_text` 新增 `site_map`/`site_none_map`（默认 `"0"`，向后兼容）：§1b/§1c 站位 SQL 写实际图名；
   `site_map != "0"` 时计划内附**跨图告警**（须实拍客户端能进该图；MapInfo `NORECONNECT/DAY` 属性）。
4. `position_sql_findings` 新增可选 `site/site_map/site_none/site_none_map`：命中该坐标的站位 UPDATE，
   `MapName` 必须 == 选点图，否则红（点名「图名与选点不一致」）。
5. `plan_conformance` 透传上述四参；`main()` 新增
   `--best-site-all-maps` / `--client-map-dir`（默认 `D:/MirClient-run/Map`）/ `--site-none-map`，
   并把解析出的 `site_map` 同时喂给 `plan_text` **与**`plan_conformance`（同一真实来源，不走两遍）。
