## 2. 判据①：战斗·伤害序列（固定种子 100 次攻击逐项相同）

- 种子注入点 = `OpenMir2.RandomNumber.random`（私有静态 `System.Random`）反射换成 `new Random(seed)`，
  与 D2 `RngSeedHook` 同一注入点；Rust 用 `RandomNumber::with_seed(seed)`（复刻 `RandomNumber.cs`，
  非 `rand` 默认算法）。
- **关键口径（本片踩到并纠正）**：种子注入必须在**对象构造之后**。`PlayObject`/`MonsterObject`
  构造函数本身会消耗随机数（实测 5+5 次），先注入会把构造消耗算进攻击序列，Rust 侧无法复现。
- 攻方是真 `PlayObject` ⇒ 走 **`PlayObject.GetAttackPower` override**（`PlayObject.cs:2911`），
  比 `BaseObject` 版**多一次取数**（`Luck == 0` 时先 `Random(power+1)` 再 `Random(10)`）。
  Rust 侧新增 `AttackPowerMode::Player{luck,power_rate,bo_power_item,power_item}` 忠实复刻。
- 4 个 case（`Attack` 数 = 100/100/30/1000）：

| case | 攻方 | 守方 | 统计（两侧一致） |
| --- | --- | --- | --- |
| `dodge_mix_100` | DC=0x1E14(20..30), HitPoint=20 | AC=0x0A05, SpeedPoint=40 | hits=57 dodges=43 attacked=57 sum=873 |
| `no_dodge_100` | HitPoint=20 | AC=5, SpeedPoint=1 | hits=100 dodges=0 attacked=100 sum=1517 |
| `undead_30` | UndeadPower=7 | LifeAttrib=1(LA_UNDEAD), AC=5, SpeedPoint=12 | hits=30 sum=663（含不死加成） |
| `stats_1000` | HitPoint=20 | AC=5, SpeedPoint=12 | hits=1000 sum=15978（统计样本） |

`crates/world/tests/combat_skill_vectors.rs::combat_damage_sequence_matches_csharp` 逐项核
`power / damage / hp_after / hit / attacked / hp差` 与统计；`attack_with(Player)` 全等。

## 3. 判据②：命中 / 躲闪统计

- oracle 口径字段是 `BaseObject.HitPoint`（准确，`BaseObject.cs:386`）与
  `BaseObject.SpeedPoint`（敏捷，`BaseObject.cs:387`）；文档里说的 `HitSpeed`/`DodgeSpeed` 即这两项
  （命名映射在此登记）。判定 = `if (target.HitPoint > 0 && attacker.HitPoint < RandomByte(target.SpeedPoint)) nPower = 0;`
  （`BaseObject.Attack.cs:39-44`）。
- 统计值两侧一致且**非平凡**（`hits>0 && dodges>0`）；并覆盖「守方 `HitPoint == 0` ⇒ 整段跳过命中骰」
  分支（`stats_1000`/`no_dodge` 与 `dodge_mix` 的取数账本差异即由此分辨）。

## 4. 判据③：每个已实装技能一条用例（前置 / MP / 效果 / 冷却）

**已实装 11 个技能**（`crates/world/src/magic.rs`）：`1 火球术`、`2 治愈术`、`5 大火球`、
`6 施毒术`、`11 雷电术`、`13 灵魂火符`、`14 幽灵盾`、`15 神圣战甲术`、`16 困魔咒`、
`18 隐身术`、`19 集体隐身术`。每条用例逐项核：

1. **施法前置**：`!IsTrainingSkill && (Job==99||Job==char.Job) && Abil.Level >= TrainLevel[0]`
   （`PlayObject.Base.cs:2170-2196` 的 `ReadBook` 口径）；
2. **MP 消耗**：`GetSpellPoint = Round(Spell/4.0*(Level+1)) + DefSpell`，Level 0..3 四个值；
3. **效果威力**：调用 oracle 真身子函数算出的威力（`GetAttackPower(GetPower(MPow)+…, …)`、
   `GetPower13(n)+GetRPow(SC)*k` 等，逐技能分支），每技能独立子种子 `seed ^ magic_id`；
4. **冷却**：`Magic.DelayTime` 与 `MagicAttackInterval = DelayTime + MagicHitIntervalTime`（oracle 实测 800）。

输入是**真魔表**：解析 `sql/mir2_data.sql` 的 `magics` 行，字段映射口径 = `MySqlDB.LoadMagicDB`
（`TrainLevel[3]=NeedL3`、`MaxTrain[3]=MaxTrain[2]`、`TrainLv=3`）。共 108 行。

**未实装逐条登记**：`skills_registry.json`（108 行，每行 `implemented` + 承接说明）；
`implemented=false` 的行为 97 个，承接 = 后续 M3 技能批次（理由：需要地图 `MagCanHitTarget` /
`AntiMagic` 判定 / 护身符消耗 / 召唤与状态挂载等 oracle 上下文）。

## 7. 本批哪些项**不等价**（含理由与登记去向）

1. **`PlayObject.GetAttackPower` override 未接入世界宿主**（**已证的真实差异，登记，不在本卡修**）：
   `World::attack_once` 对所有攻方都走 `AttackPowerMode::Base`（`BaseObject` 版，1 次取数）；
   真 oracle 里玩家攻方走 `PlayObject` override（`Luck=0` 时**多一次 `Random(10)`**，另有
   `PowerRate`/`BoPowerItem`/`AutoChangeColor`）。本片已把该 override 在 `combat.rs` 里忠实建模
   （`AttackPowerMode::Player`），向量对拍全绿；但**接线**会改变 M2 既有 golden 的取数序列，
   而 golden 生成器 `tests/parity/csharp/WorldGolden` 的 `ActorStub.GetAttackPower` 用的是 Base 版，
   且该目录**不在本卡写集**。⇒ 承接 = M3 后续批次，需同步更新 `WorldGolden` 桩后销账。
   （`player_attack_power_is_a_registered_distinct_path` 断言两种口径确为不同实现，防止误以为已覆盖。）
2. **`DoSpell` 完整施法流程未覆盖**：地图 `MagCanHitTarget` / `AntiMagic` 判定 / 护身符
   （`CheckAmulet`/`UseAmulet`）/ `MagPassThroughMagic` / 召唤（`MagMakeSlave`）与状态挂载
   （`RM_DELAYMAGIC`/`RM_POISON`）需要地图、目标 Actor、物品栏等上下文，本片只取**纯数值部分**
   （前置 / MP / 威力 / 冷却）。⇒ 承接 = 后续 M3 技能批次。
3. **未实装技能 97 个**：逐条在 `skills_registry.json` 登记（不许静默漏）。
4. **真机跨侧对拍未做**：需 5000/7000/7100/7200 两侧栈（本片不占端口）。⇒ 承接待 owner 发窗口；
   窗口优先级按卡面：`m2-svr` 进图门 → `m3bag` T-14 复跑 → 本卡。

> 口径纪律：以上差异**不**用白名单盖掉；白名单只用于「连 bug 一起搬」。本片未新增任何 `T-*`。
