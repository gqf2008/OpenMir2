## 1) 为什么返工（reviewer-6 F-1）

原实现按「优先级字节稳定排序」推出出帧序：
`(byte)RM_CHANGENAMECOLOR` = 8090&0xFF = 154 < `(byte)RM_USERNAME` = 8101&0xFF = 165
⇒ 「**所有色帧先于所有名帧**，两组内各按入队序（mutinied 序）」。
但 oracle 的 `MsgQueue` 是 `PriorityQueue<SendMessage, byte>`
（`src/M2Server/Actor/ActorEntity.cs:16`），.NET 8 的实现是 **4 叉最小堆**
（`dotnet/runtime release/8.0 .../PriorityQueue.cs:52 Arity = 4 / :57 Log2Arity = 2`），
**同优先级元素的出队序不是入队序**（二叉堆 sift 结果）。reviewer-6 在 net8.0.26 实测：

    入队 色(s2),名(s2),色(s1),名(s1)  =>  出队 色(s2),色(s1),名(s1),名(s2)   （名组与入队序相反）
    入队 c1,n1,c2,n2,c3,n3（n=3）    =>  出队 c1,c2,c3,n2,n3,n1
    入队 c1..n4（n=4）               =>  出队 c1,c4,c2,c3,n3,n2,n1,n4
    入队 c1..n5（n=5）               =>  出队 c1,c4,c5,c2,c3,n3,n1,n2,n4,n5

`hero_pet_diff.py` 对帧种类序列**逐项**比 ⇒ 原期望（名组=入队序）会让卡级真机 diff 必红。
本片按 reviewer-6 的选项 ①：「忠实复刻观察者 MsgQueue 的堆出队序」，逐操作复刻 .NET 8 的 4 叉堆。

### 2.1 新增 `bins/game-svr/src/msgqueue.rs`（+225，lib 导出）

`NetPriorityQueue<T>`：`.NET PriorityQueue<TElement, TPriority>`（`TPriority = u8`）的**出队序等价物**。

- `.NET 8` 是 **4 叉**最小堆：`GetParentIndex(i) = (i-1) >> 2`、`GetFirstChildIndex(i) = (i<<2)+1`；
- `enqueue` = .NET `MoveUpDefaultComparer`（严格小于父才上浮）；
- `dequeue` = root 取出 + **末元素回填根** + `MoveDownDefaultComparer`
  （4 个孩子里取**首个**最小者；末元素 `<=` 选中子时停）；
- 单测 `matches_dotnet_priority_queue_dequeue_order` 钉 n=1..12 的实出队序
  （与 net8.0.26 实跑逐位对齐，见 `msgqueue-dotnet-ref.txt` / `dotnet-pq8-source-excerpt.txt`）；
- 单测 `ties_are_not_insertion_order` 钉「同优先级 ≠ 入队序」这一 F-1 根因。

`lib.rs` +1 行：`pub mod msgqueue;`（bin 与集成测试共用）。

### 2.2 `main.rs::drain_slave_mutiny_downlink`（改：两循环 → 堆）

- 新增局部 `enum MutinyFrame { NameColor{sid,color}, UserName{sid,color,show_name} }`；
- 对每个观察者，按 **oracle 入队序**（每只宝宝 `RefNameColor(); RefShowName();`，
  `PlayObject.Base.cs:351-352`）`enqueue` 进 `NetPriorityQueue`
  （优先级 = `(byte)wIdent`：色 154、名 165），再 `dequeue` 逐条编码下发；
- **不再**用「所有色循环 + 所有名循环」；
- 函数头「次序」段改写为堆出队序说明（含 F-1 的实例），并补一条登记：
  本模块只复刻堆算法，混合队列（入队前已有其它消息）场景 `not_verified`（R 级）。
