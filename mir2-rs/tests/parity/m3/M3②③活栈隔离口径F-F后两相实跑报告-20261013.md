## 5. 根因定位：C# 专用流按**调用点**共享（第一分歧在 index=0，class=`base_unit`）

`requests/40-analyze-clean.txt`（cA2 vs rA2）：

```
第一处请求分歧 index(0based)=0  class=base_unit
  csharp: atk_power_base(1)->0    # BaseObject.GetAttackPower@BaseObject.Base.cs:892（非 PlayObject 攻方）
  rust  : atk_power_a(2)->0       # combat.rs:109（玩家攻方）
```

- **C# 专用流的第一条取数就是 `atk_power_base`**：在玩家攻方首次出手**之前**，进程里另一实体已抽了同一条
  `Random(attack_seed)`。数量上 C# 多出 `atk_power_base +11`、`hit_gate +11`（131 vs 120）。
- **机制（事实）**：C# 影子 hook 的隔离是**按调用点**（`divert-sites.txt` = `attack_sites.tsv` 的 `divert=1` 行），
  **不按攻方实体** ⇒ 进程里任何实体走这些站点时抽的是**同一条专用流**。本片能直接证的：
  **C# 流里混入 11 次 `atk_power_base`（base unit）**，第一分歧即落在 base unit。
- **并发（假设，未单独证）**：这 11 次来自「同一 `GameSvr` 进程其它地图上的怪物/守卫在测量窗口内出手」，
  `0137` 本身零刷怪（owner 已核）。m3bag 正在查证那个非玩家攻方是谁；若证伪，则改用「按攻方实体分流」。
- 在「并发非玩家攻方」假设下，这解释了 C# **不可复现**：其抽取时机每次不同 ⇒ 同种子下玩家每击拿到不同 draw
  ⇒ `cA vs cB=242`、`c1 vs c2=328`。
- 请求**模板形状**两侧已一致（`requests/42`）：miss=`atk_power_a,atk_power_b,hit_gate,attack_success`；
  hit=再带 `hit_struck_damage,hit_struck_damage2,struck_durability`。⇒ 分歧是「抽到的值不同 ⇒ 命中/躲闪序列不同」，
  **不是**结构缺站点。

> **结论**：本隔离口径的必需补强 = 专用流按**攻方实体**分流（ActorId/对象引用），或保证测量窗口内除被测量攻方
> **零攻击者**。这不是判据问题、不是统计/集合降级；属夹具/接线**设计**层，请 owner 定归属（建议 m3bag）。
