## 1. 本片解决的 DoD③ 问题（第三轴：`DoSpell` 之外的可达性）

第五片的 `skill-probe` 把真魔表里 `IsWarrSkill`（`MagicManager.cs:82-100`）命中的 **8 行**
登记为 `warr_reject`，reason 写「`DoSpell` 前置即 `return false`；承接 = 战士技能走 ClientHit/Attack 路径」。
第七片只按 `MagicManager` 的私有方法做了可达性分类——这 8 行在那一轴里是「前置拒绝」，**看起来像没有效果体可达**。
实际情况是：它们的**效果在 `PlayObject` 的近战路径**（`RecalcHitSpeed` / `GetAttackPowerHit` / `SkillAttackDamage` / `DoMotaebo`）。

本片把这条路径补上，并只对其中**能独立反射直调**的两个入口产真身向量；不可独立调的 4 行**只登记 + source-cited**，不冒充真身：

| 3 | 基本剑术 | `RecalcHitSpeed`（`HitPoint`） | `probeable` |
| 4 | 精神力战法 | `RecalcHitSpeed`（`HitPoint`） | `probeable` |
| 7 | 攻杀剑术 | `RecalcHitSpeed`（`HitPlus`）+ `GetAttackPowerHit`（mode 3） | `probeable` |

## 2. oracle 事实（逐行核过，含行号自检）

1. **`PlayObject.RecalcHitSpeed`（`src/M2Server/Player/PlayObject.cs:3659-3713`，protected）**：
   `HitPlus = 0; HitDouble = 0;` → 按 `Job` 选 `SystemShare.Config.BonusAbilof{Warr,Wizard,Taos}` 写
   `HitPoint`/`SpeedPoint`（**道士分支不写 `HitPoint`**）→ 遍历 `MagicList`：
   基本剑术(3) `HitPoint += (byte)Round(9/3.0*Level)`；精神力战法(4) `+= (byte)Round(8/3.0*Level)`；
   攻杀剑术(7) `+= (byte)Round(3/3.0*Level)`、`HitPlus = (byte)(DEFHIT+Level)`、
   `AttackSkillCount = (byte)(7-Level)`、`AttackSkillPointCount = RandomByte(AttackSkillCount)`（**Level 为 0 也取数**）；
   烈火剑法(26) `HitDouble = (byte)(4+Level*4)`。
2. **`PlayObject.GetAttackPowerHit`（`src/M2Server/Player/PlayObject.Attack.cs:579-625`，protected）**：
   `canHit = false`；目标非 null 时 mode 3(且 `PowerHit`) `nPower += HitPlus; canHit = true`，
   mode 7(且 `FireHitSkill`)/mode 9(且 `TwinHitSkill`) `nPower = (ushort)(nPower + Round(nPower/100*HitDouble*10.0)); canHit = true`，
   并**清对应标志**；目标为 null 时 mode 3 同式置 `canHit`，但 mode 7/9 **只清标志、不改威力、不置 `canHit`**。
3. **锚点自检**：探针内置 `VerifyAnchors`，读 oracle 源断言
   ①`PlayObject.cs:3659` 首行含 `RecalcHitSpeed(`、②`:3713` 末行 trim == `}`；
   ③`PlayObject.Attack.cs:579` 首行含 `GetAttackPowerHit(`、④`:625` 末行 trim == `}`。任一不符**直接终止**（不出带错行号的向量）——
   与第七片 `MagicManager` 锚点自检同一机制（F-1 行号漂移同族的机器化预防）。
4. **`warr_reject` 集合以已入库 artifact 为准**：探针读 `skill-probe/vectors/skill_vectors.tsv` 的 `reg` 行取
   `dospell_class == warr_reject` 的 id，断言恰 = `{3,4,7,12,25,26,27,34}` 且名字与登记一致；Rust 用例再对一次同一集合。

## 6. 本批哪些项**不等价 / 未做**（含理由与登记去向）

1. **4 行 `map_context` 未产真身向量**（12 `SkillAttackDamage` mode 4 / 25 mode 5 / 27 `DoMotaebo` / 34 mode 8）：
   入口公式可读，但尾调 `SwordLongAttack`/`SwordWideAttack`/`CrsWideAttack`/`DoMotaebo` 需要 `Envir` 与地图目标集；
   `SkillAttackDamage` 的 `nSecPwr` 表达式本身是纯计算，但它和施加同步发生 ⇒ 本片**只 source-cited + 登记**，
   承接待「攻击/魔法接线」（`openmir2` 的 `attack-magic-wiring` 卡）落地后按本片同一口径（真身反射 + 取数账本）续产。
2. **`GetHitMode`（`PlayObject.Attack.cs:84-138`）未产向量**：它把 `wHitMode` 映到 `RM_*` ident，
   依赖 `MagicArr[SKILL_*]` 是否非空；属**协议帧面**，承接 = 攻击接线批次（本片只登记 `GetAttackPowerHit` 的伤害倍率）。
3. **`SkillAttackDamage` 只登记未实装**（同 1）。
4. **`RecalcHitSpeed` 的调用点未接线**：Rust 侧 `world` 目前没有「学技能/升级时重算 HitSpeed」的宿主路径；
   本片只交付**逐行等价的可对拍实现**，接线随攻击/魔法接线批次（写集在 `bins/game-svr`）。
5. **真机 DoD①② 未做**：需 5000/7000/7100/7200 两侧栈（本片不占端口，等 owner 排窗口；窗口优先级按卡面）。
6. **`PlayerJob` 未知值分支**：oracle `switch` 无 `default` ⇒ 两项都不改；Rust 用 `_ => {}` 对齐（不是“当道士算”）。
