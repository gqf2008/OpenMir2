## 0. 一句话结论

**⑩ 的一半在 oracle 里根本不存在；另一半不是「拍卖」，是一套只读且坏的 P2P 元宝寄售。**

1. **邮件：oracle 无任何实现。** 全仓 `src/` 里与 mail 相关的只有 `boShowMail`（客户端界面开关，纯配置）——
   没有邮件实体、没有 `CM_*`/`SM_*`、没有表、没有调用链（证据 `00` §[0]、`01` §[7]）。
   ⇒ §6 的「发送 / 到期 / 退回」**没有 oracle 行为可对齐**，属 `oracle_absent`；**不得自行发明**一套邮件去「对齐」。
   请 owner 按 §6.0-3 登记判据处置（见 §3 建议）。
2. **拍卖 = 两套，且都不是「带出价 / 佣金」的拍卖行**：
   - **5700 `MarketSystem` 寄售行**：源码存在，但**死接线**——不被任何 `.csproj` 引用、现网 `M2GameSvr` 未部署
     （无 `modules.json` / 无 `Plugins/` / 无 `MarketSystem.dll`）、存储 SQL 指向的 `marketitems`/`marketitem`
     **表不在冻结 schema**、四个搜索分支全是空桩、`MarketItem` 未注册 MemoryPack ⇒ 线上任何携带它的帧都抛异常
     （证据 `02`）。**Rust M1 S4b 已 1:1 实现该面**（含空桩 / 抛 / 不可达），此面**无新缺口**。
   - **`元宝寄售`（`goldsales`）**：**活代码**（`M2Server/Player/PlayObject.Sale.cs` + `PlayObject.Message.cs` 派发 +
     `GameSrv/Npc/Merchant.cs` 入口），但是**只读且坏**——启动加载读**错列名**（`DealChrName` vs DDL `DealCharName`）
     ⇒ 恒加载 0 行；`SaveSellOffItemList` **所有调用点被注释** ⇒ **永不写库**（证据 `00` §[1]、`02` §[F]）。
     Rust：`crates/data` 加载器已 1:1（bug-replica `D-5`/`B-5`），**世界侧 7 个 `CM_SELLOFF*` 派发 + `DealOffInfo`
     世界态 + 帧 = 未实现**（`rg` no match，证据 `01` §[5]）。

**⇒ ⑩ 的实质缺口 = 世界侧元宝寄售派发 / 世界态 / 帧（+ 启动时 `goldsales` 只读加载接线）；DB 面已由 M1 S4b / D 线覆盖；
邮件无 oracle 行为、不是「未实现」，是「无物可对」。**

1. **上架一致**：固定起点 + 固定动作（`CM_SELLOFFADDITEM` → `CM_SELLOFFEND`）下，两侧
   `M2Share.SellOffItemList` 的条目（卖家/买家名/`nSellGold`/`Flag`/`UseItems[9]`/`dSellDateTime`）与
   `RM_SELLOFFEND_OK/FAIL` 帧序列一致；失败门（`nSellGold` 范围、不能自己买自己、`SellOffItemList.Count<10`）返回一致。
2. **成交一致**：买方 `CM_SELLOFFBUY` ⇒ 两侧「买方 `GameGold` 扣减 = `nSellGold + DecUserGameGold(10000)`」、
   「卖方 `GameGold` 增加 = `nSellGold`」、「物品进买方背包/落地」、「`RM_SELLOFFBUY_OK` + `RM_MENU_OK` 文案」一致；
   覆盖卖方在线 / 离线（`Flag=1` 待取）两档，以及 `GameGold` 不足档。
3. **退回 / 取消一致**：`CM_CANCELSELLOFFITEMING`（卖方）与 `CM_SELLOFFBUYCANCEL`（买方）后，物品/元宝回流与
   `Flag`/帧一致；金刚石特判档（`nCode==short.MaxValue`）一致。
4. **DB 落库字段级 diff = 0**：这里的 oracle 真实行为是
   - **读**：启动加载 `goldsales`，因读错列名（D-5）⇒ **两侧都恒加载 0 行**；
   - **写**：`SaveSellOffItemList` **无调用点** ⇒ **两侧都不写**。

   ⇒ 判据不能是「两边都写出一致行」——那需要先改 oracle（禁止）。**正确口径**：对拍结束时 `goldsales` 表
   **行数与逐列内容在两侧会话前后完全相同（diff=0，且增值 = 0）**，并**显式断言「上架/成交/退回都不落库」**。
   这是 §6 词面「diff=0」在 **oracle 真实语义**下的落实（**不是降级**：加了「两侧都不写」这个非平凡断言）。

> **判据总口径（建议）**：`selloff_diff.py diff = 0`（逐帧 + 逐字段 + `goldsales` 表快照逐列），
> 且 `goldsales_delta == 0`（两相 BEFORE/AFTER 一致）作为**非平凡门**（表为空也须证明「加载 0 行」这一读路径走过）。
