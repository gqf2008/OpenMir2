## 1. 问题（reviewer-6 M-3，原文要点）

> 标量帧参数表在 `npc_shop_scenario.json.frame_scalar_fields` 与
> `npc_shop_diff.py.DEFAULT_FRAME_SCALAR_FIELDS` 各存一份，且 `run_npc_shop_pair.ps1` 调 `diff`
> 时未把场景的 `frame_scalar_fields` 透传 `--frame-scalars` ⇒ 窗口期只改场景这一项**不会**改变判据
> （当前两份一致，无现实漂移）。建议比较器读场景或 runner 显式透传，保持单一真源。

即：`npc_shop_diff.py` 头部注释写的「**窗口期可按真机实测补/删（改场景即改判据）**」当时是**假的**
——runner 不透传、比较器不读场景，判据实际来自比较器内建常量。

## 2. 处置（单一真源 = 场景）

1. `npc_shop_diff.py`
   - 新增 `--scenario <path>`：给定后，`frame_scalar_fields` 由场景解析，作为**判据真源**；
   - `load_scenario_frame_scalars()` fail-closed：缺文件 / 非法 JSON / 缺
     `frame_scalar_fields` 键 / 键非整数 / 值非字符串数组 ⇒ **`Prereq`（rc=2）**，绝不静默退回内建表；
   - `--scenario` 与 `--frame-scalars` **互斥**（判据真源只能一个；同时给 ⇒ rc=2）；
   - 无 `--scenario` 时保留内建 `DEFAULT_FRAME_SCALAR_FIELDS` 作为 ad-hoc 回退（runner 总是传场景）。
2. `run_npc_shop_pair.ps1`
   - `Invoke-ShopRawDiff` 透传 `--scenario $ScenarioFile`；
   - 顺带修一处 fail-closed 保真：比较器返回 **rc=2（PREREQ）** 时，runner 现在**保留 2**，
     不再把它压成 `RED=1`（否则上游分不清「有差异」与「判据缺件」）。`DiffOnly` 直接 `exit $ShopDiffRc`。

**行为影响**：真机/离线口径下，判据内容与改前**相同**（当前场景声明 == 内建默认），
但「改场景」现在**真的**改判据了。默认关（无 `--scenario`）路径不变。
