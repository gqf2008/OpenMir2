# M3 夹具链深检门（`fixture_chain_gate.py`）报告 — 2026-10-13

卡：`openmir2-m3-fixture-chain-gate`（companion 至 `openmir2-m3-fixture-matrix`）。

## 1. 要解决的问题

`fixture_matrix.py`（M3 夹具矩阵与就绪度门）刻意只做**轻量**核对：三件套在场 + 比较器
`selftest`，以便**高频跑、不依赖 dotnet**。但 M3 的十副动作序列夹具**共享同一条工具管线**
（`src/BotSrv/**` + `mir2-rs/tests/parity/m3/{run_pair,gate_guards}.ps1` +
`tools/botload/run_bots.ps1`），每合并一张夹具卡都要在这 9 处**并集解冲突**——owner 本日已两次
手工解（⑥-5 / ⑦-5 / ⑩-3 一轮、⑧-10 / ⑨-5 一轮）。而矩阵门**不跑**各夹具驱动自己的
`-SelfCheckNoStack`，所以「共享管线被后来的一张夹具卡踩坏、把早先的夹具弄红」这件事
**没有单条命令的机判面**。

本件补上这一层：把 owner 手工做的「夹具链未劣化周期复核」变成**一条命令**。

## 2. 设计（单一真源 + 深检）

- **登记表不复制**：`fixture_chain_gate.py` `import fixture_matrix`，直接用 `fm.MATRIX`
  （三件套 / T 号 / 承接卡）与 `fm.evaluate`（比较器面口径与矩阵门**逐字一致**，含 `--require-all`
  的 whitelist T 号核对）。⇒ 无第二真源（reviewer 在别处点过的 duplication 坑）。
- **对每个 current-tree `READY` 的系统额外跑** `runner -SelfCheckNoStack`（离线、零端口）：
  rc=0 ⇒ `RUN-OK`；rc=2 ⇒ `PREREQ`（驱动自己声明的「前置未到」fail-closed）；其它 rc ⇒ `RED`。
- **共享管线自检**：`tools/botload/run_bots.ps1 -SelfCheckNoStack` 与
  `mir2-rs/tests/parity/m3/selftest_gate.ps1`（路径相对仓库根 `REPO_ROOT` 解析）。
- **fail-closed 口径**：缺件 / `PENDING` / runner `PREREQ` / 共享管线缺件 **默认只登记**，
  `--require-all` 判 `RED`；**在场却坏**（比较器 selftest rc≠0、runner rc∉{0,2}、共享管线 rc≠0）
  与 `INCONSISTENT`（半拉子合并）**恒 `RED`**；绝不对「没跑」判绿。
- `selftest` 用**注入式 stub**（`run_runner` / `run_shared` / `run_comparator` 可替换）覆盖
  三级分类、`--require-all`、共享管线红/缺件、以及「删 runner ⇒ INCONSISTENT」改坏必红。

命令：

```sh
cd mir2-rs/tests/parity/m3
python -I fixture_chain_gate.py selftest
python -I fixture_chain_gate.py check [--require-all] [--skip-shared] [--json OUT] [--evidence-dir DIR]
```
