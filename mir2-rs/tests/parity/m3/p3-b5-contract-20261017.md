## 0. 结论摘要（先看这里）

1. **四魔号按 ID + `MagicConst.cs` 常量钉死**：**9 `SKILL_FIRE`（地狱火）**、**10 `SKILL_SHOOTLIGHTEN`
   （疾光电影）**、**22 `SKILL_EARTHFIRE`（火墙）**、**36 `SKILL_UENHANCER`（常量注释「无极真气」，
   部署行却是「火焰冰」，Job=1 法师 48 级）**。oracle **只看 `MagicId` 分派**（`MagicManager.cs:172`）
   ⇒ 法师放「火焰冰」执行的是 `AttPowerUp` 友方加攻逻辑，**不得按名字/职业改语义**。
2. **RNG 账本（成功路径，`Luck==0`，玩家施法者）**：
   - 9/10：施法 tick **4 + 逐格 `R(10)`（≤12）**；10 的 `undeadAttack=true` 会让 `magPwr` **逐次 ×1.5 复合**
     （第一击就 ×1.5，第二击再 ×1.5，**不是只对不死系**）。
   - 22：施法 tick **5–6**（`MPow`+`GP`+`AP(2)` = 4，再 `GP(10)` 1，再 `RP` 0/1）；事件落地**本身零抽**。
   - 36：施法 tick **4**（`R(Level)` 1 —— **`Level==0` 也推进一次**；`GP13` 1；`AP` 2）。
   - 尾抽 `Random(3)+1` 仅当 `boTrain` 且训练门过；`R(0)` 也推进（`RandomNumber.cs:93-100`）。
3. **9/10 的 `RM_MAGSTRUCK` 是 600ms 延迟消息**（**调用点** `BaseObject.cs:912`；**定义**在
   `BaseObject.Message.cs:234-252` 的带显式 actorId 重载 `SendStruckDelayMsg`），
   **不在施法 tick 的帧序里**；投递 tick 还要抽 `R(1000)`（条件）+ `MSD` 的 `R(|Hi(MAC)-Lo(MAC)|+1)`
   （`BaseObject.Base.cs:620/624/814`）。本仓 **`Entity` 无 `MAC`、无 `RushMode`、无 MSD 实现**
   ⇒ 这是 B5 的硬前置（§6 P-B5-0）。
4. **22 的 `FireBurnEvent` 事件子系统在本仓完全未建模**（无事件表、无 `GetEvent`、无事件处理器/`RunTick` 门、
   无事件格对象）。B5 必须落一个最小事件模型，并照搬三个 oracle 缺陷：`MapEvent.Id` 恒 0、
   `CellObjectMgr.TryAdd(0, …)` 第一条胜、`FireBurnEvent` 的首次伤害门用**进程 uptime**（`FireRunTick=0`）。
5. **36 的 `AttPowerUp` 不是只发 52**：`AttPowerUp` 先 `SysMsg("物理攻击力增加…")`（→ `SM_SYSMESSAGE(100)`）
   再 `RecalcAbilitys()` 再 `SendMsg(RM_ABILITY)`（→ `SM_ABILITY(52)`）。**`IsProperFriend` 对玩家施法者
   只放行 `Race==Play`**（`PlayObject.Attack.cs:757-820` 的 `Race < Animal` 提前返回 + 基版对非玩家返回
   false）⇒ 36 只会 buff 玩家（含自己）；`(IPlayerActor)` 强转在玩家路径**结构安全**。若未来有路径绕过 `IsProperFriend`
   把非玩家目标送进 `AttPowerUp`，oracle 会抛 `InvalidCastException` 被 `PlayObject.Base.cs:1525-1529` 吞掉 ⇒ 639、无尾；
   Rust 保留该防御臂但当前不可达（§3.4）。
6. **帧序必须按「每收件人 .NET 优先级队列」判，不是发送调用序**：`ActorEntity.MsgQueue` 是
   `PriorityQueue<SendMessage, byte>`（`ActorEntity.cs:16-22`），`SendMsg` 用 `(byte)wIdent` 作优先级
   （`BaseObject.Message.cs:94/181`）。因此 36 的目标端 **17(24) → 52(67) → 638(136) → 100(252)**；
   施法者端 **638(136) 先于 642(141)**。**所有收件人（含自己）都先入队**：`RM_SPELL` 的自投递
   在 `:1455` 被 `ActorId != ActorId` 自守卫吞掉线上帧，但仍占一个 17(24) 队列项（§2.5）。仓内已有逐位复刻 `.NET` 4 叉堆的 `game_svr::msgqueue::NetPriorityQueue`，
   B5 必须用它（或显式登记 `T-*`）。P2/B1 测试断言的是发送调用序，**与 oracle 不同**（§7-2）。
7. **可复算性**：本件给出三条一致路径 —— 手写 max 序列、`mir2_shared::rng::RandomNumber::with_seed(20261017)`
   实测、独立 Python 版 .NET legacy `System.Random` 转录；逐项相同（§4）。
8. **目标 `AntiMagic` 注入面已落地**（`ab73cc645` 引入 `Entity::anti_magic` 与
   `spell_target_anti_magic`）⇒ 计划件 §6.1-2 的「未定前 B1/B4/B5 不开工」**已解除**（仅 AntiMagic；
   AntiPoison 与 B5 无关）。

### 2.3 收件人语义（必须逐字复刻）

1. **`SendRefMsg`**（`BaseObject.Message.cs:383-450`）：`ObMode/FixedHideMode` ⇒ 只给自己；

4. **`SendSelfDelayMsg`**（`:188-206`）：投递到 **this 自己的队列**，`DeliveryTime=now+dwDelay`、

   `GetMessage` 未到点重新入队（`:339-342`）。
5. **`SendStruckDelayMsg`（带显式 actorId 的重载，`:234-252`）**：投递到 **this（被击中者）自己的队列**，

### 2.8 22 的地图事件模型（FireBurnEvent）

oracle 结构：

- `MapEvent` ctor（`src/Modules/SystemModule/MagicEvent/MapEvent.cs:60-85`）：
  `OpenStartTick=now`、`ContinueTime=dwETime`、`RunStart=now`、`RunTick=500`、`Visible=true`；

  `CellObjectMgr.Add` 是 `ConcurrentDictionary.TryAdd`（失败静默，`CellObjectMgr.cs:10-16`）
  ⇒ **只有第一条 id=0 的事件进入管理器**；`GetEvent` 返回的是管理器里的第一条，不是当前格的对象。
  `MagMakeFireCross` 只判 `GetEvent != null`，所以「是否已有事件」= 该格 ObjList 里有 Event 格对象
  **且** `CellObjectMgr` 里存在 `CellObjId=0` 的已注册事件；**只有格对象、没有注册事件时 `GetEvent`
  仍返回 null**（该格会被重复新建），返回值对象本身不影响 22；但 `WalkTo` 的踩火伤害（`BaseObject.cs:1551-1565`）会取到**第一条**事件的
  `Damage/OwnBaseObject`（第二个火墙格的踩火伤害是错的，照搬）。
- **BUG-REPLICA 2**：`FireBurnEvent.Run`（`FireBurnEvent.cs:23-43`）用**自己的** `FireRunTick`（初值 0）
  做 `now - FireRunTick > 3000` 门 ⇒ 服务器 uptime >3000ms 时**第一次 Run 就造成伤害**；
  之后每 >3000ms 一次。`base.Run()` 的关闭门是 `now - OpenStartTick > ContinueTime`（**严格大于**）。
- **BUG-REPLICA 3**：`new FireBurnEvent` 即使 `AddMapEvent` 因越界/不可走而 no-op，事件仍被
  `EventMgr.AddEvent` 追加到全局列表（`EventManager.cs:37-40`）⇒ 越界格也建事件、也参与事件处理器轮询（`RunTick=500ms`）；
  `GetEvent` 对无 Event 格对象的格子返回 null ⇒ 可重复叠事件。
- 处理器（`EventProcessor.cs:27-60`，事件循环 `:31-48`）：计时器周期 **20ms**；每个事件受自己的
  `RunTick=500ms` 门（`now - RunStart > 500`），遍历 `Events` **逆插入序**
  （`for i=Count-1 downto 0`），`Active && now-RunStart > RunTick` ⇒ `RunStart=now; Run();`；
  `Closed` ⇒ 移入 `ClosedEvents`（5 分钟后清）。`Closed` 的事件不再 `Run`。
- `FireBurnEvent.Run` 对格内 `GetBaseObjects(nX,nY,true)` 的每个对象：
  `OwnBaseObject != null && OwnBaseObject.IsProperTarget(obj)` ⇒
  `obj.SendMsg(OwnBaseObject, RM_MAGSTRUCK_MINE, 0, Damage, 0, 0)`（`FireBurnEvent.cs:34-37`）。
  `RM_MAGSTRUCK_MINE` 与 `RM_MAGSTRUCK` 共用处理器（`BaseObject.Base.cs:618`），但
  **`R(1000)` 只对 `RM_MAGSTRUCK` 生效**（`:620`），`GetMagStruckDamage` 的 `MSD` 照抽（`:624`）。
- 踩火（`BaseObject.cs:1551-1565`）：`WalkTo` 到达格若有 Event 且 `OwnBaseObject.IsProperTarget(this)` ⇒
  `SendMsg(OwnBaseObject, RM_MAGSTRUCK_MINE, 0, mapEvent.Damage, 0, 0)`。B5 只要求事件表可被这条路径命中；
  移动接线不在本批。
