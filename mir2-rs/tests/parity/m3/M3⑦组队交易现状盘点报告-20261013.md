## 0. 一句话结论

**组队与交易在 oracle 里都是「会话内内存状态机」**（组队 = `GroupOwner: int` + `GroupMembers: IList<IPlayerActor>`；
交易 = `Dealing`/`DealCreat`/`DealItemList`/`DealGolds`/`DealSuccess` + `DealLastTick` 时间门），**两者都不落库**
（唯一的持久列是 `characters.AllowGroup` / `AllowGroupReCall` 两个**开关**，以及交易结算后写回背包/金币的既有存档路径）。

Rust 现状（逐条证据见 §2）：

- ✅ **常量表齐全**：35 个组队/交易 `CM_*`/`SM_*`/`RM_*` 常量在 C# 与 `crates/protocol` **两侧 35/35** 都在。
- ✅ **角色记录 `allow_group`/`allow_group_re_call` 已解析/重编码**（M2 record-fields）；进图帧 50 的 `Tag1` 已接。
- ⚠️ **拾取归属的 group 分支与 `Dealing` 守卫「已建模但恒死」**：`bins/game-svr` 的接缝有 `group_owner`/`group_member_actor_ids`/`dealing`
  字段，但 `main.rs` 一律传 `0`/`&[]`/`false`（无组队/交易系统）。
- ⚠️ **`HAM_GROUP` 攻击模式「不同」**：`crates/world` 明写 `IsGroupMember` 未建模 ⇒ 按 oracle 语义会**误允许**打同组成员。
- ❌ **服务端无组队/交易实体、无派发、无帧发送**：`bins/game-svr` 对 `CM_GROUPMODE/CREATEGROUP/ADDGROUPMEMBER/DELGROUPMEMBER`
  与 `CM_DEAL*` **全部 no match**；`GroupOwner`/`GroupMembers`/`DealItemList` 在 `crates/world`/`bins/**` **无对应结构**；
  `crates/data` **无** `GroupMembersMax`/`TryDealTime`/`DealOKTime`/`CanNotGetBackDeal`/`DisableDeal` 配置项。
- ✅ **夹具侧现成件很多**：BotSrv 已有**全部**组队/交易**发送原语**（`RobotPlayer.cs:3112-3196`）并能观测**全部**组队/交易
  `SM_*` 帧（`RobotPlayer.Operate.cs:1212-1380`）——但**这些发送原语当前无任何调用点**；`run_attack_pair.ps1` 的
  「两相 pin + 会话入库 + peer 双护栏」可直接套用到「两条假人连接」的组队/交易场景。

⇒ 本卡 DoD②③ 的**真缺口 = 服务端「状态机 + 收包派发 + 帧」**（+ 一个把 BotSrv 发送原语接起来的动作序列夹具）；
落库面与 oracle 一致（**不落库**），DoD 的「落库一致」= 两侧都不写组队/交易态、都只写 `characters.AllowGroup`/背包金币。
本片**未起栈、未占端口、零 `.rs`**。

## 4. 判据设计草案（DoD②）与夹具可复用性（DoD③ 口径）

### 4.1 §6 原文判据（不放宽）

> 「组队/交易：**两人及以上**：**归属、分配、取消、掉线中断**的结果一致。」

拆成四条机判（**全部需要两条假人连接**）：

1. **归属一致**：固定起点 + 固定动作序列下，两侧的**物品归属结果**逐项相同——`OfBaseObject`/`DropBaseObject`
   在「自己拾取 / 组员拾取 / 非组员拾取 / 团长 ghost / 超 `FloorItemCanPickUpTime`」五种情形下的
   可拾取判定与 `RM_ITEMHIDE`/`SM_ADDITEM` 结果帧序列一致（复用 ① 的拾取会话 + `scoped_diff` 的
   `characters_bagitem` 作用域）。
2. **分配一致**：`GainExp` 组队分配后两侧 `Abil.Exp`/等级逐字段相同（覆盖 `HighLevelKillMonFixExp` 两档、
   相同/不同地图、距离 ≤12/`>12`、成员死亡；**必须含「漏比 `CurrY`」的 oracle BUG 向量**）。
3. **取消一致**：`CM_DEALCANCEL` / `DealOKTime` 太快 / 容量不足 / `CanNotGetBackDeal` 四类取消路径下，
   两侧的**帧序列**（`SM_DEALCANCEL` 等）与**交易前后背包/金币**（`GetBackDealItems` 归还）逐项相同。
4. **掉线中断一致**：一侧假人在交易中/组队中被断线，另一侧的下一 tick 行为一致——交易 ⇒ `DealCancel`
   （跑循环 `GetPoseCreate()!=DealCreat` 或断线 `DealCancelA`），组队 ⇒ `DelMember`（`Disappear`）且团长掉线整组散；
   判据 = 存活侧的帧序列 + 会话态 + DB 快照 `scoped_diff --canonical` diff = 0。
5. **落库一致（= oracle 的「不落库」）**：动作后两侧 DB 快照在 `characters`（组队/交易**无专列**）与
   `characters_bagitem`/`Gold`（交易副产物）上 diff = 0；组队/交易态本身**两侧都不新增行/列**。

### 4.2 夹具可复用性

- **两条假人连接 = 现成路径**：`run_attack_pair.ps1` 已实现「`-Bots 2` 两条连接 + 两相 pin（预热建角 → SQL pin →
  BEFORE 快照 → 计分跑）+ `-PeerSession` 跨侧比对」，并带**四个 peer 护栏**（`Get-M3PeerScenarioGuard`
  /`Get-M3PeerAttackScopeGuard`/`Get-M3PeerAttackPoseGuard`/`Get-M3PeerIsolationGuard`，`gate_guards.ps1:262/1562/958/147`）。
  组队/交易对拍**直接复用这条路径**，只把「攻击序列」换成「组队/交易动作序列」。
- **BotSrv 现成件**：全部组队/交易**发送原语**已存在（`RobotPlayer.cs:3112-3196`）——夹具卡只需把它们**接进动作序列**；
  全部组队/交易 `SM_*` 帧的**观测**也已存在（`RobotPlayer.Operate.cs:1212-1380`）——夹具可直接从 bot 日志取帧序列。
- **DB 侧判据现成**：`scoped_diff.py diff --canonical --fixed-newchr`（selftest 14/14）可直接用来判「交易副产物落库」。
- **不要重造**：`run_pair.ps1` 的 pin/会话/快照/`SHA256SUMS` 口径、`run_attack_pair.ps1` 的 peer 护栏、`server_state_gate.py`
  的 fail-closed 风格都可原样搬；新夹具只新增「动作序列 + 组队/交易比较器」。

### 4.3 缺口对 DoD②③ 的阻塞关系

DoD②③ 需要**服务端真的收包并回帧**；在 `2`/`3`（组队/交易状态机 + 派发 + 帧）落地前，夹具即使接好
也只会得到 `SM_DEALTRY_FAIL`/无回帧 ⇒ **DoD②③ 阻塞于承接卡 `1`→`2`/`3`→`5`**，本片只交 DoD①。
