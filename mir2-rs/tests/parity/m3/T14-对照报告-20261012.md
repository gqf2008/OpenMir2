## 3. 本片修出的两处**夹具竞态**（只影响 `-PinStartPose` 路径）

owner 06:5x 的「固定起点 + 固定初始背包」两相 pin 口径**第一次真机跑就暴露两处夹具问题**（都在夹具面，`BagEquipSequence=false` / 非 pin 路径逐字节不变）：

### 3.1 预热建角恒假红（`tools/botload/run_bots.ps1`）

- 现象（修前，`run-prefix-prewarm-fail.txt`）：`PROGRESS … login_ok=0/1` → `RED: 登录成功 0/1 未达标` → `预热建角失败`。
  但 bot 日志里账号/角色**都已建出**（`帐号创建成功`/`创建角色`）。
- 根因：`-RequireCharCreated` 的 break 只判日志里的「创建角色」标记（登录后立即落），
  而 `load_stats.ndjson` 的 `login_ok` 是 BotSrv **每 5s 采样**一次 ⇒ 采样边界提前 break，读到上一拍的 `login_ok=0`，
  末尾成功判据（`$success -ge $Count`）恒假红。
- 修法：`$RequireCharCreated` 分支 break 条件改为 `charCreated >= $Count -and $success >= $Count`（另等一拍日志采样）。

### 3.2 SQL pin 被预热掉线存档**异步覆盖**（`mir2-rs/tests/parity/m3/run_pair.ps1`）

- 现象（修前，`run-pre-settle-pin-race-*.txt`）：`baseline.json.start_pose` 记录的是 pin（`289,618`/`90000001…`），
  但 C# 侧实际进图是**预热末态** `CM_PICKUP x=285 y=622`、`make=36685075`；
  跨侧 diff 因此多出 `CX/CY/Dir` + `bagitem` 3 行的 `MakeIndex`。Rust 侧一直用 pin（`289,618`/`90000002`）。
- 最小实验结论（owner 06:5x 要求的那条）：**SQL pin 确实写进去了，但随后被预热相的异步断线存档覆盖**。
  - pin 后校验命中（BEFORE 快照 = `289,618`、`MakeIndex=90000001..4`）；
  - 预热 BotSrv 被 kill ⇒ oracle `WorldServer.SaveHumanRcd`（`src/GameSrv/Word/WorldServer.cs:1077`）→
    `FrontEngine.AddToSaveRcdList` → 异步落库，若晚于 pin 则把 pin 覆盖；
  - 排除「ghost 复用」：`PlayObjectFreeList` 只用于超时清理（`:583-589`）与广播（`:899`），
    进世界一律 `new PlayObject()` 重新取档（`:234`/`:246`），不按 ChrName 复用 ghost。
- 修法：pin 后加 **settle + hold 循环**——pin → 等 3s → 复验「图/坐标/Level + 背包 4 件 + Abil.Level」，
  被覆盖则重 pin，最多 5 轮；仍 hold 不住 ⇒ `throw`（fail-closed）。修后 `PIN_HOLD attempt=1`，
  C# 侧 `CM_PICKUP x=289 y=618`、`make=90000002`，与 Rust 逐条相同。

## 5. `IncHealth` 差异的根因（源码 + 真身探针）

1. pin 的药品 `金创药(小量)`（`StdIndex=3`）模板（`mir2_data.stditems`）：`StdMode=0, Shape=0, Ac=20, Mac=0`。
2. **吃药即时**：oracle `EatItems` case 0 default 分支 `if (stdItem.AC > 0) IncHealth += stdItem.AC;`
   （`src/M2Server/Player/PlayObject.Base.cs:2073-2076`）⇒ `IncHealth = 0 + 20 = 20`；
   Rust `useitem.rs` 同分支同结果（=20）。**这一层两侧一致**，真身探针
   `tests/parity/m3/fixtures/eat_vectors.json::eat_ok_shape0_inc_pool`（`inc_health 3→18`）证明「即时叠加」语义。
3. **oracle 周期 tick 把它消费掉**：`src/M2Server/Player/PlayObject.Message.cs:70-141`——
   当 `IncHealth/IncSpell/IncHealing > 0` 时，每 `dwInChsTime = 600 - _MIN(400, WAbil.Level*10)` ms（1 级=590ms）
   按 `PerHealth=Level/10+5=5` 把 `IncHealth` 消费回 HP，且消费后 `if (WAbil.HP == WAbil.MaxHP) IncHealth = 0;`。
   pin 的 `characters_ablity` 把 `Hp = MaxHP = 19`（满血）⇒ 吃药后第一次 tick 即把 `IncHealth` 归零。
4. **Rust 无此子系统**：`bins/game-svr` 是事件驱动的（`CM_EAT`/`CM_TAKEON*`/… 状态迁移 + 断线存档），
   **没有玩家周期恢复 tick** ⇒ 存档保留 20。
5. 存档链两侧都写 `IncHealth`（oracle `PlayDataStorage.Save.cs:86/112`；Rust `main.rs:1519`）⇒ 差异来自内存值，不是落库丢字段。

结论：这是**未实现**（Rust 缺周期恢复 tick），不是随机、不是夹具放宽。
