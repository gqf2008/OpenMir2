### 1.1 为什么 17/30/41 是 (c)（具体缺什么，不是一句「需要真环境」）

三条方法体唯一的效果是 `playObject.MakeSlave(...)`（`BaseObject.cs:1179-1207`），而 `MakeSlave` 第一句即

```csharp
MonsterObject monObj = (MonsterObject)SystemShare.WorldEngine.RegenMonsterByName(Envir.MapName, nX, nY, sMonName);
```

- `SystemShare.WorldEngine` 是 `IWorldEngine`（`src/Modules/SystemModule/SystemShare.cs:20`），
  生产实现是 **`GameSrv` 宿主**（`src/GameSrv/**`）；探针只引用 `src/M2Server/M2Server.csproj`
  （`M2Server` 不反向引用 `GameSrv`）⇒ 探针拿不到真 `WorldEngine`。
- `RegenMonsterByName` 还要按 `Envir.MapName` 查 **刷怪配置/怪物模板**（`MonsterInfo`，来自
  `Envir` 数据），并真的 `AddMapObject` 出实体；随后 `MakeSlave` 还读 `monObj.WAbil`/`RefNameColor`。
- 30 还要读 `SystemShare.Config.Dragon/DragonArray`、41 读 `SystemShare.Config.Angel`（`GameSvrConf`）。
⇒ **不是探针口径能替代的**：要么起真栈（`WorldEngine` 就绪）调 `DoSpell`/`MakeSlave`，要么把
`WorldEngine` 的最小工作面（怪物模板 + 生成）抽成可离线构造的接口（另一批设计，需 owner 裁决）。

## 4. 向量口径（真身 / 替身分栏，不混称）

- **真身**：`Envirnoment.LoadMapData`（`src/M2Server/Maps/Envirnoment.cs:903`）加载**合成真格式**
  `.map`（52B 头 + 12B/格，列主序，与 oracle 同格式；由探针在临时目录生成，运行结束即删）
  ⇒ 真 `CanWalk`/`MoveToMovingObject`/`AddMapObject`；真 `PlayObject`/`MonsterObject`；
  反射直调 `MagPushArround`/`MagSaceMove`/`MagMakeClone`；`System.Random` 覆盖为记录包装
  （`ReplayRandom` 行式账本）。
- **替身（唯一一处，显式分栏）**：21 的 `SystemShare.MapMgr` 用探针内最小 `IMapSystem` 实现，
  只做 `FindMap` 注册表查找；`MagSaceMove`→`MapBase.MapRandomMove`→`SpaceMove` 的效果路径
  全部真身 M2Server 代码。**不声称** `MapMgr` 本身是真身。
- `char_pushed` 的 Rust 实现先判 `CanWalk`（`cellSuccess`）再 `MoveToMovingObject` 的簿记等价，
  与 oracle `CharPushed`（`BaseObject.cs:854-901`）同序；目标未注册 `ActorMgr` ⇒ 活体阻挡分支
  两侧都不命中（探针口径明确）。
- **可复现性**：探针连续两次运行逐字节相同（`commands/03-probe-repro.txt`；`ActorId` 已固定，
  否则 `Guid` 分配会污染向量）。
