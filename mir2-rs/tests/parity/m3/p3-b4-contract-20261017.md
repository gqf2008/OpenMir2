## 0. 结论摘要（先看这里）

1. **四魔号按 ID + `MagicConst.cs` 常量名钉死**（任务文本里的中文名与常量注释有错位，见 §1.1）：
   **6 `SKILL_AMYOUNSUL`（施毒术）**、**48 `SKILL_GROUPAMYOUNSUL`（群体施毒术）**、
   **50 `SKILL_MABE`（常量注释「冰焰」，部署行「无极真气」）**、
   **42 `SKILL_GROUPLIGHTENING`（常量注释「群体雷电术」，部署行「龙影剑法」）**。
   oracle **只按 `MagicId` 分派**（`MagicManager.cs:172`），部署行的名字/职业不改变分派。
2. **6 的 `boSpellFail` 初值 true**（`MagicManager.cs:226`）：`IsProperTarget(null)` 为假
   （`PlayObject.cs:1926`）⇒ **空目标/非 proper 目标 = 零抽数 + 恰一条 `SM_MAGICFIRE_FAIL(639)`**，
   无 `RM_DURACHANGE`/`RM_MAGICFIRE`/训练尾。只有 `CheckAmulet(1,2)` 过 **且**
   `GetStdItem(...) != null` 才在 `:254` 清 false（**清 false 与骰门是否过无关**）。
3. **48 的护身符是「每目标消耗一次」**（`MagicManager.cs:908/913` 在循环体内）。`CheckAmulet` 失败的目标
   不抽骰、也**不** `SetTargetCreat`（`:934` 在 `if (CheckAmulet)` 内）；`SetTargetCreat` 在代码位置上
   位于 `if (stdItem != null)` **外**——与 6 的 `:253`（在 `stdItem != null` 内）**不对称**，必须照抄。
   该不对称只做结构性登记：`CheckAmulet` 已对同一 slot 强制 `stdItem != null`（`MagicBase.cs:57-58`），
   「目录缺件」分支不可观测（§2.5）。
4. **48 的 `UserMagic.Magic` 行有两条路径，但两行的 RNG 账本完全一样**：
   - 本会话内读「气功波」书 ⇒ `ReadBook` 用 `FindMagic(stdItem.Name)`（`PlayObject.Base.cs:2174`）
     ⇒ 取 `magics.Idx=48`（`DefPower/DefMaxPower=0/0` ⇒ `GetPower13` 的抽是 **`R(0)`**）；
   - 重新登录/读档 ⇒ `WorldServer.cs:1201` 用 `FindMagic(MagicDB.MagIdx)` = **按 MagID 首行**
     ⇒ 取 `magics.Idx=38`（群体施毒术行，`DefPower/DefMaxPower=4/4` ⇒ 同样是 **`R(0)`**：
     `GetPower13` 取的是 `Random(DefMaxPower-DefPower)`，`MagicBase.cs:26`）。
   两行的抽数次数与取值序列完全相同；唯一可区分处是 `GetPower13` 的**基数**
   （Idx=48 ⇒ GP13=33；Idx=38 ⇒ GP13=37，即每个目标 nPower +4）与 **MP**
   （`GetSpellPoint`：6 vs 39）。现有 Rust `MagicTable` 的「首行胜」等于**读档路径**；本会话读书路径在
   `ReadBook`（T-17 未实现）接通前不可达。B4 必须把「传给效果体的 `MagicInfo` 行」做成显式输入，
   两种夹具分别钉死 Idx=48 / Idx=38（断言点用 nPower 与 MP，**不能**用 RNG 账本）。
5. **42 的 null 目标 NPE→639**：`MagGroupLightening` 在循环前 `:987` 直接读 `targetObject.ActorId`；
   `targetObject == null`（无 snap 目标，或目标 `Death` 被 `:160-163` 归一成 null）⇒ NPE ⇒ 被
   `PlayObject.Base.cs:1525-1529` 吞掉 ⇒ 包装层返回 false ⇒ 调用方 `PlayObject.Attack.cs:1280` 发**恰一条 639**。
   此时 `SM_SPELL(17)` 已发（`:159` 在 NPE 之前）、**MP 已扣**（包装层先扣后调）、无 638/无尾。
6. **50 有两相位抽数**：施法 tick 的 4–10 抽（§3.3），以及 **600ms 后两条 `RM_DELAYMAGIC` 的投递**：
   每条投递在投递者侧各抽一次 `GetMagStruckDamage`；命中后目标收到 `RM_MAGSTRUCK`，目标处理时
   **再抽一次 MSD**（`BaseObject.Base.cs:624`），怪物 `Race>=Animal && Level<50` 还抽 `R(1000)`
   （`:622`）。42 的逐目标 `RM_DELAYMAGIC` 同理。**投递 tick 的全局 RNG 交错依赖 actor 调度**，
   只有「每 actor 在其处理点的抽数与取值」可判（§6-2）。
7. **6/48 的毒不在线上帧里**：`RM_POISON` 是目标的自延迟消息，目标处理时 `MakePosion`
   （`BaseObject.Base.cs:740-759` → `BaseObject.cs:1941-1973`）；可观测帧是
   `CharStatus` 变化触发的 `SM_CHARSTATUSCHANGED(657)`（`:1964-1967` → `:1514-1517`），
   目标为玩家时另有 `SysMsg(YouPoisoned)` ⇒ `SM_SYSMESSAGE(100)`。**没有 `SM_POISON` 这种帧。**
8. **帧序按 oracle 的优先级队列判**：立即 `SendMsg` 的优先级是 `(byte)wIdent`（`BaseObject.Message.cs:94/181`），
   自延迟 `SendSelfDelayMsg` 一律 `255`（`:204`）。同一 socket 上 657/642/638 的先后由优先级决定，
   **不是按入队序**（例：6 成功路径 SELF 上 `53 → 638 → 642`，不是 `642 → 638`）。
   同优先级（如 48 的多条 `642`）在 .NET `PriorityQueue` 中**没有稳定性保证**（§6-4）。
9. **横切硬前置（未齐不许开工）**：目标 `AntiMagic`（已有）/`AntiPoison`（`World::attack_poison` 注入面）、
   `GetMapBaseObjects` 的 `x→y→格内插入序` 枚举、通用延迟队列（现有 `SelfDelayMsg` 只有
   `RM_MASTERDIE*` 窄口径）、`Entity` 的 `WAbil.MAC`（`GetMagStruckDamage` 用）、
   `MabMabeHit*`/`AmyOunsulPoint` 配置项（Rust 侧尚无）。
10. 每魔号给出：oracle 行区间 / 有序门 / 逐抽账本（含 `R(0)` 也推进）/ 帧表（RM→SM、收件人、延迟、优先级）/

### 4.2 路径 B：out-of-tree 的 .NET legacy `System.Random` 转录

按 .NET Framework 的 Knuth 减法滞后斐波那契（与 `mir2-shared::rng::DotNetRandom` 同一参考源）
用 Python 独立实现，**不调用任何 Rust 代码**；同一 max 序列与 §4.1 **逐项相同**（本件已跑）。
复算脚本（out-of-tree，`/e/tmp/b4rng/dotnet_random.py`，仅供复算，不入库）：

```python
MBIG = 2147483647; MSEED = 161803398
class DotNetRandom:
    def __init__(self, seed):
        a=[0]*56; sub = MBIG if seed==-2147483648 else abs(seed)
        mj = MSEED - sub; a[55]=mj; mk=1
        for i in range(1,55):
            ii=(21*i)%55; a[ii]=mk; mk=mj-mk
            if mk<0: mk+=MBIG
            mj=a[ii]
        for _ in range(4):
            for i in range(1,56):
                a[i]-=a[1+(i+30)%55]
                if a[i]<0: a[i]+=MBIG
        self.a=a; self.inext=0; self.inextp=21
    def sample(self):
        inext=self.inext+1; inextp=self.inextp+1
        if inext>=56: inext=1
        if inextp>=56: inextp=1
        r=self.a[inext]-self.a[inextp]
        if r==MBIG: r-=1
        if r<0: r+=MBIG
        self.a[inext]=r; self.inext=inext; self.inextp=inextp
        return r*(1.0/MBIG)
    def next_max(self,n): return int(self.sample()*n)
```

**契约**：实现卡至少跑通 A/B 两条；若真机窗口可用，再加路径 C（C# `System.Random(seed)` 反射探针，
`magic-effect-probe` 模式），三路必须一致。

## 6. 未决项 / 已知偏差

1. **48 的会话内读书行**：`ReadBook` 在 Rust 侧未实现（T-17），`MagicRcd` 只存 `MagIdx`，无法区分
   Idx=38/48。B4 必须把 `MagicInfo` 行作为显式输入（测试可直传）；生产路径在读档时按
   `FindMagic(MagIdx)` 首行（与 oracle 读档同）。两行的 RNG 账本相同（都是 `R(0)`）；**会话内读书
   路径（Idx=48）与读档首行（Idx=38）的差异（GP13 33 vs 37 ⇒ nPower +4；MP 6 vs 39）
   在真机窗口可用前只做构造级判据**（R 级窗口项）。
2. **投递 tick 的 RNG 交错**：oracle 每个 actor 一条线程、共享一个 `System.Random`；
   `RM_DELAYMAGIC`/`RM_MAGSTRUCK`/`RM_POISON` 的投递顺序跨 actor 不确定。固定种子只能钉
   「每 actor 在处理点的抽数序列」；真机账本必须把「施法 tick」与「投递 tick」分开记，
   并声明驱动顺序。**不得**把投递 tick 的抽数并入施法 tick 的连续序列判据。
3. **657 的 `HitSpeed`**：oracle 逐收件人取 `this.HitSpeed`（`PlayObject.Message.cs:1846`）；
   本仓 `Entity` 无该字段，现有 buff 下行传 0。**未定前，657 只能判 `(ident, recipient)` 与
   `status` 两字段，不能判末参字节**（与 B3 §6-1 同一偏差）。
4. **同优先级队列序**：.NET `PriorityQueue` 对同优先级元素不保证 FIFO（48 的 `642 × N` 耐久值
   500/400/300 可能乱序）。实现卡必须先做**C# 反射/真机探针**确认同优先级出队序，再决定
   Rust 侧是复刻堆序还是仅判 multiset；在确认前，测试对 `642×N` 只判**集合/计数**。
5. **`SendRefMsg` 的 500ms 缓存**：`VisibleHumanList` 只在距上次 ≥500ms 或列表空时重扫
   （`BaseObject.Message.cs:395-450`）；缓存期内只按 `|Δ|<11` 过滤。本件夹具是静态位置，不受影响；
   真机窗口若涉及移动观察者，收件人集合可能与本件表不同（登记）。
6. **`AntiPoison`/`AntiMagic` 来源**：Rust 侧 `AntiPoison` 只在 `attack_poison` 注入面；
   普通怪 `AntiMagic=0`、`AntiPoison=0`（与 oracle 普通生成路径同）。特殊怪/玩家装备面未建模的
   部分保持默认（登记，勿按常识补）。
7. **50 的 `R(nLevel)` 与 `nLevel=0`**：`Random(0)` 仍推进一次（.NET `Next(0)` → `Sample()`），
   Rust `random_below(0)` 同口径。夹具 Level=2；Level=0 的边界应另加单测（1 抽、值恒 0）。
8. **42 的 `target.Death` 归一**：`DoSpell:160-163` 把死亡目标置 null ⇒ 42 走 NPE/639 支；
   6 的 `IsProperTarget(null)=false` ⇒ 639；50 会先抽 4 次再返回 false。三者的空目标语义**不同**，
   测试必须分别覆盖，不能合并成一个「null 目标」用例。
9. **`AmyOunsulPoint=0`**：`nPower / (double)0` ⇒ `Infinity`/`NaN`，`HUtil32.Round` 对 `NaN` 在 .NET
   抛 `OverflowException`；本件按默认 10 实现，配置为 0 的防护另开条目（登记）。
10. **`MabMabeHitRandRate=0`**：`Random(0)` 恒 0 ⇒ 门恒真（`0 < MAX(...)` 在 `MAX>=1` 时）；
    按「照抽一次」实现，别短路。
11. **`invisible` 折叠（B2 §C13）**：Rust `is_proper_target_grouped` 顶部折入 `invisible`，oracle `IsProperTarget`
    （`PlayObject.cs:1924-1962`）与 `GetMapBaseObjects`（`BaseObject.cs:2808-2844`）都不读 `Invisible`。
    B4 的「非 proper」夹具改用 `race=10`（NPC 段，`PlayObject.Attack.cs:632-641` 的 `HAM_ALL` 分支直接 false），
    **不依赖**该偏差。注：`AdminMode/StoneMode` 门（`BaseObject.Base.cs:384-387`）在 `IsProperTarget` 里只在
    兜底 `base.IsAttackTarget(...)` 才求值；玩家施法对 race≥NPC 的目标首查即 true（`PlayObject.Attack.cs:632-641`），
    单靠它造不出非 proper。
