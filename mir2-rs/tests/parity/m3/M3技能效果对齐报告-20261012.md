## 2. 一处建模口径修正：效果威力必须走 `PlayObject.GetAttackPower` override

`MagicManager.DoSpell` 的施法者是 `PlayObject` ⇒ 威力表达式里的
`playObject.GetAttackPower(...)` 走 **`PlayObject.GetAttackPower` override**（`PlayObject.cs:2909`），
与 `BaseObject.GetAttackPower`（`BaseObject.Base.cs:886`）的**取数次数不同**：
`Luck <= 0` 时后者只抽 1 次，前者在算出结果后**再抽一次 `Random(10)`**（`== 0` 时把结果压回 `basePower`）。

第一片 `crates/world/src/magic.rs` 的效果函数只调用了 `get_attack_power`（Base 口径），
因为当时每条用例只比**最终威力值**、且该 `Random(10)` 未命中 0，所以 11 个技能“碰巧全绿”。
本片新增的**火墙**（`SKILL_EARTHFIRE=22`）在同一次施法里**威力之后还要抽数**求 `time`
（`GetPower(10) + (GetRPow(MC) >> 1)`），Base 口径会把后续序列整体错位 ⇒ 实测
`fire_wall.time rust=18 csharp=22`（差 4）。

修正：`magic.rs` 的效果函数统一接收 `AttackPowerMode`（复用 `combat.rs` 的建模），
探针在 `seed` 行附上施法者的 `luck/power_rate/bo_power_item/power_item`
（本探针施法者 = `Luck 0 / PowerRate 100 / BoPowerItem false / PowerItem 0`），
Rust 用例按同一 mode 驱动。修正后：

- 24 个技能的**效果值全部逐项一致**（含火墙 `power=27 time=22`）；
- 既有 11 个技能的值**未变**（`Random(10)==0` 在这批种子上没有命中）；
- 这与第一片 §7.1 的登记**是同一件事的两面**：物理攻击的 `World::attack_once` 仍走 Base
  （golden 口径，未接线），而**技能效果**这条路径按 oracle 真相走 Player override，已在本片对齐。

| 魔号 | 名称 | 效果表达式 |
| --- | --- | --- |

| 28 | 心灵启示 | `interval = GetPower13(GetRPow(SC)*2+30) * 1000` |
| 29 | 群体治疗术 | `GetAttackPower(GetPower(MPow)+Lo(SC)*2, ΔSC*2+1)`（`MagBigHealing` 施加，未建模） |
| 31 | 魔法盾 | `power = GetPower(GetRPow(MC)+15)`（`MagBubbleDefenceUp` 施加，未建模） |
| 33 | 冰咆哮 | `GetAttackPower(GetPower(MPow)+Lo(MC), ΔMC+1)` |
| 36 | 火焰冰（数据行名；oracle 按 `SKILL_UENHANCER=36` 分支） | `power=(ushort)(Level+1+Random(Level))`；`time=GetAttackPower(GetPower13(60)+Lo(SC)*10, ΔSC+1)` |
| 45 | 灭天火 | 雷电术同式 + 不死 ×1.5 |
| 47 | 地狱烈焰 | `GetAttackPower(GetPower(MPow)+Lo(MC), ΔMC+1)` |
| 50 | 无极真气（数据行名；oracle 按 `SKILL_MABE=50` 分支） | `GetAttackPower(GetPower(MPow)+Lo(MC), ΔMC+1)` |

> **数据行名与 `MagicConst` 魔号的错位照搬 oracle**：DB 的 `magics.MagID=36` 行名是「火焰冰」，
> 而 `DoSpell` 的 `case MagicConst.SKILL_UENHANCER:` 也 = 36；`MagID=50` 行名「无极真气」，
> `case MagicConst.SKILL_MABE:` = 50。oracle 按魔号分派，本实现照搬（行为等价优先于“名字对不对”）。

每条用例逐项核：施法前置（`!IsTrainingSkill && (Job==99||Job==Job) && Level>=TrainLevel[0]`）、
MP 消耗（`GetSpellPoint`，Level 0..3）、效果（上表表达式，每技能独立子种子 `seed ^ magic_id`，Level=1）、
冷却（`DelayTime` 与 `MagicAttackInterval = DelayTime + MagicHitIntervalTime = 800`）。

**未实装 84 行**逐条登记在 `skills_registry.json`（`implemented=false` + 承接说明），
理由统一为「需要地图/目标/护身符/召唤/状态等 oracle 上下文」，承接待攻击/魔法接线落地后的技能批次。
