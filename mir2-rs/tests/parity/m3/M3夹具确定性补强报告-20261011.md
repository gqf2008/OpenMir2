## 2. 验收判据逐条取证

判据原文（卡内 `machine_checkable_acceptance`）：

1. 配置项能固定建角参数；未配置时行为与现在一致；
2. 同一命令连跑两次：`mir2_db.characters` 的 Job/Hair/Sex 两次相同；
3. 固定 Job 场景下跨侧 diff（规范化后）=0，且该场景 Job 列**不**置占位；
4. 改动登记 `T-*`；
5. 硬门禁 fmt/clippy/test + msgcodegen 全绿；动 C# 侧另出 C# 构建证据。

### ① 配置项可固定 / 默认不变

- `AppSetting.json` 的 `BotPlay` 段：`FixedNewChr` / `NewChrJob` / `NewChrHair` / `NewChrSex`（见 §1）。
- 实测：`baseline.json` 落 `"fixed_new_chr": "Job=1 Hair=2 Sex=0"`、`ops_runner` 带 `-FixedNewChr ...`；
  BotSrv 日志出现 `[INF] 建角参数固定: Job=1 Hair=2 Sex=0`（日志为 `*.log`，按 .gitignore 不入库、可重跑再生；
  入库判据是 `baseline.json` 的 `fixed_new_chr` 字段与 `scoped_after_norm.jsonl` 的三列值）。
- 默认不变：不传 `-FixedNewChr` 时 `FixedNewChr=false` ⇒ 走原随机路径（代码未改）。

### ② 同命令两次 ⇒ Job/Hair/Sex 相同


### ③ 固定 Job 场景：Job **不**置占位 + 规范化后 diff = 0

**夹具机制（已实现并取证）**：`scoped_diff.py diff --canonical --fixed-newchr` 把
`mir2_db.characters` 的 `Hair/Sex/Job` 从易变白名单里摘掉，逐字节比；其余易变列（自增 PK / 墙钟）照旧置占位。

```
命令： python scoped_diff.py diff sessions/csharp-20261011-124347/scoped_after_norm.jsonl \
                                  sessions/csharp-20261011-124752/scoped_after_norm.jsonl \
                                  --canonical --fixed-newchr
输出： GREEN: 作用域内 4 张表逐行一致        （exit 0）
对照： 同数据不带 --fixed-newchr 时 Job 被置占位 ⇒ 也能判绿，但那不叫"比到值"
       （红线用例 7/7：同场景把 Job 改坏即判红，证明 Job 真的在比）
命令： python scoped_diff.py selftest
输出： 7/7（含「固定建角场景：Job 固定且不置占位，仅 Id 变判绿」+「Job 被改坏即判红」+fail-closed）  exit 0
```
