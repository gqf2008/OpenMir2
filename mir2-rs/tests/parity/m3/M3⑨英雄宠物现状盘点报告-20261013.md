## 0. 一句话结论

**本 oracle（mirbeta/OpenMir2 的 M2Server）没有「玩家英雄」实体**：全仓无 `HeroObject` / `PetObject`；`HeroActor`
只在 **BotSrv**（客户端假人）；`GameSvrConf` 里 `boHeroAttackTao` / `dwHeroWarrorAttackTime` / `btHeroSkillMode` /
`sHeroAIConfigListFileName` 等 `hero*` 字段**全部属于机器人（RobotSystem/RobotPlayer）**。§6 的「英雄/宠物」在
本 oracle 里只能落到 **宝宝/下属（slave）** 这一条真实系统上：

- **宠物/宝宝 = `Master` + `SlaveList` + `MakeSlave`**（`BaseObject.cs:133/141/1179`）；召唤来自技能
  **17 召唤骷髅 / 30 召唤神兽 / 41 召唤精灵 / 46 分身**，外加 **20 诱惑之光**（tame）把野怪变奴。
- **「英雄经验」= `ExpHitter.Master`**（宝宝击杀 ⇒ 经验发**主人**，`BaseObject.cs:2434-2437`）——与
  whitelist **T-33** 登记一致（本片复核：**成立**）。
- **宝宝不落库**：三库无 `slave/pet/hero/tamming` 表或列；跨服才随 `SwitchDataInfo.SlaveArr`（换服包）带一次。

Rust 现状（逐条证据见 §2）：

- ✅ **主从骨架已建模**：`Entity.master`（`entity.rs:64`）、主从目标判定（`combat.rs:410-445/510-530`，含 oracle 反直觉写法）、
  主从可见集（`aoi.rs:32/60/112`）、**掉落归属走 master**（`world.rs:588-592`）。⚠️ 但**生产路径尚无召唤** ⇒ `master` **只由测试设值**
  （`world.rs:1279`）⇒ 这些分支目前是「已建模、未接线」，随承接卡 2 生效。
- ✅ **诱惑之光 `MagTamming` 已实现**（`magic.rs:548-819`，24+ 真身向量 + 红检，`magic_effect_vectors.rs`）。
- ✅ **脚本条件「宝宝数量」已实现**（`conditions.rs:451-456`，**照搬 oracle 恒假**）。
- ⚠️ **召唤技能（17/30/41/46）未实现**：`magic.rs:471-472/833` 明写「体内部走 `Envir`/`WorldEngine`/`MakeSlave`，本片只登记可达性」。
- ⚠️ **宝宝列表/等级/颜色/叛变/阵亡清理未实现**：Rust 全无 `SlaveList` / `SlaveExpLevel` / `SlaveMakeLevel` /
  `MasterRoyaltyTick` / `CheckRoyalty` / `RecallSlave` 的等价物。
- ⚠️ **经验给主人未实现**：`settle_deaths` 只对 `race == Play` 的 `ExpHitter` 发经验（`world.rs:635-650`）⇒ **T-33 缺口**。
- ✅ **无英雄 = 与 oracle 一致**（不是缺口；`crates/**` 无英雄实体，也不该造）。
- ✅ **不落库 = 与 oracle 一致**（两侧都不新增 slave/pet/hero 表行列；任务态/宝宝态都是会话内存）。

**关键新发现（需登记）**：`MonsterObject.GainSlaveExp`（宝宝按击杀数升级、`SlaveExpLevel++`，`MonsterObject.cs:71-84`）
在本 oracle 里**是死代码**——全仓**只有定义、无任何调用点**（`rg -n "GainSlaveExp" src/` 仅 1 行）。⇒ 忠实照搬 =
**宝宝等级不由击杀增长**，只在召唤时（`SkeletonArray`/`DragonArray[i].nLevel`）与跨服恢复时（`ChangeServerMakeSlave`）设定。
本片**未起栈、未占端口、零 `.rs`**。

## 4. 判据设计草案（DoD②）与夹具可复用性（DoD③ 口径）

### 4.1 §6 原文判据（不放宽）

> 「英雄/宠物：**召唤 / 升级 / 阵亡 / 经验分配 / 上限判定**一致。」

按 oracle 的真实语义拆成五条机判（**本系统与其它系统最大的不同 = 召唤物由服务端生成、且有时间门**）：

1. **召唤一致**：固定起点 + 固定动作（`CM_SPELL` 17/20/30/41）下，两侧「`MakeSlave` 结果」逐项相同——
   宝宝名/`SlaveMakeLevel`/`SlaveExpLevel`/初始 HP（`HP<MaxHP ⇒ 补一半`）/`MasterRoyaltyTick` 是否存在，
   以及**失败门**（`CheckServerMakeSlave` 有 `RM_10401` / `SlaveList.Count >= nMaxMob` / 诱惑的 `MagTammingCount` 门）
   的返回一致；`SlaveList` 计数一致。
2. **升级一致**：宝宝 `SlaveExpLevel`/`SlaveColor` 在**召唤时**（`SkeletonArray/DragonArray[i].nLevel`）与
   **跨服恢复时**一致；**并显式钉住 oracle 死代码语义**：击杀后 `SlaveExpLevel` **不变**（`GainSlaveExp` 无调用点）。
   （玩家升级曲线归 ④，本卡不重复。）
3. **阵亡一致**：`CheckRoyalty` 的三种结局（`SpiritMutinyTick` 立即叛变 / `MasterRoyaltyTick` 到期叛变 + `HP/10` /
   `MasterTick>12h` 死亡）+ 主人死/幽灵时 `ProcessSlaveMutiny`/`ProcessSlaveGhost` + 死亡清表的**帧序列 + 状态**一致。
   **时间门**（10s 检查、12h、`SpiritMutinyTime`）必须可注入（见 §4.3）。
4. **经验分配一致**：宝宝击杀 ⇒ `ExpHitter.Master` 拿经验（`RM_PLAYERKILLMONSTER`），主人 `Abil.Exp`/等级与
   `drop_exp_raw.jsonl` 的 `hero_exp_delta` 逐 k 相同；对照「主人自己击杀」两档。**判据 = `hero_pet_diff.py` diff=0**。
5. **上限判定一致**：`SlaveList.Count < nMaxMob`（1）与 `< MagTammingCount`（5）边界两侧一致；跨服 `nSlavecount`（道士 1 / 其它 5）一致。

### 4.2 夹具可复用性

- **召唤物不是第二条连接**（§3 证据 `03` §C）：宝宝由**服务端** `WorldEngine.RegenMonsterByName` 生成
  （`BaseObject.cs:1190`），随主人会话存活 ⇒ **一条 bot 连接 + 一只真怪**即可构造「宝宝击杀主人得经验」。
  只有「归属对照（主人自击 vs 宝宝击杀）」才需要第二条假人连接——`run_attack_pair.ps1` 已提供。
- **现成编排**：`run_pair.ps1`（两相 pin / BEFORE-AFTER 快照 / `M3ATTSEQ` 标记）/ `run_attack_pair.ps1`
  （`-AttackPinPair` + `-PeerSession` + 四个 peer 护栏 `Get-M3Peer*`）/ `scoped_diff.py --canonical`（落库一致）
  / `drop-exp/run_drop_exp_pair.ps1` + `drop_exp_diff.py`（**已带 `hero_exp_delta` 通道**）⇒ 直接用。
- **BotSrv 现成件**：`SendSpellMsg`（`RobotPlayer.cs:2926`）可发召唤；`RobotPlayer.Operate.cs:360-380` 能观测
  自己宝宝（`SlaveObject`）⇒ 夹具只新增「召唤 + 观察」两个动作步骤与一个比较器（属 m3bag 写集，按 T-22/T-29 登记）。
- **不要重造**：pin/快照/`SHA256SUMS` 口径、peer 护栏、`server_state_gate` 的 fail-closed 风格都可原样搬。

### 4.3 缺口对 DoD②③ 的阻塞关系 + **时间门可控性**

- 判据需要服务端真的**收包召唤并回帧**；在承接卡 `2/3/4`（召唤 + 生命周期 + 经验）落地前，夹具即使接好也只会
  「召唤失败/无宝宝」⇒ **DoD②③ 阻塞于承接卡 `1`→`2`→`3`/`4`→`5`**，本片只交 DoD①。
- **时间门（本系统与别系统最大的不同）四类**：
  1. **uptime**（`GetTickCount()`）：`CheckRoyalty` 10s 检查间隔、`MasterTick>12h`、`ExpHitter` 6s 过期；
  2. **墙钟/绝对时刻**：无（本系统不用 `DateTime.Now`）；
  3. **日期**：无；
  4. **随机**：`MagTamming` 多层 `Random(...)`、`MasterDieMutinyRate` 的 `Random`。
  ⇒ Rust 世界已用虚拟时钟 `world.clock_ms`（每 tick 推进）——夹具须能**注入/快进**它；C# 侧需**影子 hook 注入
  `GetTickCount()`**（`MIR2_CLOCK_*`）。这正是 owner 盘点点名的**跨系统前置 `openmir2-m3-clock-injection`**
  （⑧ 盘点已建议开卡）——**本卡也依赖它**，请求 owner 把该前置排在本卡实现卡之前。
