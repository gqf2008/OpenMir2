## 0. 一句话结论

**行会与攻城在 oracle 里都是「文件持久化 + 内存状态机」**：行会落 `GuildBase/GuildList.txt` +
`GuildBase/Guilds/<行会名>.txt`（另有 `GuildConf` 的 `<行会名>.ini` 式配置），攻城落
`Castle/List.txt` + `Castle/<N>/SabukW.txt` + `Castle/<N>/AttackSabukWall.txt`；**`sql/` 里没有任何
`guild` / `guildmember` / `castle` 表**（唯一持久列是 `characters.AllowGuildReCall`）⇒ §6 的「落库一致」
在 oracle 侧就等于「**不落库，只落文件**」。

Rust 现状（逐条证据见 §2）：

- ✅ **常量表齐全**：行会 9 个 `CM_GUILD*` + 16 个 `SM_GUILD*` + 2 个 `RM_BUILDGUILD*` + `ISM_*`/`SS_*`
  在 C# 与 `crates/protocol` **两侧全部命中**（数字一致）。
- ✅ **角色记录 `allow_guild_re_call` 已解析/重编码**（M2 record-fields）；`data` 层已有
  `ACTOR_RACE_SABUK_DOOR(110)/SABUK_WALL(111)` 与「城门/城墙 HP 不随 `MonsterPowerRate` 缩放」特判。
- ⚠️ **行会/城池相关接缝「已建模但恒死」**：`bins/game-svr/src/bag.rs` 的 `has_guild`/`guild_rank_no`/
  `is_castle_member` 三个字段存在，但 `main.rs:850-852` 一律传 `false/0/false`（无行会系统）。
- ⚠️ **`HAM_GUILD` 攻击模式「不同」**：`crates/world/src/combat.rs:487-491` 明写 `MyGuild` 未建模 ⇒ 不剔除。
- ⚠️ **进图帧 766 的 `InGuildWarArea` 恒 `false`、frame50 的 `%guildname` 恒空**（`enter.rs:269/343`）。
- ❌ **服务端无行会/攻城实体、无派发、无帧、无文件加载器、无配置项**：`bins/game-svr` 对 9 个 `CM_GUILD*`
  与全部 `SM_GUILD*`/`RM_BUILDGUILD*` **no match**；`GuildList.txt`/`SabukW.txt`/`AttackSabukWall.txt`
  加载器 **no match**；`BuildGuildPrice`/`GuildWarPrice`/`GuildWarTime`/`castle_*` 配置 **no match**。
- ⚠️ **oracle 自身的攻城链有 10 处 `NotImplementedException` 断点**（§1.L / 证据 `00-…:N1`）：NPC 申请攻城、
  城池自动占领、GM 改沙巴克归属、城堡金库提取/上缴、开城门时的 `CheckInPalace` 都落在抛异常重载上
  ⇒ 这些站点在 oracle 里**不可达**。另有 4 处 oracle bug（“宣战”反逻辑、`UpdateRank` 清空成员表、
  名称校验漏末位、雇佣 Substring 越界），按硬约束 3 **必须逐条面对**（照搬 or owner 签字登记）。
- ✅ **夹具面现成件很多**：BotSrv 已有行会**发送原语**（`RobotPlayer.cs:3141-3246`）与**全部行会帧观测**
  （`RobotPlayer.Operate.cs:765/1293-1500`），但**这些发送原语当前无任何调用点**；`run_pair.ps1` 的两相 pin +
  会话入库、`run_attack_pair.ps1` 的 peer 双护栏可直接套用，**唯一新前置 = 时间门可控**（§4.3）。

⇒ 本卡 DoD②③ 的**真缺口 = 服务端「文件加载/落盘 + 状态机 + 收包派发 + 帧」+ 时间门注入**；落库面与 oracle 一致
（不落库）。本片**未起栈、未占端口、零 `.rs`**。

## 4. 判据设计草案（DoD②）与夹具可复用性（DoD③ 口径）

### 4.1 §6 原文判据（不放宽）

> 「公会 / 攻城：**建会 / 宣战（费用、时限）/ 城门状态 / 自动结束，逐项一致**。」

拆成五条机判（含时间门）：

1. **建会一致**：固定起点 + 固定输入序列下，两侧在建会申请（费用不足 / 无号角 / 已有会 / 重名 / 名非法 /
   正常）六条分支上的**回包码**（`RM_BUILDGUILD_OK/FAIL result`）与**状态**（行会是否新增、号角/金币扣减、
   `GuildRankNo==1`、`SS_205` 跨服消息）逐项相同；落盘文件（`GuildList.txt`/`<名>.txt`）逐字节/逐行相同。
2. **宣战费用一致**：`GuildWarPrice` 扣减、`MyGuild.GuildWarList` 条目（`WarTick`/`WarTime`）、
   反向 `AddWarGuild`、`SS_207`；**必须覆盖 N2 反逻辑的三个可观测结果**（未战申请不生效 / 已战申请重复条目 /
   `warGuild.WarTick>0` 分支的走向）。
3. **宣战时限一致**：把 `GuildWarTime` 钉成小值（夹具 Server.conf 覆盖），在**可控虚拟时钟**下推进：
   到期前条目在、`SS`/`SendGuildMsg` 文案与次数、到期后条目移除 + `UpdateGuildFile` 落盘。
4. **城门状态一致**：门/墙四态（`closed`/`opened`/`destroyed`/`HP<MaxHP`）下的 `$CASTLEDOORSTATE` 文本、
   `RM_DIGUP`/`RM_DIGDOWN`/`RM_TURN`/`RM_ALIVE` 帧、`SetMapXyFlag` 通行结果；开门/关门/修门/修墙
   （含 `UnderWar` 拒绝、HP 满拒绝、`StruckTick>60s` 门、`TotalGold` 扣减）逐项相同。
5. **自动结束一致**：`CastleWarTime` 到期 ⇒ `UnderWar=false`、`AttackGuildList` 清空、非守方
   `ChangePkStatus(false)`+`MapRandomMove(HomeMap)`、广播文案；`GetCastleTime` 前的占领被拒、
   之后（若 N1 裁决为实现路径）占领生效 + `OwnGuild`/`SabukW.txt` 落盘。
6. **落库一致（= 不落库）**：动作后两侧 DB 快照在 `characters`（`AllowGuildReCall` 除外无专列）与
   `characters_*` 上 `scoped_diff --canonical` diff = 0；**两侧都不新增 guild/castle 行/列**。

> **N1 断点必须在 DoD② 开工前由 owner 裁决**：这些站点在 oracle 里是 `NotImplementedException`。
> 判据要么按「两侧都不可达/都抛」写（并把「不可达」当行为锁死），要么按「实现 `GuildInfo`/`PlayObject` 重载、
> 即修 oracle bug」写（须 owner 签字 + 白名单登记）。**本车道不自行选择。**

### 4.3 时间门可控性（**本系统与其它系统最大的不同**）

本系统有**四类时间门**（证据 `03: [F]`）：

| 类别 | oracle 实现 | 现网值 | 可控手段 |
| --- | --- | --- | --- |
| 进程 uptime 门 | `HUtil32.GetTickCount()`：行会战 `WarTick/WarTime`；攻城 `StartCastleWarTick`+`CastleWarTime`/`GetCastleTime`/`ShowCastleWarEndMsgTime`；修门/墙 `StruckTick` 60s；`SaveTick` 10min | 2h/2h/600s/600s/60s/10min | ① 夹具 Server.conf 钉小；② **Rust 已有虚拟时钟** `world.clock_ms`（每 tick +200，模拟不读墙钟，`crates/world/world.rs:2-6`）；③ C# 侧需影子 hook 补 `GetTickCount` 注入 |
| **墙钟门** | `DateTime.Now.Hour == StartCastlewarTime`（每日开战，`UserCastle.Run`）| 20 点 | C# 侧需 `DateTime.Now` 注入；否则只能「把 `StartCastlewarTime` 钉成运行开始时的当前小时 + `AttackSabukWall.txt` 写今天日期」这种**墙钟锚定**技巧（非确定，不推荐当正式判据）|
| 日期门 | `AddDateTimeOfDay(Now, StartCastleWarDays)` + `AttackDate` 与今天同日 | `StartCastleWarDays=2` | 同墙钟门；正式判据需时钟注入 |
| 随机门（副作用）| `UserCastle.GetHomeX/Y = Home-4+Random(9)` | — | 归入既有 `MIR2_RNG_*` 口径（与 ②③ 同种子流对齐）|

⇒ **DoD③ 的新前置 = `openmir2-m3-clock-injection`（§3 `1`）**：两侧同一时钟起点 + 同一推进量，
把「第 N tick / 推进 T ms」当判据坐标，而不是比墙钟读数。在它落地前，行会/攻城的 **2/3/4/5 条判据
只能做「状态迁移」的离线构造级向量**，真机两侧对拍不可判。**本片只登记该前置，不实现。**

### 4.4 缺口对 DoD②③ 的阻塞关系

DoD②③ 需要**服务端真的收包并回帧、且状态机能推进**；在 §3 的 `4`（行会状态机）与 `6/7/8/9`（攻城/门/金库）
落地前，夹具即使接好也只会得到「无回帧 / 无城堡实体」；而 `8/9` 还额外阻塞在 **N1 owner 裁决**。
⇒ **DoD②③ 阻塞于 `1`(时钟) → `2/3`(配置/文件) → `4`(行会) / `6`(攻城) → `7/8/9` → `10`(夹具)**。本片只交 DoD①。
