## 1. ① 「同一流」机判（结论：**是**，隔离等价）

方法（`compare_dedicated_streams.py`）：把每一侧**自己的** `(kind,arg)` 请求序列喂给本工具内**逐行复刻的
.NET legacy `System.Random`**（与 `crates/shared/src/rng.rs` 同算法；复刻器对 seed=42 的 8 项与真机
`SEED_PROBE` 逐值相同），逐次比**结果值**。

| 侧 | 取数 | 自复算 mismatch |
|---|---|---|
| C# stack2 专用流 | 300 | **0** |
| Rust stack2 流水（攻击站点） | 354 | **0** |
| C# stack1 专用流 | 618 | **0** |
| Rust stack1 流水 | 450 | **0** |

⇒ 两侧的「按调用点分流到 `Random(40545)`」都是**真的**：种子公式、分流谓词、算法逐条对齐。
跨侧逐 k ≠ 0 **不是**隔离/路由不等价——两侧对**同一**请求序列的结果**逐一相同**。

两侧的 `(kind,arg)` **请求序列**不同（第一处分歧 index=2：C# `Next(max 8)`[base 门] vs Rust `Next(max 10)`[玩家攻方第二抽]）。
请求序列 = 被测行为（游戏逻辑），故分歧是**行为差**。见 §2/§3。

## 2. ② 攻方属性判别（结论：**无输入差**；分岔在「到达命中门的攻击数」）

命中门 oracle（`src/M2Server/Actor/BaseObject.Attack.cs:37-44`）：

```csharp
if (IsProperTarget(targetObject)) {
    if (targetObject.HitPoint > 0) {
        if (HitPoint < M2Share.RandomNumber.RandomByte(targetObject.SpeedPoint)) nPower = 0;   // :41
    }
} else { nPower = 0; }
```

⇒ 命中 ⇔ `draw <= HitPoint`；未命中 ⇔ `draw > HitPoint`。对每个 player unit，用「有没有 `hit_struck_damage`」
判过门/未过门，即可反解 `HitPoint` 的一致区间：

| 侧 | player 攻击单元 | 到达命中门 | 命中 | SpeedPoint | HitPoint 区间 |
|---|---|---|---|---|---|
| C# stack2(cA) | 120 | 3 | 1 | {15} | **[4,10)** |
| Rust stack2(rA) | 120 | 38 | 19 | {15} | **[5,6) ⇒ 5** |
| C# stack1(c1+c2) | 260 | 9 | 3 | {15} | **[3,7)** |
| Rust stack1(r1) | 140 | 57 | 28 | {15} | **[5,6) ⇒ 5** |

- `SpeedPoint=15` 两侧相同 ⇒ **输入对齐**。
- Rust 严格反解 `HitPoint=5`；C# 两侧区间 [4,10) / [3,7) **都含 5**，与 5 不冲突。
- ⇒ **命中门本体两侧等价**（同公式、同输入、同判定）。
- 真正的分岔是**「有目标且目标 HP>0」的入口数**：Rust 38/120 vs C# 3/120。
  这与 m2-svr 已登记的「oracle `GetPoseCreate()` 用当前 `Dir`（`AttackDir` 在其后才 `Dir=nDir`），
  而 Rust `handle_hit_cmd` 用消息 `Tag` 方向」同源，属 `bins/game-svr`（m2-svr 写集）。
- 另注：受害者 maxhp=19（§4），Rust 19 中后目标死亡、此后不再过门；「目标解析差」与「死亡驱动差」
  在未修 §4 前会叠加，建议先修夹具。

## 3. ③ `atk_power_base`（C# 16 / Rust 0）是谁（结论：**进程级并发实体，非夹具攻击路径**）

- oracle：基版 `BaseObject.GetAttackPower`（`src/M2Server/Actor/BaseObject.Base.cs:886`，`Random` 在 `:892`）
  是 `PlayObject.GetAttackPower` 的**被 override 者**（`src/M2Server/Player/PlayObject.cs:2909`）
  ⇒ **玩家攻方必走 2929/2934**；只有**非 PlayObject actor**（MonsterObject/NPC 等）才落到 892。
- 但夹具 0137 只有两名玩家（attacker/victim，都在 `characters`/`characters_ablity`），MonGen/NPC 皆 0（owner 已核）。
- 观测：base 单元的 target `SpeedPoint ∈ {8,13,15}`（多目标）、基版攻方 `HitPoint>=13`（全过门），
  与玩家路径（`SpeedPoint=15`、`HitPoint=5`）**明显不同**；计数随运行变化（stack2=16、stack1=23、
  同卡 F-1 会话实测 34）。
- 根因：C# 影子 hook 的 divert 谓词是**调用点级、进程级**（`rng-hook/divert-sites.txt`），覆盖 GameSvr
  整个生命周期与所有地图；Rust 侧只在空图 0137 上跑两名玩家 ⇒ 无对应消费者。
- ⇒ **夹具/仪器口径**（**m3bag 写集**）：C# 专用流需按**会话/actor**收敛，或比对时只取 player 单元。
  本工具已按 unit 首站点把 base 单元单列；跨侧比对只取 player 单元即可。

## 4. ④ `-AttackVictimHp 30000` 未生效（结论：**被登录序重算覆盖**；夹具 bug，m3bag）

- 夹具 `Get-M3AttackPinSql`（`gate_guards.ps1:807`）写 DB：`a.Level=1, a.Hp={1}, a.MaxHP={1}`（{1}=30000）。
- oracle 登录序：`AbilCopyToWAbil()` → **`RecalcLevelAbilitys()`**（`PlayObject.cs:1308-1309` / `:5245-5246`）
  → `RecalcAbilitys()`。
  - `RecalcLevelAbilitys()` 对战士**无条件重算** `Abil.MaxHP`（`PlayObject.cs:5295`）：
    `14 + Round(((L/4) + 4.5 + (L/20)) * L)`（缺省 `nLevelValueOfWarrHP=4`、`Rate=4.5`，
    `src/Modules/SystemModule/Conf/Model/GameSvrConf.cs:1893-1894`）⇒ `L=1` ⇒ **19**；
  - 收尾 `if (Abil.HP > Abil.MaxHP) Abil.HP = Abil.MaxHP;`（`:5309-5312`）把 DB 的 30000 夹回 19；
  - `RecalcAbilitys()` 写 `WAbil.MaxHP = Abil.MaxHP + AddAbil.HP`（`PlayObject.cs:2900`），无装备 ⇒ 0 ⇒ 19。
- 真机读数一致：cA / rA 两侧 `attack_seq` 与 `bot.log` 均为 `maxhp=19`，`attack_pose` 两侧逐字节相同
  （`vhp=30000` 确实透传，但**对 L1 角色恒被改成 19**）。
- ⇒ 直接写 `characters_ablity.Hp/MaxHP` 无效；修法（m3bag 定）：抬高 `Level`，或经 `AddAbil.HP`
  （如 `characters_bonusability`）。**本片只登记 + 给 oracle 行号，不改夹具。**
