## 2. 判据设计（对齐盘点报告 §4.1；**不放宽**）

逐 k（每次交互一行 `npc_shop_raw.jsonl`）比较：

1. **op / npc**（选对动作与 NPC 的直接证据）；
2. **req**（只比声明的稳定键 `item`/`n`/`label`；`make_index`/`merchant actor` 等动态 id **不作判据**，只留审计）；
3. **帧种类序列**（`sm` id 顺序）——失败分支的身份（钱不够/负重满/背包满/仓库满/取回满/无帧**不可互相顶替**）；
4. **声明的标量帧参数**（`647.a` 卖价 / `651.a` 的 `n1C` 2 vs 3 / `671.a` 修理价 / `669.a,b,c`）；
5. **gold_before / gold_after**（原宽度整数，**不 i32 截断**，selftest 有 `i32-truncation-red` 钉住）；
6. **price**；
7. **branch**（`ok` / `fail_nomoney` / `fail_overweight` / `fail_storage_full` / `fail_bagfull` / `fail_no_frame` / …）；
8. **bag / storage / goods 多重集**（`Counter` 计数式，**不做 set 差集**）。

**fail-closed**：缺文件 / 缺字段 / 类型错 / 非法 JSON / `k` 不连续 / op 非法 / frames 非数组 /
`assemble` 有 send 无 end / `done.ops` 与 send 数不一致 ⇒ **rc=2 PREREQ**，绝不静默 GREEN。

**改坏必红**：`selftest` 27 用例逐项改坏 op / npc / req / 帧种类 / 帧标量 / price / gold / bag /
storage / goods / branch / 记录数；另在 `08-external-break-comparator-branch.txt` 里做了**外部改坏**——
把比较器的 `branch` 比较删掉 ⇒ `selftest` 变 **26/27**（`mutate-branch-red` FAIL）、rc=1；还原 ⇒ 27/27、rc=0。

### 2.1 两个必须处理的「状态/时序」坑（写进场景，窗口期验证）

- **货架靠墙钟**：`GoodsList` 初始为空、只在 `Merchant.Run()` 的 5 分钟门后补货且商品不落盘
  ⇒ 场景取 **(a) 先卖后买回**（`shelf_strategy.mode=sell_then_buyback`），货架由夹具自造，确定且不依赖墙钟。
- **距离口径不一致**：买/卖用 `<=15` 放行（`PlayObject.Operate.cs:200`），视野用 `<15`
  （`:1715`）⇒ pin 距离取 **1**，两侧都稳定通过；`dx=15` 边界留作边界用例。
