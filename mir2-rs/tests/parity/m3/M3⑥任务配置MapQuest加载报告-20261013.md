### 1.1 连 bug 一起搬的三条 oracle 语义（§1 硬约束③）

1. **`MapQuestInfo` 没有 `Quest` 字段**（`src/OpenMir2/Data/MapQuestInfo.cs`）：脚本名只进
   `Merchant.ChrName`，不进任务结构 ⇒ Rust 结构同样不带 `quest` 字段。
2. **`sQuest == "*"` 时先清空再当 NPC 名**（`MapQuestManager.cs:35-38` 在 `:45` 之前）⇒ `ChrName` 是空串。
3. **`nValue` 只钳上界**（`> 1 → 1`，负值不钳）；**`nFlag < 0` 直接 `CreateQuest` 失败**。

### 1.2 建模登记（非行为差异，冻结硬约束）

oracle 在 `QManage.txt`/`QFunction-0.txt`/`RobotManage.txt` 缺失时会 `CreateDirectory` + `SaveToFile`
**写模板文件**（`LocalDB.cs:238-257` / `:197-204` / `:298-302`），随后 `File.Exists` 为真 ⇒ 仍建 NPC。
Rust 侧**冻结数据目录**（硬约束②）⇒ 本模块**不落盘**：文件缺失时仍产出同形 NPC 记录（oracle 会补建成功），
并把「oracle 会写什么」放进 `MapQuestLoad.hidden_files_created`（纯数据）。部署件三目录都存在、只有
`Robot_def/RobotManage.txt` 缺（见 `01-deployment-input.txt`）⇒ 该路径实测**只登记不写**，与 oracle 的可观测 NPC 记录一致；
两侧仅在「父目录不可创建/不可写」这类 oracle 走 `catch` 的异常路径上会不同（部署件不可达）。
**不写 `whitelist.md`**：这是「不写冻结数据目录」的硬约束落实，不是被测行为差异。
