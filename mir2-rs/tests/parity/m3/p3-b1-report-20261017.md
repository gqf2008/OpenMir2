## 2. 期望表复算方法（两条独立路径）

**路径 A（手写推导，主判据）**：用例 `b1_replay` 按 C# 表达式求值序逐项重放：

```text
Random(10)                                  // 骰门
Random(MaxPower - Power)                    // MPow
Random(DefMaxPower - DefPower)              // GetPower
Random(HiByte(stat) - LoByte(stat) + 2)     // GetAttackPower 内 Random(nPower + 1)，nPower=Δ+1
Random(10)                                  // Luck <= 0 的第二次抽（PlayObject.cs:2932）
[Random(20); Random(Level)]                 // 仅 44 且 caster.Level > target.Level
Random(3)                                   // 共享尾 :663（训练门内）
```

断言 = **完整 RNG 状态相等**（`format!("{:?}")`）+ `draws_between` 计数。该对照流不调用生产 helper，
因此「取数序/参数/次数」任一项写错都会让状态不等。

**路径 B（既有向量/真身口径）**：
- `MPow`/`GetPower`/`GetRPow` 的公式与取数已由 `crates/world/src/magic_effect.rs` 的
  `draw_formulas_and_order_source_cited` 与 `mir2-rs/tests/parity/m3/magic-effect-probe`（真身反射直调）
  钉死；本片直接复用同一函数（`mpow`/`get_power`）。
- `GetAttackPower` 的玩家 override（`Luck<=0` 多一抽）由 `combat::get_attack_power_player` 的既有向量
  覆盖（`M3②③` 攻击线）。
- 13 的 SC 口径与 1/5 的 MC 口径只差 `WAbil.SC`/`WAbil.MC`，公式同形。
- 不死 ×1.5 另由 `world::tests::p3b1_lightening_undead_multiplier` 直调生产方法，用同一手写推导算期望值。

> 取数参数订正（实现期发现）：`GetAttackPower(nBase, nPower)` 内部再 `Random(nPower + 1)`，
> 所以调用点 `nPower = Δ+1` 时实际抽数是 `Random(Δ+2)`。本报告与用例均按 `Δ+2`。

## 5. 未决项 / 登记（不阻塞本片判据）

1. **`RM_DELAYMAGIC` / `RM_DELAYPUSHED` 的延迟结算未建模**：oracle 的 `SendSelfDelayMsg` 把消息排进
   **服务端**自队列；600/1200ms 后 `BaseObject.Base.cs:711-724` 做 `GetMagStruckDamage` +
   `RM_MAGSTRUCK`（`CharPushed` 同理）。本仓无延迟队列 ⇒ 本片只保证**取数序**与**线上帧**
   （`SM_SPELL/SM_MAGICFIRE/LVEXP`），延迟伤害落地单独成卡。
2. **`StickMode` 未建模**：44 的推挤门恒按 `false`（与既有 `MagPushArround` 登记同口径）。
3. **`FastTrain` 未装载**：`finish_spell_tail` 恒传 `false`（既有五处同口径）。
4. **目标 `AntiMagic`（订正）**：oracle ctor `BaseObject.cs:390` 置 **0**；只有
   `RecalcAbilitys`（`BaseObject.Abil.cs:30/67`，`1 + AddAbil.AntiMagic`）会置非 0。
   **普通 `MonGen` 生成路径不调用 `RecalcAbilitys`** ⇒ 普通怪 `AntiMagic = 0`
   ⇒ `Random(10) >= 0` 恒真、骰门**永不失败**（同结论见
   `design-monster-run-overrides-20261017.md` §4.1.2-5 / §6-2）。
   Rust 侧 `Entity.anti_magic` 默认 0，只在等价路径（玩家登录/升级、宝宝召唤）置
   `1 + AddAbil.AntiMagic`；旧实现「怪物/离线目标回落 1」错误，已删除。
   **剩余未接线面（登记）**：复活（`BaseObject.cs:2739`）、怪物 `MakeClone`
   （`MonsterObject.cs:100`）/`GainSlaveExp`（`:73-86`）、装备/卸下后的实体属性同步
   （会话 `SubAbility` 已重算但 `apply_ability_to_entity` 未在该路径调用）、
   buff 触发的 `RecalcAbilitys`（`ActorBuffSystem.cs:228`）、`ElfMonster.AppearNow`
   （`ElfMonster.cs:24/:78`）与 `ElfWarriorMonster.AppearNow`（`ElfWarriorMonster.cs:15/:153`）
   ——后两者形态本身未建模，本仓神兽走 `make_slave_adopt` 已置 1，当前无行为分岔。
   上述路径上实体保持 0。
5. **`MagCanHitTarget` 在生产入口的「不可达失败」**：平地上距离门（`|Δ|<=8`）已保证
   目标在 13 步内可达 ⇒ 生产入口观测不到该门失败；门本身由 U1 单测覆盖。
6. **`ushort` 截断**：C# `MagicManager.GetPower` 返回 `ushort`，本仓 `get_power` 返回 `i32`
   （既有全部威力 helper 同口径；量级内等价）。
7. **真机窗口未跑**：本片 tier=R，RNG 取数序与训练尾的**真机全量对拍**仍待窗口；本地判据为
   生产入口 + 固定种子 + 手写对照流的全状态相等。
