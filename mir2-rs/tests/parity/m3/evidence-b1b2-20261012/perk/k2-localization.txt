# k=2 定位结论（跨侧 c1(155255) vs r1(155659)：C# 命中 dmg=2 / Rust 躲闪）

**结论：归「属性输入差」类 —— 更精确地说，是「真机 Rust 攻方实体没有装载 pin 的
`characters_ablity` 属性」⇒ 攻方 `dc=0` ⇒ 攻击力恒 0 ⇒ 无伤害 ⇒ 无 `SM_STRUCK`。**
**不是命中/躲闪门的公式差（该公式已 1:1 对拍），也不是单纯 PIN_RETRY 次数。**
**修点在 `bins/game-svr/**`（§1 禁止的 m2-svr 写集），本片只登记、不修。**

## 1. 为什么不是「命中门公式差」

- `crates/world/src/combat.rs:685` 的门
  `if target.hit_point > 0 && attacker.hit_point < rng.random_byte(target.speed_point)`
  与 oracle `BaseObject.Attack.cs:39-44`（`if (HitPoint < RandomNumber.RandomByte(targetObject.SpeedPoint)) nPower = 0;`）
  同形；`combat-probe` 的 `dodge_mix_100`（攻方 `HitPoint=20` / 守方 `SpeedPoint=40`，100 击）
  逐 k 与 oracle 全等（`../combat-probe/vectors/combat_vectors.tsv` + Rust 用例
  `crates/world/tests/combat_skill_vectors.rs`）。
- `RecalcHitSpeed` 的 `HitPoint/SpeedPoint` 派生也由 `../attack-hit-probe`（真身反射直调）钉死。
  ⇒ 命中门的**公式与派生**都不是 k=2 的候选。

## 2. 真机 Rust 攻方实体是「空实体」（属性差的一阶原因）

生产进图只造空实体、**从不把角色记录/ pin 的 `characters_ablity` 写进世界实体**：

`attack_diff.py` 用 `SM_STRUCK` 判 hit ⇒ Rust 侧 120/120 全记 dodge，`hits=0`。

## 3. 反面/次要证据：逐 k 也不是 seed+属性的函数

同侧同种子（C# c1 vs c2，同代码/同 seed=42/同 pin 属性）逐 k **不一致**（见
`c1-vs-c2-same-side.txt`：k=2,8,14,34,41,60,74,87,106 差）⇒ 逐 k 还取决于**攻击起始 RNG 流位置**。
C# `rng-stream.tsv`（本次 c3 栈，341,775 行）里攻击只占 ~120×2 次 `PlayObject.GetAttackPower`，
其余是**非 0137 图**的 `AnimalObject.Wondering`（112,529）与
`WorldServer.RegenMonsters`/`MonGetRandomItems`（数千）——即全局流仍被别的图持续消耗。
⇒ 即使属性补齐，两侧流位置仍需夹具层对齐（本片登记，属 m3bag/夹具面）。

## 5. 承接（本片不做）

- **属性装载**：在 m2-svr 的进图装配里把 `characters_ablity`/`RecalcAbilitys` 的
  `dc/ac/hit_point/speed_point/luck/...` 写进世界实体（`bins/game-svr/src/main.rs` 进图路径 +
  `enter.rs`）。⇒ owner 转 **m2-svr** 车道（写集外，未动）。
