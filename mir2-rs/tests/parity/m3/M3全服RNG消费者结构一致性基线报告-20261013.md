### 2.2 组集合 + 相对次序 diff（`groupdiff`，`include_attack=False`）

```
A_GROUPS  {... monster_ai 4028939, merchant 500838, drop 410383, construct 82840,
             spawn 63705, npc_ai 3770, revive 60, homemap 6, startup 1}
B_GROUPS  {startup: 8, homemap: 6}
ONLY_IN_A(missing_in_B) {monster_ai, merchant, drop, construct, spawn, npc_ai, revive}
ONLY_IN_B(extra_in_B)   {}
SHARED_GROUPS           [homemap, startup]
FIRST_SHARED_ORDER_DIVERGENCE index=1  a=homemap  b=startup
RUNS  a=76374  b=2
FIRST_RUN_DIVERGENCE run=0  a=construct  b=startup
VERDICT GROUP_SET_DIFF+SHARED_REL_ORDER_DIFF     （--strict ⇒ rc=1）
```

- **diff 项数（口径 = 组集合）**：C# 有 9 个非攻击组、Rust 有 2 个；**7 个组只在 C# 出现**，
  合计 **5,090,528 draws**；反向 **0**。这就是 Claim B 的当前结构缺口。
- **第一分歧点**：全流 index 0（C# `BaseObject..ctor` vs Rust `main.rs:2856`）；非攻击组序 index 1
  （共享组 `homemap` vs `startup`）。

> **⚠ 口径诚实性（必读）**：这一对 trace 是**两个不同场景**下各自起的栈（C# 是开世界/怪 AI 在跑，
> Rust 是攻击夹具的固定世界）。因此：
> 1. **组集合差（7 组缺）是可信的结构基线**——它反映当前 Rust 活栈**根本没有**这些消费者；
> 2. **相对次序 / run 序的第一分歧是「场景差异」而非「实现差异」**（C# 的 `homemap` 抽数发生在玩家
>    进图、Rust 的 `startup` 抽数发生在进程启动）⇒ **次序判据必须在「同场景、同起点」的两侧
>    trace 上重跑**才有仲裁力（见 §4 缺口 R-2）。**本片不据此判任何实现缺陷。**

- Rust 侧 trace 为 **④-C/④-D 的 .rs 改动之前**的旧代码件（旧行号、无 `attack_success`）；
  当前 master 已有 `crates/world/src/monai.rs` / `mongen.rs` 与 `crates/formula/src/drop.rs` 的消费者，
  但**尚未在含怪的固定场景里同种子两侧实跑** ⇒ 上表的 Rust 侧 0 是「窗口/场景」缺，不是「代码没写」。
