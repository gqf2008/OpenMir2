## 1. 本片发现的 oracle 事实（DoD③ 前置）

第五片把真魔表 **108 行逐行登记**（`skills_registry.json` / `skill_vectors.tsv` 的 `reg` 行），
并声明「已实装 29」。核对 oracle 的**按魔号取定义**路径后发现一处未登记的语义：

1. **真魔表 `MagID` 不唯一。** 按 `sql/mir2_data.sql` 的 `magics` INSERT 逐行解析（108 行）：
   - 不同 `MagID` = **95** 个；重复 `MagID` = **13** 个，各出现 2 行：
     `48, 66, 71, 88, 89, 90, 91, 92, 93, 94, 96, 97, 98`。
   - 例：`Idx=38`（群体施毒术，`MagID=48`）与 `Idx=48`（气功波，`MagID=48`）；
     `Idx=66`（四级魔法盾）与 `Idx=158`（白日门四级法盾），等等。
2. **装表顺序 = SQL 行序。** `MySqlDB.LoadMagicDB`（`src/GameSrv/DB/MySqlDB.cs:105-160`）用
   `select * from magics`（无 `ORDER BY`，InnoDB 按主键 `Idx` 返回）逐行 `MagicList.Add`；
   Rust `mir2_data::loaders::load_magic_db` 同样按行序 `push`（`Vec<MagicInfo>`）。
3. **按魔号取定义 = 首匹配。** `WorldServer.FindMagic(int nMagIdx)`
   （`src/GameSrv/Word/WorldServer.cs:1430-1444`）线性扫描并 `break` 在**第一个** `MagicId == nMagIdx`
   的行；`WorldServer.cs:1201` 进世界重建 `playObject.MagicList` 即走它。
   ⇒ `FindMagic(48)` 恒返回先入表的**群体施毒术**；`气功波` 一行被**遮蔽（shadowed）**，
   运行时按魔号永远到不了。
4. **`DoSpell` 按魔号分派。** `MagicConst.SKILL_GROUPAMYOUNSUL = 48`
   （`src/Modules/SystemModule/Const/MagicConst.cs:154`）⇒ 魔号 48 走群体施毒术分支，
   与首匹配结果一致。Rust `magic.rs` 的 `48 => Some((1,2))`（群体施毒术）本就正确。

**对 DoD③ 的影响**：探针按**真魔表行**产用例（29 行 implemented），其中「48 气功波」是遮蔽行，
不构成一个独立的**已实装技能** ⇒ **可达已实装魔号 = 28**。本片不改探针产物（见 §5 承接），
而是把「可达魔号口径」与「首匹配语义」做成机器门禁 + Rust 侧原语。

### 2.1 `resolve_magic`（oracle 1:1）

```rust
pub fn resolve_magic(magics: &[MagicInfo], magic_id: u16) -> Option<&MagicInfo> {
    magics.iter().find(|m| m.magic_id == magic_id)
}
```

对 `WorldServer.cs:1430-1444`：线性扫描、取首行、找不到返回 `null`。**禁止** `HashMap`/`last-wins`
（后者会把 48 解析成遮蔽行气功波，与 oracle 不一致）。

### 2.2 三条新用例

| 用例 | 判据 |
| --- | --- |
| `duplicate_magic_ids_resolve_to_first_row_like_oracle` | 从 `reg` 行序重建装表序 ⇒ 断言 108 行 / 95 个不同 `MagID` / 13 个重复（逐 id 恰 2 行）；每个重复 id 的解析结果 == 该 id 首行；点名 `48 → 群体施毒术`，遮蔽行 = `气功波` |
| `implemented_cases_are_counted_per_reachable_magic_id` | 首行 = 可达、其余 = 遮蔽 ⇒ `implemented` **行**数 == 用例数（29），可达**魔号**数 == **28**，遮蔽的 implemented 行 == 恰 `[(48, 气功波)]`（逐条点名，不许静默漏）；用例侧 phantom 也点名 |
| `redcheck_duplicate_resolution_is_order_sensitive_must_fail` | 红检⑨：`first(48) == 群体施毒术` 且 `last(48) == 气功波` 且二者不等 ⇒ 任何 last-wins 覆盖必判红 |

## 5. 本批哪些项**不等价 / 未做**（含理由与登记去向）

1. **探针仍按「行」产用例**：`skill_vectors.tsv` / `skills_registry.json` 里 `48 气功波` 仍是
   一条 `implemented` 行与一条 phantom 用例（29 行 / 29 用例）。本片**不改探针产物**——
   探针重跑会改动 5 件向量哈希与 `SHA256SUMS.txt`，属独立可审的一格。
   ⇒ 承接 = 后续技能批次（或魔法接线批次）把探针改为**按可达魔号产用例**并给遮蔽行单独的
   `shadowed_duplicate` 类别；届时 `dospell_classes_are_fully_registered` 的 `implemented=29`
   需同步订正为「29 行 / 28 可达」。本片已用 `implemented_cases_are_counted_per_reachable_magic_id`
   把该差异钉成机器可见、且点名唯一 phantom，**不静默**。
2. **`resolve_magic` 尚未接线**：`game-svr` 目前无 `CM_SPELL` 派发（属 `m3-svr`/魔法接线卡的写集），
   `crates/world` 也没有「按魔号取定义」的调用点。本片先把原语与语义门禁落地，
   ⇒ 承接 = 魔法接线批次直接复用 `resolve_magic`（勿另写 `HashMap`）。
3. **真机 DoD①② 未做**：需 5000/7000/7100/7200 两侧栈（本片不占端口）。窗口优先级按卡面：
   `m2-svr` 进图门/移动/攻击接线 → 本卡。⇒ 登记等窗口。
4. **`DoSpell` 完整流程**（`MagCanHitTarget`/`AntiMagic`/护身符/召唤/状态挂载）仍不在本片，
   沿用前几片登记，承接 = 魔法接线批次。
