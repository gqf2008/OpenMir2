## 2. oracle 事实（逐行核过，含行号自检）

1. **`PlayObject.TrainSkill`（`PlayObject.cs:4393-4400`）**：`if (FastTrain) nTranPoint *= 3; userMagic.TranPoint += nTranPoint;`
   ⇒ 返回本次实际加点（`FastTrain` 时 ×3），调用方只负责累加。
2. **`PlayObject.CheckMagicLevelUp`（`PlayObject.cs:5198-5226`）**：
   `nLevel = (Level < 4 && TrainLv >= Level) ? Level : 0`（`:5202-5209`）；
   `if (TrainLv > Level && MaxTrain[nLevel] <= TranPoint)` ⇒ `TranPoint -= MaxTrain[nLevel]; Level++`，
   `UpdateDelayMsg(RM_MAGIC_LVEXP, 0, MagicId, Level, TranPoint, "", 800)`，`CheckSeeHealGauge`（`:5214-5217`），
   `result = true`（`:5223`）。**帧参数是调用后的 `Level`/`TranPoint`**（先改后发）。
   **死代码**：`:5212` 的内层 `if (TrainLv > Level)` 在外层已成立时恒真 ⇒ `:5219-5222` 的
   `else { TranPoint = MaxTrain[nLevel]; }` 永不执行（连 bug 一起搬：保留结构，结果不受影响）。
   `CheckSeeHealGauge`（`:5231-5240`）：仅 `MagicId == 28 && Level >= 2` 时置 `AbilSeeHealGauge = true`。
3. **`PlayObject.CheckSkillProficiency`（`PlayObject.Attack.cs:200-213`）**：
   `if (userMagic != null && Level < 3 && TrainLevel[Level] <= Abil.Level)` ⇒ `TrainSkill(…, nTranPoint)`；
   `if (!CheckMagicLevelUp(…)) SendSelfDelayMsg(RM_MAGIC_LVEXP, …, 3000)`。
   **取数顺序与 DoSpell 尾相反**：攻击路径由调用方 `AttackSuccess` **先抽** `Random(3)+1`（且只在 `Level < 3` 时），
   DoSpell 尾则是**先判门、门内才抽**（`:659`→`:661`→`:663`）。⇒ Rust 侧拆成 `check_skill_proficiency`（入参已抽好）
   与 `do_spell_tail`（门内抽数）两个入口，取数顺序各自对齐。
4. **锚点自检**：探针 `VerifyAnchors` 读 oracle 源断言三个方法首行含方法名、末行 trim 为 `}`，
   以及共享尾 9 个逐行锚点；任一不符**直接终止**（不出带错行号的向量）——与第七/八片同一机制。

### 3.1 取数账本口径

攻击路径调用方的 `Random(3)+1` 账本按 `ReplayRandom` 行式格式（`seq|Next(max)|arg|result|site`）带出；
Rust 用例 **强制回放同值**，断言「①取数序列零分歧 ②消费到底 ③抽到的 `n_tran_point` 与向量一致」。
`CheckSkillProficiency`/`CheckMagicLevelUp`/`TrainSkill` 本身**不取数**（取数在调用方），故 `chklv`/`train` 行无账本。
