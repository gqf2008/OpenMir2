## 1. 为什么要有它

M3「逐系统对齐」的十项系统**各有一副动作序列夹具**（`run_*_pair.ps1` + 比较器 + 场景），
但它们**分散在不同 branch / 不同 merge 片**里，且后一张常基于前一张**未合入**的 head
（例：⑦-5 基于⑥-5、⑩-3 基于⑦-5）。合并不齐时会出现「runner 在场、比较器/场景缺」的
**半拉子状态**——手敲七条命令逐副复核既费时又容易把半拉子当绿。

本片把这套「哪副夹具在哪、对应哪张卡 / 哪个 `whitelist.md` 登记号」做成**单一真源**
（`fixture_matrix.py` 内联的 `MATRIX`）与**一条命令的机判入口**，供：

1. owner 的周期性「夹具/判据链未劣化」复核；
2. M3 总验收收口前回答「十项夹具是否全部就绪」。

## 2. 判据（fail-closed 三级）

对当前树做**只读**核对，对矩阵里每项（十项系统 + Claim B）分类：

| 状态 | 含义 | 处置 |
| --- | --- | --- |
| `READY` | 三件套（runner + comparator + scenario，另加卡声明的额外件）**全在场** | 比较器必须 `selftest` rc=0；否则 `RED` |
| `PENDING` | 三件套**全不在场**（尚未合入） | 默认只登记；`--require-all` 判 `RED` 并点名 |
| `INCONSISTENT` | **部分在场**（缺一） | **恒 `RED`**：半拉子合并/漏提交，绝不当绿 |

`--require-all` 另核 `tests/parity/whitelist.md` 里的 `T-*` 登记号（缺则 `RED`）。
`selftest` 用合成树证明三级分类、`--require-all`、whitelist、以及「删一件 ⇒ 改坏必红」。

## 5. 口径 / 边界 / 未做

- **只读**：不写仓库文件、不起栈、不占端口；跑的是各比较器**自带的** `selftest`（`python -I`）。
- **不做**：不跑 runner 的 `-SelfCheckNoStack`（那会 `dotnet build BotSrv`，重且非必要；owner 的
  完整就绪度包逐副跑它就是）；不判「夹具内容正确性」——那是各卡审线的职责，本门只判
  **在场性 + 比较器自检**。
- **不占 T 号**：本件零 `crates/**` / `bins/**` / `src/**` 改动，不需要新 whitelist 登记；
  它只是读 `whitelist.md` 的 T-42..T-46。
- **未做（等窗口/等他线）**：真机两侧同序列 diff=0（各夹具 DoD②③）仍等实现卡 + 独占窗口；
  本件不改变那些判据。
