## 1. 本片解决的 DoD③ 问题

第五片把真魔表 **108 行**按 `DoSpell` 的控制流归入 6 个分派类别，其中 `context_required = 10 行`
（8/17/20/21/30/32/37/40/41/46）只给了一句「效果需地图/目标/可见集/召唤/状态」。这条口径
**太粗**：10 行里其实混着「真有独立方法、连地图都不需要就能直调」与「体内必须走 Envir/刷怪」
两种，若一律登记为「需上下文」，就等于把**可以现在做实**的技能也一起挂起。

本片在**不改第五片 `dospell_class` 口径**的前提下，对每一行再加一轴 **`effect_entry`（效果入口可达性）**：

| `effect_entry` | 含义 | 行数 |
| --- | --- | --- |
| `<implemented>` | 本卡已实装（`crates/world/src/magic.rs`） | 29 |
| `IsWarrSkill+DoSpell` / `DoSpell` | 前置即 `return`，无效果体可达（`warr_reject` / `magicid_reject`） | 8 / 35 |
| `MagicManager` 私有方法 | case 体是**独立可调**函数（点名 + 行号锚点） | 9 |
| `<inline>` | case 体**内联**在 `DoSpell` switch 里（40 十方斩清状态） | 1 |
| `<inline break>` / `<none>` | 无副作用 / switch 无此魔号 | 6 / 20 |

再对 9 条「独立方法」标 `probeability`：**只有 20（`MagTamming`）与 32（`MagTurnUndead`）**
能被真身反射在**无地图、无 socket** 的独立对象上直调（其余 7 条体内走
`CharPushed→Envir.CanWalk`、`MapRandomMove`、`MakeSlave`、`PlayCloneObject` 等）。本片把
**这两条真的调起来**产向量并逐字段核对进 Rust；其余 7 条**只 source-cited、不冒充真身**。

## 2. oracle 事实（逐条核过，含行号自检）

1. **`MagTurnUndead`（`src/M2Server/Magic/MagicManager.cs:827-856`，32 圣言术）**：
   `SuperMan || LifeAttrib != LA_UNDEAD` ⇒ `return false`；否则 `((AnimalObject)target).Struck(playObject)`
   （`TargetCret == null` 时**不抽** `Random(6)`；`Animal` 为真时 `MeatQuality -= Random(300)`；
   `IsProperTarget(施法者)` 为真 ⇒ `target.TargetCret = 施法者`；因 `TargetCret` 已写，**不进** `RunAwayMode` 分支），
   `playObject.SetTargetCreat(target)`，再 `Random(2) + (caster.Lv-1) > target.Lv` 且
   `target.Lv < MagTurnUndeadLevel` 时 `Random(100) < (magicLevel << 3) - magicLevel + 15 + level`
   ⇒ `target.WAbil.HP = 0`。
2. **`MagTamming`（`:704-825`，20 诱惑之光）**：外层 `Race > Play && Random(4 - magicLevel) == 0`；
   命中后**无条件** `target.TargetCret = null`；`Master == 施法者` 走早分支；
   否则 `Random(2)` → 等级差门 → `Random(3)` → `Random(caster.Lv + 20 + magicLevel*5) > target.Lv + cfg`，
   全部通过且 `!NoTame && LifeAttrib != LA_UNDEAD && target.Lv < MagTammingLevel && SlaveList.Count < cfg`
   时，`n14 = MaxHP / MagTammingHPRate`（`<=2` 取 2，否则翻倍）再 `Random(n14) == 0` 才受奴：
   先 `if (Master != null) WAbil.HP /= 10`，再 `Master = 施法者`、`Random(caster.Lv * 2)`（`MasterRoyaltyTick`）、
   `WalkSpeed/NextHitTime` 按 `1500/2000 - magicLevel*200` 封顶、`SlaveList.Add`；
   受奴失败 `Random(14) == 0` ⇒ `HP = 0`；不死系未受奴 `Random(20) == 0` ⇒ `HP = 0`；
   变红分支 `OpenCrazyMode(Random(20) + 10)`。**`MasterRoyaltyTick` 里的 `GetTickCount()` 非确定，
   不入向量**（只核稳定输出）。
3. **锚点不再手抄**：探针内置 `VerifyAnchors`，逐条读 `MagicManager.cs`，断言
   ①首行含 `方法名(`；②末行 trim 后是 `}`；③末行下一行是空行或 `}`。任一不符**直接终止探针**
   （不出带错行号的向量）。这条是对 F-1 行号漂移（同族第 3 次）的**机器化预防**：
   本片初稿的 `MagTurnUndead` / `MagSaceMove` / `MagMakeSinSuSlave` / `MagMakeSlave` /
   `MagPushArround` / `UNAMYOUNSUL inline` 六个末行都多算了 1 行，已被自检当场拦下并逐条订正。

### 3.1 向量取数账本口径（比"只比最终数值"更强）

探针把 oracle 的 `System.Random` 覆盖成记录包装，按 Rust `ReplayRandom` 的行式格式
（`seq|Next(max)|arg|result|site`）逐次记账。Rust 用例用 `ReplayRandom` **强制回放同值**，
再断言「①取数序列零分歧（kind/arg 逐条相同）②消费到底（`remaining == 0`）③可观测输出逐字段相等」。
⇒ 多抽、少抽、换参数都会红（见 §5 红检实跑）。

4. **`DoSpell` 完整流程**（`MagCanHitTarget`/`AntiMagic`/护身符/召唤/状态挂载）仍不在本片，
   沿用前几片登记，承接 = 魔法接线批次。
