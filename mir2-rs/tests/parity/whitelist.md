# 对拍白名单 / 已知边界登记

按 §6.0-3：差异要么 0，要么进本文件；每条写明「差异点 / 为什么无害 / 谁审的」。

## B 线（脚本引擎）

### 登记 1：Envir 全量解析的 427 条“脚本错误”不是两侧差异

- **差异点**：无两侧差异（C# 427 条 / Rust 427 条，逐行多重集差 0/0）。登记原因是验收口径：M4 验收①写“解析错误 = 0”，但 C# 参照在同一份语料上就产出 427 条。
- **内容**：24 个文件含未知命令行（`TakeOn`/`H.TakeOn` 222 条、`GAMEGIRD`/`GAMEDIAMOND` 系 96 条、`ReadRandomLine`、`CHANGEATTACKMODE`、`RecallHero`、`SETOFFLINEPLAY` 等），这些命令名在 C# 源码（`ConditionCode.cs`/`ExecutionCode.cs` 及全部 `src/`）中不存在，属 LEGM2 等引擎变体遗留内容；C# 行为为逐行记 `脚本错误` 并跳过该行继续。
- **为什么不能“收敛到 0”**：内容冻结 + 行为等价约束下，实现这些命令会偏离 C# 参照（C# 没有这些命令）；改脚本内容违反内容冻结。唯一合规状态是两侧逐行一致（已达）。
- **证据**：`tests/parity/envir-2026-10-10/`（双侧 JSON + diff.txt + handler-maps.txt + SHA256SUMS）。
- **审**：待 owner 确认口径（建议把验收①的“解析错误”修订为“双侧解析错误逐行一致”；或明确以生产实际加载的脚本子集为口径）。

### 登记 2：命令码位移（解析 `字段序号-1` vs 执行注册 `枚举值` 键）

- **差异点**：无两侧差异。登记原因是它是后续批次实现求值器时的最高风险点。
- **内容**：C# 解析器对普通条件/动作命令存 `GetFields() 字段序号 - 1`（特判 `CHECK`/`CHECKOPEN`/`CHECKUNIT`/`Set`/`ReSet`/`SetOpen`/`SetUnit`/`ResetUnit` 存原值），执行侧注册表以枚举值为键，导致脚本命令派发到前一个枚举成员的处理器。已实机反射 dump 双表（`handler-maps.txt`：条件 111 条 / 动作若干条）。
- **处置**：Rust 求值器按位移后语义 1:1 派发，不“修正”。
- **审**：B 线自查（实机探测记录见 `crates/script/README.md` 怪行为清单第 2 条）。

### 登记 3：重名 label 改名随机源

- **差异点**：无计数差异。改名后缀值域 [1,200]；C# 生产为无种子 `new Random()`（不可复现），harness 反射播种 42；Rust 侧用复刻的 `System.Random(42)`，序列逐位一致（`random.rs` 测试钉死）。
- **为什么无害**：后缀取值不进入任何验收计数；仅在数据文件被误当脚本喂入且重名 >200 次时影响崩溃时点（两侧同样整文件丢弃）。
- **审**：B 线自查。
