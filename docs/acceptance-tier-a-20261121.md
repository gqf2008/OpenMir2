# 验收口径 A（2026-11-21 Owner 定方向，总监落口径）

> Owner 原话："C#逐字节是什么 逻辑一致就可以了 逐字节什么东西"。
> 总监据此定口径 A：**逐字节仍是核心玩法的验收手段，但不再是全系统硬约束**。
> 本文是口径的唯一事实源；与 `docs/qa-charter.md`、`docs/merge-gate.md` 冲突时以本文为准，
> 直到口径被正式修订。

## 1. 仍然逐字节（不得放宽）

以下路径在**同一驱动、同一虚拟时钟**下必须与 oracle 逐字节一致（帧内容、字段、顺序、时序）：

- 技能 / 魔法：施法、伤害、自延迟投递、帧广播（含 `Sent[].tail` 严格比较）；
- 战斗 / 掉落 / 经验；
- 物品 / 装备 / 拾取 / 交易；
- 任务 / NPC / 商店；
- 聊天与协议编解码（含 `SM_ABILITY` 等尾编码）。

理由：这些是玩家可感知的玩法结果，"逻辑一致"在这里必须落到可比对的面上；逐字节是最便宜、
最不会自欺的判法（已有 150 驱动 / 50 比较器）。

## 2. 放宽（允许差异，但须可判）

| 维度 | 从 | 到 |
| --- | --- | --- |
| 线程数 | 单进程单模拟线程 | 允许多 World / 多 worker（每 World 仍固定单线程） |
| 地图归属 | 全图在一 World | 允许按地图组切分，**一张图仍只归一个 World**（拆图另立项） |
| 内部数据结构 | 不许改但需等价 | 允许改（哈希/索引/缓存），**前提：可见输出不变** |
| 时序 | 逐毫秒相等 | 允许毫秒级差，但**同收件人的帧相对顺序不变** |

## 3. 判 "逻辑一致" 的三条硬面

任何放宽都必须在这三面给出断言，缺一不算通过：

1. **同屏可见性**：同一时刻、同一观察者可见的实体集合与 oracle 相同；
2. **帧内容与数值**：帧的 ident/param/tag/series/tail 与数值字段相同；
3. **顺序**：同一收件人收到的帧序列相对顺序相同（跨收件人不要求）。

## 4. 回归义务

- 放宽不得让第 1 节的任一条变红；改结构前先跑全量对拍取基线，改后逐支点名比对。
- 每条放宽必须留痕：改了什么、为什么不会改变第 3 节三面、如何验证（断言或对拍原文）。

## 5. 仍未定（需 Owner 一句话才能再放宽）

- **拆图分区**（一张图拆给多个 World）：会改变跨区可见性与帧时序，属新增语义，需 Owner 明示；
- **过程帧不判**（只比最终态）：等价于口径 C，未采用。
