## 0. 一句话结论

真 C# 栈上「同账号/角色在旧会话仍在线时再登录一次」的实测是：**旧连接收到
`SM_SYSMESSAGE` 红字提示「当前登录帐号正在其它位置登录，本机已被强行离线!!!」（不是 `SM_OUTOFCONNECTION(528)`），
且旧连接不立即断开；新连接被放行还是被 `CloseUser` 关，取决于 `ProcessHumansIsLogined`
（`InSaveRcdList`/`PlayObjectList`）在那一刻是否命中——两轮都实测到了。**

这纠正/细化了 owner comment `272582e1` 的单一结论「两边都不放行」：该结论对应**命中时**的那一支；
不命中时新会话照常进世界。

## 1. 做法（为何这样采）

- 起真 C# 栈（`E:\MirServer\start-all.ps1`，端口 5000/7000/7100/7200 独占）。
- 账号 `fixt0`（`tools/client/account_provision.ps1` 在 LoginSrv 启动前建；角色 `fixt0`）。
- 两轮：
  - **轮 A**：两个 `src/BotSrv` 进程（仓库自带 headless 客户端）同账号同角色——第一个先进世界（旧），第二个再登录（新）。
  - **轮 B**：真 Delphi 客户端（`D:\MirClient-run\run-release.cmd` + `tools/client/mir_flow.ps1 -KickVia fixt`）先进世界（旧），
    BotSrv 同账号再登录（新）。
- 判据只登记实测，不预设分支。

## 2. 结果

| 观测项 | 轮 A（bot/bot） | 轮 B（真客户端/bot） |
| --- | --- | --- |
| ① 旧连接收到 | `SM_SYSMESSAGE`：「当前登录帐号正在其它位置登录，本机已被强行离线!!!」；不立即断开 | 同左（真客户端截图 `fixtureB*-06b-after-kick.png` 仍在世界里、聊天框红字提示） |

| ③ 旧 PlayObject 离场 | kick 后 GameSvr 记 `角色数据保存中,稍后重新读取`（+1.1s），随后离场 | 同左（kick 后数据保存中） |
| ④ 何时能再进 | kick 后 ≈3.4s 新会话进世界成功 | 旧数据仍在保存时新进不去；旧数据保存结束/离场后可进 |

## 3. 源码锚点（只作对照）

- 旧连接的提示：`M2Server/Net/TCP/TCPNetChannel.cs:229` `KickUser` → `PlayObject.SysMsg(..., MsgType.Hint)`
  （`BaseObject.cs:1588+`）→ `RM_SYSMESSAGE` → `SM_SYSMESSAGE`。
- 新连接的准入：`GameSrv/Word/WorldServer.cs:503` `!IsFull && !ProcessHumansIsLogined(chr)`；
  `ProcessHumansIsLogined`（`:200-217`）= `FrontEngine.InSaveRcdList(chr)` 或 `PlayObjectList` 有同名；
  命中 ⇒ `:535` 置旧 `BoKickFlag` + `:536-537` 记新 + `:568-570` `NetChannel.CloseUser(新)`。
- 旧离场：`WorldServer.cs:705-710`（`PlayObjectList.Remove` + `AddToHumanFreeList` + `SaveHumanRcd`）。

## 4. 对 Rust 的提示（交 owner 裁决，本片不改 Rust）

现 Rust `bins/game-svr` 的重复进世界处置（`enter_map` 返回 `AlreadyInWorld` ⇒ 踢旧 + 关新，旧收 `528`）：
- 「关新」与 oracle 命中支一致；
- 「旧收 `528`」与实测不一致（实测旧收的是登录链路账号级 kick 发来的 `SM_SYSMESSAGE`）；
- 若 Rust 登录链路没有等价的账号级 kick，Rust 的旧会话不会被软关、也就不会被同名新会话取代，端到端与 oracle 不同。
