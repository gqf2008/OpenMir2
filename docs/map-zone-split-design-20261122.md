## 0. 结论摘要

1. **可行性（先给结论，别附和）**：在**今天**的「单 World 单线程 + 单一 HostInbound 队列」上，**单图 1 万在线物理上做不到**——
   - tick 成本 `W_total(10k, 39.5k) ≈ 813ms` / `(10k, 53.5k) ≈ 937ms` ≫ 200ms 预算（附录 A 线性模型）；
   - 更硬的是**入站**：5000 档实测 `frames_in ≈ 3319 帧/s` vs `drain ≈ 345 事件/s`，队列净增 ~2970/s、窗口末积压 ~1.07M 事件，tick 从 201ms 涨到 513ms（`docs/capacity-preflight-5000-10000.md` §5.1/§5.1b）。**这不是 tick 算力问题，是入站是单线程单队列。**
2. **可做的前提**（缺一不可）：**区（region）粒度拆到 N=10–12 个 World + T=8–10 个有效 worker 线程 + 每区自己的入站队列（入站必须并行排水）+ 热点密度治理**。满足后 10k 在 200ms 内有机会（推算 81–156ms/线程），100ms 需 T≥8–10 或再降 25–50%。
3. **反例/物理上限**：若 1 万人**空间聚集**（攻城/主城），AOI 是「以人为中心、边长 `2*view_range+1` 的方格扫描」（`aoi` `search_view_range`），一个热点始终落在**单个区**里 ⇒ 该区按「1 万人的同屏集合」退化，拆区救不了热点。⇒ **必须配每区/每格块的人数上限或 AOI 降频**，否则「单图 1 万」等价于「单区 1 万」。
4. **一句话**：拆区能把「空间分散的单图 1 万」跑进 200ms；跑不进 100ms 与「空间聚集 1 万」是两条独立的硬约束，必须单独立判据。
5. 所有 N>1 结论**标记为外推**（线性模型、无 C×E 交互、同图 AOI 上界未测），以 P0 二维网格实测为准（`capacity-model` §4.6 可辨识性缺口）。

### 0.1 两层可组合（Owner 2026-11-21 补充：打开 bevy 多线程调度）

原硬约束「单线程 executor」由 Owner 放宽为「可开 bevy 多线程调度」。设计按**两层正交**写，可单独、也可同时用：

- **L1 区内并行**：一个区的 World 内启用 bevy 多线程执行器。**门槛 = 重放确定性门**（同 N / 同种子 / 同输入，两次运行逐字节相同）；达不到就退回该区单线程执行器。**L1 能把单区每 tick 墙钟压低多少：待实测，不填理论倍数。**
- **L2 区间分区**：同一张图拆成多区、多 World / 多 worker / 多进程（本设计主线）。
- **组合**：`每区墙钟 = W_region / s_L1`，`总墙钟 ≈ (W_total / N) / s_L1 / T_region`（`s_L1` = 实测区内并行加速比，待测）。
- **对拍口径不变**：R=1 且未开 L1 时仍须与 oracle **逐字节等价**（合并硬门）。**若在 R=1 也开 L1**，只有证明帧面与 oracle 逐字节相同才算「对拍模式」，否则按 N>1 口径（可重放 + 三面判据）验收——不得用「多线程但逻辑一致」含糊过去。

## 1. 目标、口径与硬约束

- **目标**：同一张地图（同一 `map_id`）的 1 万在线，由多个 World（区）共同承载。
- **A 口径硬面（拆图后仍须成立）**：同屏可见性集合、帧内容/数值、**同一收件人帧相对顺序**（`acceptance-tier-a` §3）。
- **1 区模式 = 对拍模式**：`R=1`（不拆）必须与 master/oracle **逐字节等价**，作为合并硬门（`decisions-10k` O2）。
- **N>1 不是 oracle 逐字节等价**：每区独立 RNG、跨区一拍延迟；改为「可重放 + 帧完整性 + 场景测试」（`decisions-10k` O2）。
- **跨区换图/跨区过界允许 1 tick 过渡**，但必须**有界、可观测、可测**（`decisions-10k` O5）。
- **tick 上限**：10k 交付按 **P99 ≤200ms**（`decisions-10k` O3）；100ms 为 stretch。
- **执行器（Owner 2026-11-21 补充）**：**打开 bevy 多线程调度**，原「单线程 executor」硬约束就此放宽。但**重放确定性门**成为新的硬门：同 N / 种子 / 输入两次运行逐字节相同；过不了门 = 该区退回单线程执行器。**R=1 对拍模式默认仍单线程**（保 oracle 逐字节）；L1 多线程主要在 N>1 模式启用，或须单独证明帧面与 oracle 逐字节相同。

## 3. 七问逐条（每条：结论 / 依据 / 可证伪断言）

### Q1 切分边界：按格子矩形切，还是按连通性切？边界怎么选？

**结论**：**按格子矩形切（rectangular cell blocks）**，不按连通性切。
- 理由：AOI 是**纯几何距离**扫描（边长 `2*view_range+1` 的方格，`search_view_range`），行走连通性/水域/障碍只影响 `CellAttribute`（能不能走），**不改变可见性判据**；按连通性切既不减少可见性跨界，又引入「连通块可能细长/回环」的病态边界。
- 边界选择（降低跨区交互，不改变语义）：优先把边界放在**低流量或不可走**的格列/格行（水域/障碍 `CellAttribute` 非 Walk），避开单一高流量走廊（桥、传送点）；每张图的区分块是**预计算静态布局**，写进启动配置，运行期不再平衡。

**依据**：`aoi` `search_view_range` 的方格扫描语义；`map` 的 `CellAttribute`；`decisions-10k` 项目内决策「地图组划分：先连通性 + 静态均衡，热点再告警」（这里把「组」下探到「区」，边界同理取静态均衡 + 低流量）。

**可证伪断言**：
- 对每个边界格 `c`，任取观察者 `v` 使 `|v-c| ≤ view_range`（`v` 可在邻区），其 AOI 方格必须被「本区 owned + 邻区 halo 镜像」完全覆盖——构造级穷举断言。
- 边界交通量 `cross_region_moves/s` 在目标场景（分散 10k）低于阈值；若某边界超阈值 ⇒ 布局不合格，需重切。

### Q2 跨区可见性：halo 多宽？谁产出跨界出现帧？会不会「两侧各发一次」或「谁也不发」？

**结论**：
- **halo 宽度 = `view_range`**（观察者能看到的最远距离 = 其方格半边长；`view_range` 是逐观察者字段，取**全局上界**做静态 halo）。即每区额外持有邻区 `view_range` 宽的**只读实体镜像**（位置/外形/名字/HP 等出帧所需字段）。
- **单一发射者规则**：**实体所属区（owner region）是该实体所有帧的唯一发射点**，发往「本区 + halo 内邻区」的观察者；观察者所在区**绝不**替外来实体出帧。
- 「两侧各发一次 / 谁也不发」由单一发射者规则**结构性地排除**，并用计数器对账兜底：`xreg_frame_sent` vs `xreg_frame_recv` 逐 `(observer, entity, event)` 相等，`dup=0`、`never=0`。

**依据**：A 口径 §3.1「同一时刻同一观察者可见集合与 oracle 同」；AOI 方格几何 ⇒ halo≥view_range 才不丢邻区可见目标。

**可证伪断言**：
- 边界场景（观察者贴边、实体在邻区来回移动）：两侧可见集合逐 tick 与「不拆/1 区」相同（同屏可见性面）。
- `xreg_frame_sent == xreg_frame_recv`（按事件 key）、`dup=0`、`never=0`；任一非零 ⇒ 判据红。

### Q3 跨区交互：远程技能/普攻/掉落/聊天/组队各自怎么路由？同一帧对同一收件人不得乱序（A 硬面 3）。

**结论**：
| 交互 | 路由 | 权威方 |
| --- | --- | --- |
| 远程技能/普攻命中**邻区实体** | 攻击意图发到**目标所属区** | 目标区算伤害/HP/RNG，发 31/53/656/struck 等帧 |
| 掉落 | 落在哪格就归**该格所属区** | 落点区拥有 `floor_items`，出拾取/视图帧 |
| 聊天/私聊/组队/行会/城堡/全局 | 走**协调器**（全局服务），不进区 | 协调器（零 RNG） |
| 同区战斗/交易 | **留区**（不跨区） | 区内 |

- **同收件人帧序**：跨区帧带确定性合并键 `(tick, region_id, seq)`；收件人侧（其区/网关）按该键**有序合并**，保证同一收件人的相对顺序与「不拆」一致（A 硬面 3）。

**依据**：`10k-shard-design` §2.1.1（协调线程、跨片一拍延迟）、§3.3.1（固定跨片顺序 `(thread_id, shard_id, seq)`）；A 口径 §3.3。

**可证伪断言**：
- 同一收件人在「区」与「1 区」两种布局下帧序列**相对顺序相同**（内容可因 RNG 分片不同而不同，但顺序判据只判序）。
- 合并键乱序注入测试：人为打乱到达序但保留键 ⇒ 输出仍按 `(tick, region_id, seq)` 有序 ⇒ 断言绿。

### Q4 跨区移动（handoff）：过界怎么搬？失败如何 fail-closed？

**结论**：**tick 边界受控 handoff**。玩家过区界时：
1. 源区冻结该玩家（本 tick 不再行动）；序列化最小状态：坐标、HP/MP、buff/三态计时器、技能冷却、背包/装备（引用/句柄）、组队/行会、宝宝、会话/socket、可见集合；
2. 经协调器转到目标区，**下一 tick** 插入；
3. 源区发「离开视野」帧，目标区发「进入视野」帧；中间一拍该玩家对他人不可见（`decisions-10k` O5 允许的 1 tick 过渡）。

**fail-closed**：目标区不可用 / handoff 校验失败（指纹不符）⇒ **不搬**：玩家留在源区边界格、本 tick 视为普通「到边界但走不动」，累计 `handoff_refused+=1` 并 WRN；绝不产生「两头都无 / 两头都有」的玩家。

**依据**：`10k-shard-design` §2.1.1（受控 handoff + 一拍不可见）、§2.1.5 风险 4（源+目标指纹对账）；`decisions-10k` O5。

**可证伪断言**：
- handoff 前后「源已删 + 目标已建」且 `源指纹 == 目标指纹`（坐标/HP/MP/buff/背包/宝宝/组队逐项）；失败注入 ⇒ `handoff_refused` 计数 +1 且玩家仍在源区原格（0 状态丢失、0 会话掉线）。
- 边界来回走的确定性重放：同 N/种子/输入两遍逐字节相同。

### Q5 确定性：确定性怎么保？跨区帧时序偏差上限写多少 ms？

**结论**：
- **区内仍单线程**：每 World 固定 owner 线程、不迁移、不共享 `&mut World`；RNG 每区私有、协调器零 RNG（`10k-shard-design` §3.3.1）。
- **跨区帧时序偏差上限 = 1 个 tick = 200ms**（跨区消息/过界帧一拍延迟；与 `decisions-10k` O5 一致）。**同一收件人的相对顺序不减损**（由 Q3 的合并键保证）。

**依据**：`10k-shard-design` §2.1.3 / §3.3.1；A 口径 §2「时序允许毫秒级差，但同收件人帧相对顺序不变」。

**可证伪断言**：
- 同一收件人跨区帧的**到达偏差 ≤ 200ms**（日志时间戳对账），且**相对顺序**与 1 区一致。
- 同 N/种子/输入两遍逐字节相同（可重放）；每个 World 的 tick 仍由**单一 owner 线程发起**（bevy 执行器可在其内部并行跑系统），`TickOwnerThread` 语义调整为「owner 线程唯一发起者」而非「无并行系统」。
- **L1 区内多线程（Owner 打开 bevy 多线程）**：`Query`/系统调度序不是契约 ⇒ 必须过**重放确定性门**（同输入两次运行帧字节相同）；不过门 ⇒ 该区退回单线程执行器。该门与 A 口径 §3 三面一起构成 N>1 的确定性判据。

### Q6 容量核算：N 区 × 每区玩家 × 每区 E；建议 N、每区上限；哪些系数是外推。

**结论**：用线性总模型 `W_total ≈ 0.04644×C + 0.008834×E`，10k 场景：

| N（区/World） | 每区玩家 C/N | 每区实体 E/N（E=39.5k） | 每区 ms（推算） | ≤100ms？ |
| --- | --- | --- | --- | --- |
| 8 | 1250 | ~4938 | ~102 | 否（临界） |
| **10** | **1000** | **~3950** | **~81** | **是（勉强）** |
| **12** | **~833** | **~3292** | **~68** | **是** |
| 16 | 625 | ~2469 | ~51 | 是（收益递减） |

- **建议 N=10–12**；**每区上限**：玩家 ≤1000、实体 ≤4000（按 39.5k；内容上限 53.5k 时每区实体 ≤4458，N=12）。
- **线程**：`每线程墙钟 = W_total / T`（与 N 无关）。T=6→135–156ms（基准/上限）；T=8→102–117ms；T=10→81–94ms。⇒ **200ms 单机 6 核可行**，**100ms 需 T≥8–10**（`10k-shard-design` §3.4）。
- **哪几个系数是外推**（必须标）：
  1. `0.04644×C`（固定分量随 C 线性）——只在 C=500 测过；
  2. `0.008834×E` 的系数在 10k 档不变；
  3. **无 `C×E` 交互项**——这是**最大不确定性**：`H(C,E)` 的 `1.1998e-5×C×E` 若因果，单进程 10k ≈ 5040ms（6× 于线性）；**拆区把它除以 ~N²**（`(C/N)×(E/N)`），N=10 ⇒ ~50ms，故拆区对该悲观项也有效。
  4. 同图 AOI 的 O(N²) 上界**未测**（`capacity-model` §4.6「同图口径警告」）。

**可证伪断言**：
- P0 二维网格（C×E 独立变化）实测出 `C×E` 系数；用实测系数替换后，每区 `tick P99 ≤ 目标`（200ms 或 100ms）且 `internal_errors=0`、`OOM=0`。
- 若实测 P99 超目标 ⇒ 优先加 T / 降 N-per-thread，而不是先加机器（多机属 O7，需先出计划报批）。

**Q6b 单区多线程（L1）能抬多少：待实测，不填理论倍数。**
- L1 把「每区 `W_region`」除以实测区内并行加速比 `s_L1`（**待测**）；与 L2 正交：`每区墙钟 = W_region / s_L1`、`总墙钟 ≈ (W_total/N) / s_L1 / T_region`。
- **在 `s_L1` 实测出来前，§0/§4 的 N/T 结论仍按单线程外推，不得把理论核数当结论。** L1 的真实收益受「同 tick 内可并行的系统占比、共享写冲突、`SlotTable` 顺序约束」限制，只有实测能定。

### Q7 验收：怎么证「同屏可见性/帧内容数值/帧序」三面不变？新断言与对拍改动。

**结论**：
- **R=1 模式**：所有现有 golden/parity/五门**原样**跑，逐字节不变（合并硬门）。
- **N>1 模式**：oracle 无拆图，故改为四面判据（对齐 A 口径 §3 + `decisions-10k` O2）：
  1. **同屏可见性**：边界观察者的可见集合逐 tick 与 1 区同（halo 正确）——新断言。
  2. **帧内容/数值**：同一事件产生的帧 `ident/param/tag/series/tail` 与 1 区同（RNG 依赖项除外，按场景关随机对照）。
  3. **帧序**：同一收件人相对顺序与 1 区同（合并键有序）——新断言。
  4. **无重复/无丢失**：`xreg_frame_sent==recv`、`dup=0`、`never=0`——新断言（Q2）。
- 另加：`handoff_refused` 可观测、跨区偏差 ≤1 tick 可测、同 N 可重放逐字节同。
- **可改的现有对拍**：R=1 一个都不改；N>1 **新增**场景测试（边界 halo / 跨区技能 / 跨区拾取 / 跨区聊天组队 / 过界 handoff），**不**把 N>1 塞进 oracle 逐字节比较。

## 4. 可行性判定（含反例与数字，不为附和而写）

### 4.1 今天的设计为什么不行（硬数字）
- `W_total(10k,39.5k)=813ms`、`(10k,53.5k)=937ms` ⇒ 单 World 单线程超 200ms 预算 4–4.7×（附录 A）。
- 入站：5000 档 `frames_in≈3319/s` vs `drain≈345/s`，净增 ~2970/s（`capacity-preflight` §5.1）；这是**单 `sim_loop` 事件队列**的墙，拆 World 但共用一条入站队列**不解**。

### 4.2 什么条件下可做
- **区级 World + 每区入站队列 + T 个 worker 线程并行排水**（A 口径 §2 允许「多 World/多 worker，每 World 固定单线程」）。
- N=10–12、T=8–10、每区玩家 ≤1000 / 实体 ≤4000、热点密度有上限。
- 满足后 200ms 有机会（81–156ms/线程）；100ms 需 T≥8–10 或总量再降 25–50%。
- **L1 区内并行（Owner 2026-11-21 打开 bevy 多线程）**：可把 `W_region` 除以实测 `s_L1`（**待实测**），是「不增区、不增进程」的另一杠杆；但必须过重放确定性门，且不得用理论倍数替代实测。

### 4.3 物理上限 / 反例（必须写进验收）
- **聚集 1 万反例**：AOI 是「人中心方格扫描」，攻城/主城 1 万人聚在一处 ⇒ 无论怎么切区，热点落**单区**，该区按「1 万人同屏集合」退化 ⇒ 该区 `W` 回到单进程量级、且 downlink `O(可见数)` 可能 `O(N²)`。
  ⇒ **必须**：每区/每格块人数上限（超限拒绝/排队/分线）或 **AOI 降频/降视距**（`decisions-10k` O6 的「AOI 降频/密度治理」）。
  ⇒ 可证伪：聚集 1 万场景下，热点区 `tick P99 > 预算` 即判定「未加密度治理前不可交付」。
- **同图 AOI O(N²) 未测**：`同图夹具密度 17.7`，分散场景未测；若真实密度更高，线性模型低估。P0 必测。

## 6. 待实测 / 外推项（一级不确定性）

1. **`C×E` 交互项是否因果**（`capacity-model` §4.6）——决定单进程是 813ms 还是 ~5040ms；拆区对两者都有效，但 N/T 选择不同。
2. **同图 AOI 的实际复杂度**（分散 vs 聚集）——决定 4.3 的密度治理是否需要先做。
3. **每区入站并行的真实吞吐**——5000 档已证单队列不行，但未见「每区一队列」的实测。
4. **跨区帧量占比**——决定 halo 镜像与跨区路由的 CPU 是否可忽略（假设「区内交互 ≫ 跨区」，未测）。
5. **10k 档 game-gate `SessionId` 4 位空间零余量**（`capacity-preflight` §1/§5.3）——拆区不改网关，仍需 ≤9000 或 sid 空间扩展（D-*）。
