## 0. 一句话结论

**先搬 `ground`（`CM_PICKUP`/`CM_DROPITEM`）作零进程态试点，同片第二步搬 `useitem`（`CM_EAT`）的

**拆片（2026-11-23 opc-27 已裁；`0c` 的 oracle 判定已出 ⇒ 走"统一单计数器"）**：
**M1c-2a** = **make_index 统一到 oracle 单计数器**（最优先）：三计数器 → **一个** oracle-faithful
计数器（init = `[Setup]ItemNumber + 屏障A`；`++` 后 `> int.MaxValue/2-1 ⇒ 1` 用 **CAS**；**返回值不带 tick**——有意确定性偏离，见 §T-72）；**删除 ②**（oracle `GetItemNumberEx` 是死码），GM-M 改走同一 Arc；

**M1c-2b** = `ground`/`bag`/`querybag`/`storage` 零进程态纯接线；

### 1.2 make_index 统一单计数器的注入点与初始化次序（2a）

**oracle 事实（`0c` 读 C#，2026-11-23；本片据此定案）**：
- **唯一活发号器** = `M2Share.GetItemNumber()`（`M2Share.cs`）：`Config.ItemNumber++` →
  `> int.MaxValue/2-1 ⇒ 1` → **返回 `ItemNumber + HUtil32.GetTickCount()`**；
- `GetItemNumberEx()`（`:557`）**全仓零调用 ⇒ 死码**；
- **唯一赋号点** = `GameItemSystem.cs`（`CopyToUserItemFromName` 内）；其余 `MakeIndex =` 全是
  **拷贝已有值**；怪物掉落无第二发号点 ⇒ **五类（掉落/商店/脚本/GM/使用物品）共用同一个计数器**。

**裁决（opc-27 2026-11-23，`0c` 核准）：统一只做「单 counter + CAS 复位」，返回值不带 tick。**
- 理由：`0c` 排查 make_index **没有** glog/sort/TSV/排序/RNG 依赖；DB 按槽位下标写、
  `characters_bagitem.MakeIndex` 已在 `masked_columns`；帧面 D-1 掩。带 tick 会让每次跑的值不同，
  **N=1 两树若比较未掩的原始字节立刻不成立** ⇒ 保留跨跑确定性优先。
- **这是一条有意的确定性偏离，必须登记**（§T-72）：oracle 返回 `ItemNumber + GetTickCount()`；
  **我们只返回计数值**。注释写死：**若将来解 D-1 掩码，必须先补 tick**。

**Rust 现状与改动面**：
- ① Host `item_number`（`SharedServices.item_number: Arc<AtomicI32>`，M1c-1 已共享）与
  ② `item_number_ex`（同形 Arc，GM-M）= **两个**；③ `SimState.item_number: ItemNumberCounter`
  （`formula/drop.rs`；`World` 经 `Deref` 访问，`world.rs`，**从不赋值 ⇒ 恒 0**）
  = **第三个**。⇒ 三 → 一。
- **① 的 7 处分配点**（M1c-1 规格 §1 表）改成统一 CAS 并返回**计数值本身**（**不加 tick**，
  与今天返回值一致 ⇒ 既有绝对值用例尽量不动）。
- **② 删除**：`SharedServices` 从 7 字段回到 6（去 `item_number_ex`）；`next_item_number_ex`
  的 clamp 语义**取消**（oracle 死码）；GM-M（`apply_pending_gm_m_commands`）改走统一计数器。
- **③ 接同一 Arc**：`ItemNumberCounter` 内部改持 `Arc<AtomicI32>`（或让 `SimState` 直持 Arc，
  二选一，行为等价）；`next_value` 改 CAS（保留 `> MAX/2-1 ⇒ 1`）；`generate_drops` /
  `mon_get_random_items` / `merchant.rs` 签名由 `&mut ItemNumberCounter` 改
  `&ItemNumberCounter`（不再需要 `&mut`）。
  **签名波及清单（实施时一次改完）**：`formula/drop.rs` 定义 + 3 处测试调用；
  `world-bevy/src/combat.rs`；`world-bevy/src/world.rs`；
  `world-bevy/src/lib.rs`（`ItemNumberRes` 系统）；`bin/drop_bench.rs`；
  `world-bevy/tests/bevy_drop_parity.rs`；`tests/parity/tests/drop_parity.rs`。

**注入点（全部经同一个 `Arc`）**：
1. 创建：`run_inner` 单点 `Arc::new(AtomicI32::new(0))`（与 M1c-1 的 ids_online 同法）；初值
   `item_number_counter_init(enter_cfg.newbie.item_number, &barrier_a)` 由 `sim_loop` 的 `store`
   写入（沿用 M1c-1 的位置，**早于 `world_start.mark_ready`**）。
2. 传递：`sim_loop(…, make_index_counter)` →（a）区 0 `production_world`（`lib.rs`；**不是 `make_world`，该名不存在**）
   → 注入 `SimState.item_number`；（b）区 k：`new_zone_state` / `HostLoop::for_zone` / `ZoneState::new` 同参
   （**当前为 7/3/3 参，注 counter 后 8/4/4**，见 §8.4）；（c）`SharedServices.item_number` 与 GM-M 同 Arc；（d）`ItemNumberRes`（bevy 资源，
   `world-bevy/src/lib.rs`；默认插入三处 `ItemNumberRes::default()`）——实施时核实生产 tick 是否经过；
   若经过，用同一 Arc 构造。
3. **复位语义显式化**：CAS 里 `>= MAX/2-1` 后写 1（与 C# 逐字一致）；**不加 tick**。
4. **区 k 可能从 0 起但不重复**：初值以 `sim_loop` 的 `store` 为准；区 world 在建 Arc 之后建成；
   首个 `WORLD_HEAD` 前必已 store（见下）。

**初始化次序（两条约束）**：
- **初值**：`store(init)` 必须在**首个 `WORLD_HEAD`**（`step_mon_gen` 首次 `generate_drops`）之前；
  现状 `store` 早于 `world_start.mark_ready` 且早于首个 tick 循环 ⇒ 成立。加源码顺序牙。
- **③ 不再 per-World 从 0 起**：`SimState` 构造不再 `ItemNumberCounter::default()` 而是注入 Arc；
  测试/legacy 路径可保留 `Default`（新 Arc(0)），生产必须注入。
- **不影响 RNG**：CAS 不抽随机 ⇒ 随机流不变。

## 2. 建议搬入顺序与理由

1. **`ground`（试点，第一提交）**：零进程态、零造件；把"族从 `INBOUND_PROCESS` 移到
   `INBOUND_LOCAL`"的全部配套跑通（区 k 调用点、`handle_zone_command_on` 分派、段序变化、
   零行为证据、N=1 两树）。失败面最小。
2. **`bag` / `querybag` / `storage`（第二提交）**：同样零进程态；连带上"区 k 会话事务"，
   为造件族铺路（背包/仓库读写先行）。
3. **`useitem` 解包支（第三提交，本片唯一真造件路径）**：
   - 前置 1：`unbind_list: UnbindList`（`Clone`、纯 `BTreeMap`，`unbindlist.rs`）进
     `SharedServices`（与 `enter_cfg` 同性质"只读副本"）；
   - 前置 2：**执行期分支门**——`CM_EAT` 在区 k 只执行"本地安全"分支（§1.1），其余分支
     必须回区 0。分类器是 **ident 级**（`CM_EAT` 一个 ident），门在**执行期**：拿到模板后若命中
     脚本/彩票/城堡支 ⇒ **不本地执行**，转区 0。
   - 前置 3（**已裁：泛化 A6 邮箱，不开第二机制**）：把 `ControlRequest` 泛化为**类型化请求枚举**；
     **本片只新增 `EatProcess(EatReq)`**；现有 GM `@` 请求（`chr_name/line/at_tick/epoch`）字段与
     行为**零变化**（枚举化后按 `GmSay` 命名；覆盖 A6 规格 r4 的字段表——同 r4 的"覆盖声明"写法）。
     一个 drain、一套计数：`wait_timeout` / `mailbox_rejected` 对 `EatProcess` 同样生效。
     **`!` 频道本片不接（A20）**：归 `Unsupported`；A-1b 的"`!` → `Process`、走 A6"**已被推翻**
     ——`!` 高频，逐条 `control_pending += 1` 会暂缓该玩家全部本地命令 ≤1 tick、撑爆
     `deferred_local`、挤占 256 邮箱把 GM `@` 挤成 `mailbox_rejected`，而 **oracle 聊天不阻塞移动**；
     `!` 的邮箱变体**不实现**（属将来"若重启该方案"的预留项）。
   - 前置 4（**顺序**）：分流后**同玩家**的相对序必须保住——`EatProcess` 请求与现有 GM `@`
     请求一样参与 A6 stop-and-wait：push 成功 ⇒ `control_pending += 1` / `first_tick`；该玩家后续的
     **本地可执行** `CM_EAT` 走同一暂缓队列（≤1 tick / 8 条上限），直到区 0 执行完并清位。
     吃没有 GM 那种跨类契约，T+1 可接受，但**不许因分流换序**。
   - 前置 5（**分支穷举 + 不许静默**）：分支判据做成纯函数（输入物品模板属性）并**默认 `Process`**
     （fail-closed：漏判的分支去区 0，不会"静默不执行"）；加一条**分支穷举牙**——枚举
     StdMode31/AniCount0、StdMode31/AniCount≠0、彩票、城堡战、StdMode3、表外模板，断言每个都
     落到枚举成员（无 `_ => Local` 兜底）、且删掉解包臂 ⇒ 解包正面牙红。回区 0 的请求在 mailbox
     满 / 区 0 不在时**计数 + WRN**（与 A6 同口径），不许静默。
4. **脚本造件族（give / 药物合成 / 开盒脚本）**：留 **M1c-3**。前置 = 脚本宿主跨线程方案
   （`NpcVars/NpcHost` 不可共享 ⇒ 只能"脚本执行留在区 0 + 请求化"或给区 k 独立脚本上下文；
   后者语义不可等价）。本片**不碰**。

**反对的顺序**：先搬 shop/药物合成（整族依赖 `NpcVars`/`sell_off_book`/`script_world`，且造件点在
脚本分支内）⇒ A9 类问题最多；先搬 `CM_EAT` 整族而不做分支门 ⇒ 部署有 `FunctionNPC` 时脚本分支在
区 k 静默变成"不吃" ⇒ **行为改变**。

## 3. ③ 定案：**统一到 oracle 单计数器（不带 tick）**

- **oracle 判定（`0c`）**：唯一活发号器 `M2Share.GetItemNumber()`；`GetItemNumberEx` 死码；唯一赋号点
  `GameItemSystem.cs` ⇒ 五类共用同一个计数器。⇒ 此前"③ 单开独立 Arc、不与 ①② 共用"的裁决
  **作废**；正解 = **三计数器并一、删 ②**（见 §1.2）。
- **确定性裁决（opc-27）**：统一后的计数器**只返回计数值、不返回 `+GetTickCount()`**——这是**有意
  偏离 oracle**，换取跨跑确定性与 N=1 两树可逐字节比对（`0c` 已核 make_index 无 glog/sort/TSV/排序/
  RNG 依赖；DB/帧面已掩）。**若将来解 D-1 掩码，必须先补 tick**（写进 §T-72 与代码注释）。
- **验收措辞（升级后，带窗口条件）**：
  - **可以写**：「**单计数器内全局唯一**」——同一原子、同一复位规则下，一个运行内 `make_index` 不重复
    （跨区、跨五类造件路径；由 trace 逐值断言）；也可写「**跨跑确定**」，但**必须带限定**：
    只对「**同 init、同复位窗口、同执行序**」成立；**并行/多区交错下值序本就不同**（已接受的
    数据面偏离）——**"跨跑确定" ≠ "跨区可复现"**，报告不得混用。
  - **仍不许写**：「**与 oracle 值相等**」——我们少了 `+GetTickCount()` 那一项（**永远不能写**）。
  - 旧说法「各计数器跨区不重叠」**作废**（只剩一个计数器）。
  - 窗口条件：复位阈值 `> MAX/2-1 ⇒ 1` 会在**复位窗口之间复用号**（既有语义）；验收窗口远小于复位点，
    报告写明。
- **② 删除的连带**：M1c-1 规格 §1.1/§2/§3 的 ② 段落、`SharedServices` 7→6、`item_number_ex`
  相关测试（CAS/clamp）全部**改或删**；GM-M 的 make_index 语义改为统一计数器（复位阈值
  `> MAX/2-1 ⇒ 1`，不再有 `MAX/2` 下限）。受影响用例清单列为 2a 的交付项。
- **① 7 处返回值不带 tick**（与今天一致）⇒ 钉绝对值的老用例尽量保持；仍逐条核（交付项）。

### 4.2 C1'：两区各造 K=1000 件（统一计数器 · 解码包路径）

  `CM_EAT` ⇒ 6 × 167 = 1002 件/区，合计 2004。

**`Copy` 去掉后的预计编译报错形态（实施风险项）**
- `ItemNumberCounter` 现为 `#[derive(Clone, Copy, Debug, Default)]`；持 `Arc` 后 **`Copy` 必去**。
- 预计报错：①**按值传参**（`fn f(c: ItemNumberCounter)` 或调用处传值）⇒ 可显式 `.clone()` 或改 `&`；
  ②**按值存字段并复制**（`let c = self.item_number;`、拆 `ItemNumberRes(c)` 后复制）⇒ 改 `&`；
  ③**依赖 `Copy` 的数组/元组复制**（如 `[ItemNumberCounter::default(); N]`）⇒ 换 `(0..N).map(...)`；
  ④ `ItemNumberRes(pub ItemNumberCounter)` 的**构造**仍合法（按值构造、不是复制）。
- **禁止**：给 `Arc` 包一层再 `impl Copy`（Copy 类型不能含非 Copy 字段；裸指针共享属未定义行为）。
  正确做法 = 去掉 `Copy`，把调用点改成 `&` / `&mut`→`&`。
- 建议 derive 收成 `#[derive(Clone, Debug, Default)]`（`Default` 仅测试/legacy 路径；doc 注明
  生产必须 `from_shared`）。
