## 1. INBOUND 拆段（INBOUND_LOCAL / INBOUND_PROCESS）

### 1.1 位分配
- 现 `INBOUND = 1<<1`（被 `PROCESS_ONLY` 引用）。
- 新增：`INBOUND_LOCAL = 1<<1`（复用旧位作 LOCAL）、`INBOUND_PROCESS = 1<<17`（新位）、
  别名 **`INBOUND = INBOUND_LOCAL | INBOUND_PROCESS`**（两位）。**`ALL` 由 17 位变 18 位：`ALL=(1<<18)-1`**。
- `has(INBOUND)` 仍是"任一位置位"：**区 0 开两位、区 k 只开 `INBOUND_LOCAL`**。
- 核点：全仓有**无测试硬钉 `INBOUND == 1<<1`**（若有改别名或改测试；`M0_MIN`/`M1A_PROD` 不含 INBOUND，不受影响）。

### 1.2 段体拆分（现 `if phases.has(INBOUND){ let svc=proc_svc!(INBOUND,"INBOUND"); …drain… }`）
- **排水与处理交错、留在 PROCESS 支；LOCAL 支暂不排空**（事件留通道保序）。
  - **依据（`max_wall` 契约）**：`EventDrainBudget.max_wall` = 「单轮最多花在**取事件 + 处理事件**上的墙钟」（lib.rs:31163）⇒ 必须 `while … drain.next()` **逐条取出即当条处理、交错在预算窗口内**；若改为"先整批取出再处理"，处理耗时被移出预算、`hit_budget`/carry 语义变 ⇒ 就不是纯结构。故**排水 + 逐条处理留在 PROCESS 支**。
- **PROCESS 支**（`phases.0 & INBOUND_PROCESS != 0`）：进入前 `proc_svc!(INBOUND_PROCESS,"INBOUND_PROCESS")`（记录位改 INBOUND_PROCESS）；**在此做排水循环 + 逐条处理**（回区 0 类 + 非 Command 事件 Closed/Kick/Register… 维持现状）。
- **LOCAL 支**（`phases.0 & INBOUND_LOCAL != 0`）：**本步为真空壳**（**暂不排空**；不调 `proc_svc!`）；本区命令的排水/执行留 M1b 补。
- **后果**：**M1b 真正接 LOCAL 时必须补「排水 + 预算 + A6」**，否则 LOCAL 支不排 ⇒ 事件在通道积压。
- **A6 接入点 = 排水层（不是命令处理层）**：分类（LOCAL/PROCESS）本就发生在**排水时逐事件判** ⇒ 控制命令的 `control_in_flight` 置位、本地命令的暂缓入队，都在 **LOCAL 支的排水循环内**完成（先分类：PROCESS ⇒ 投控制邮箱+置标记；LOCAL 且标记 set ⇒ 入延迟队列；否则执行）。§5.2 的"`handle_zone_command` 判 Local/Process"应理解为**排水层分类 + 分派**——defer/marker 落在分类处（排水层），不在 handle 内部。
- `RAN_SEGMENTS` 逐位记：跑 LOCAL ⇒ `|=INBOUND_LOCAL`、跑 PROCESS ⇒ `|=INBOUND_PROCESS`
  （区 0 全跑 ⇒ 两位齐；区 k 只 LOCAL ⇒ 只 `1<<1`）。

### 1.3 `PROCESS_ONLY` 换位 + 两条既有牙**必做重验**（不等门红才想起）
- `PROCESS_ONLY`（现 7 段 `SHUTDOWN|INBOUND|DB_POLL|PERIODIC|PLANES|PERSIST|SWITCH`）把 `INBOUND` → **`INBOUND_PROCESS`**。
- **牙 `proc_svc_segments_equal_process_only`（lib.rs:45579）必须继续绿**：区 0 跑 `ALL`、断言
  `PROC_SVC_SEGMENTS == PROCESS_ONLY`。换位后：PROCESS 支记 `1<<17`、`PROCESS_ONLY` 含 `INBOUND_PROCESS` ⇒ 相等。
  **关键**：LOCAL 支**绝不**记 `PROC_SVC`（否则多 `1<<1`、牙红）。
- **【实施·必做】`ALL` 变 18 位 ⇒ 两条既有牙期望值随之变，必须同时改并重验：**
  1. **`RAN_SEGMENTS == PhaseSet::ALL.0`**（W1 联合命题）：`ALL` 现 `(1<<18)-1`；区 0 跑 `ALL` 时 `RAN_SEGMENTS`
     须置到 18 位全齐（含 `INBOUND_LOCAL|INBOUND_PROCESS` 两位）== 新 `ALL.0`。若旧用例硬编码 17 位 `ALL`，一并改。
  2. **`M1A_PROD ∩ PROCESS_ONLY == ∅`**（正向牙）：`PROCESS_ONLY` 的 `INBOUND`→`INBOUND_PROCESS` 后，
     `M1A_PROD`（不含 INBOUND）与新 `PROCESS_ONLY` 的相交仍须为 ∅；**用常量引用（不是手抄位集）**断言。
- 旁注：`PERSIST_DB/OUTBOX` 当前**未拆**（`PERSIST=1<<13` 单一）——M1b 不动，M1c 拆（设计 §8.2 留缝）。

## 3. A6 同玩家跨类顺序（stop-and-wait）

### 3.1 面（M1b 具体）
- M1b 命令集里**唯一 PROCESS 类 = say 的 GM `@` 支**（回区 0，T+1）；本地类（move/hit/…）T。
  oracle 按到达序 ⇒ P 先 `@cmd` 再 move 应"@cmd 先"。两区下 move(T) 越 `@cmd`(T+1) ⇒ **同玩家命令序偏差**。

### 3.2 stop-and-wait 形态（含上限/溢出）
- **标记**：`SessionGround` 加 `control_in_flight: Option<u64>`（值=控制命令 `src_tick`）。
- **置位**：区 k 把 P 的 GM `@` 入控制邮箱时置 `Some(tick)`。
- **暂缓**：区 k 排水对 P 的**本地命令**：`control_in_flight.is_some()` ⇒ 不执行，入 **per-player 延迟队列**
  （`maps chr→Vec<(cmd,tick)>`，非单个 `event_carry`——carry 是单 Option，不够按玩家多命令）。
- **解除**：区 0 在 T+1 执行 P 的 GM `@` 时**持区 k 锁**(form d) ⇒ 顺手 `control_in_flight=None`（&mut 区 k SessionGround，属"会话修改"，合规）；区 k 下次排水见 None ⇒ 放行延迟队列。
- **上限/溢出**【实施·必做】：
  - **每玩家上限 N = 8 条**延迟命令。
  - **溢出策略**：满 N 再来 ⇒ **强制解除 `control_in_flight`（置 None）+ WRN + `control_defer_overflow` 计数 +1**，然后**按到达序放行**队列里已有的 + 新命令（
    **宁可越序也不丢命令、不无限延迟**）。之后该玩家恢复正常（无在飞标记），若后续再有 GM `@` 重新计。
- **超时**：控制命令保证 T+1 ⇒ 最迟 T+2 解除；`>2 tick 仍 Some` ⇒ 强制解除 + WRN + `control_wait_timeout` 计数 + 仍放行（降级不永卡）。
- **代价**：有在飞 GM `@` 时 P 的本地命令延迟 ≤1 tick（GM `@` 低频 ⇒ 可接受）。

### 3.3 能红判据（三条，含两条负例 + 一条幂等）
- `gm_say_then_move_preserves_order`：P 先 `@cmd` 再 move；断言 **P 的结果帧序 @cmd 先于 move**（对 N=1 同脚本 golden 的同玩家帧序）。
- **负例（必红）**：删 stop-and-wait（move 本地直执行）⇒ move 结果先 ⇒ 断言红（证牙真在验序）。
- **超时负例**：mock 区 0 不回控制命令 ⇒ 2 tick 后强制解除 + `control_wait_timeout+1` + 延迟命令仍执行（不丢）。
- **溢出幂等**（对应 §3.2 上限）：同一玩家连发 >8 条本地命令 + 一个在飞 GM `@` ⇒ 触发溢出 ⇒ 断言
  **溢出后命令一条不少（全被执行）、按到达序**、`control_defer_overflow==1`。

### 3.4 若判不可行 → deviation 卡草案
- 影响面：仅"同玩家 GM `@` 与本地命令相邻"⇒ 本地越序（T 先于 T+1）；帧内容不变、仅相对序变；GM `@` 低频。
- Owner 决策点：接受越序(低延迟) vs 接受 ≤1 tick 延迟(保序)。倾向 stop-and-wait（§3.2 可行、低频）。

## 5.1 第 1 步细化：INBOUND 拆段（逐文件/逐行 + 牙新期望值；只规划、不写码）

**改动文件**：仅 `mir2-rs/bins/game-svr/src/lib.rs`（生产段体 + 同文件测试）。基线 master `9db13e549`。

### A. PhaseSet 常量区（约 lib.rs:34600–34638）
- 新增 `const INBOUND_LOCAL: u32 = 1 << 1;`（=**0x2**）、`const INBOUND_PROCESS: u32 = 1 << 17;`（=**0x20000**）；
  改 `const INBOUND` 为别名 **`Self::INBOUND_LOCAL | Self::INBOUND_PROCESS`**（=**0x20002**）。
- 改 `const ALL`（:34618）：`(1 << 17) - 1` → **`(1 << 18) - 1` = `0x3FFFF`（262143）**。
- `M0_MIN`（:34633）= `WORLD_HEAD|WORLD_TAIL` = **`0x90`（144）不变**。
- `M1A_PROD`（:34638）= `M0_MIN|POST_HEAD|FRAMES|AOI_DOWNLINK` = **`0x14B0`（5296）不变**。
- `PROCESS_ONLY`（:34622）：`Self::INBOUND` → **`Self::INBOUND_PROCESS`** ⇒ 旧 `0x610F` → **新 `0x2610D`（155917）**。
- **旧 17 位 `ALL` 引用**：全仓**无硬编码** `0x1FFFF/131071`（已 grep），全部经 `PhaseSet::ALL` 常量
  （sim_loop@34490、测试@45597）⇒ 只改 `ALL` 常量即自动跟随，无需逐处改。

### B. INBOUND 段体（约 lib.rs:34987–35018）
- 现：`if phases.has(PhaseSet::INBOUND){ let svc=proc_svc!(PhaseSet::INBOUND,"INBOUND"); …drain…; RAN_SEGMENTS |= INBOUND; }`。
- 拆：
  - 外层 `if phases.has(PhaseSet::INBOUND)`（=LOCAL|PROCESS 任一）保留作「进段」，drain 两支共用。
  - **PROCESS 支**：`if phases.0 & PhaseSet::INBOUND_PROCESS != 0 { let svc = proc_svc!(PhaseSet::INBOUND_PROCESS,"INBOUND_PROCESS"); …回区0 命令 + 非 Command 事件…; RAN_SEGMENTS |= INBOUND_PROCESS; }`
  - **LOCAL 支**：`if phases.0 & PhaseSet::INBOUND_LOCAL != 0 { …本区命令（不调 proc_svc!）…; RAN_SEGMENTS |= INBOUND_LOCAL; }`
  - `RAN_SEGMENTS` **逐位**：哪支跑置哪位（区 0 两支都跑 ⇒ 置两 bit）。

### C. 两条牙新期望值（都**不改代码**、只重验/常量引用）
1. **`proc_svc_segments_equal_process_only`（:45579/@45601）**：PROCESS 支记 `INBOUND_PROCESS`(0x20000)
   ⇒ `PROC_SVC_SEGMENTS` 含 bit17；`PROCESS_ONLY` 新含 `INBOUND_PROCESS`(0x2610D 含 bit17) ⇒ **相等、绿**。
2. **`m1a_bits_do_not_intersect_process_only`（:45563）**：`M1A_PROD(0x14B0) & PROCESS_ONLY(0x2610D)` = **0**
   （bits 4,5,7,10,12 ∩ 0,2,3,8,13,14,17 = ∅）⇒ 仍 ∅、绿（常量引用，不手抄）。
3. **W1 `RAN_SEGMENTS == ALL`（M1-0e 的牙；master 现无，M1-0e 先于 M1b）**：换位后区 0 跑 `ALL`(18 位) 须跑齐
   **18 段**：`SHUTDOWN(0)|INBOUND_LOCAL(1)|DB_POLL(2)|PERIODIC(3)|WORLD_HEAD(4)|POST_HEAD(5)|PLAYER_RUN(6)|WORLD_TAIL(7)|PLANES(8)|RECOVERY(9)|FRAMES(10)|DEAL_TICK(11)|AOI_DOWNLINK(12)|PERSIST(13)|SWITCH(14)|DIAG(15)|SLEEP(16)|INBOUND_PROCESS(17)` = **`0x3FFFF`**。
   W1 若用 `PhaseSet::ALL.0`（常量）⇒ 自适配；若硬编码 `0x1FFFF` ⇒ M1b 须改 `0x3FFFF`（列为 M1b 门槛核查）。

### D. `proc_svc!` 位参数 + 误传失败形态
- PROCESS 支传 `INBOUND_PROCESS`、LOCAL 支**不传**。
- **误传红**：PROCESS 支误写 `proc_svc!(INBOUND)`（alias=0x20002）⇒ `PROC_SVC_SEGMENTS` 多记 bit1
  ≠ `PROCESS_ONLY`(0x2610D，只 bit17) ⇒ `proc_svc_segments_equal_process_only` **红**（"多一位=掩码虚位"）。
  LOCAL 支误加 `proc_svc!` ⇒ 同样多 bit1 ⇒ 同牙红。

### E. 风险点：`has(INBOUND)` 变"两位任一"
- `has(PhaseSet::INBOUND)` = `(self.0 & 0x20002)!=0` ⇒ **bit1 **或** bit17 任一即真**。全仓**仅 1 处** `has(PhaseSet::INBOUND)`
  （lib.rs:34987 段守卫）——拆后该守卫"进段"（两支共用 drain），段内再按 bit 分 LOCAL/PROCESS，语义正确。
- **"只开 PROCESS 不开 LOCAL"的错觉组合**（`PhaseSet(INBOUND_PROCESS)` 单独 ⇒ has 真但只跑 PROCESS）：**今天结构上不存在**——
  全仓 `PhaseSet(...)` 构造点仅 3 处：`M0_MIN`（无 INBOUND）、`M1A_PROD`（无 INBOUND）、测试 `PhaseSet(WORLD_TAIL)`（无 INBOUND）；
  其余全经 `PhaseSet::ALL`（两位全开）或将来 `INBOUND_LOCAL`（区 k，只 LOCAL）。**无任何 PROCESS-only 集合**（已 grep 证）。

- **控制邮箱是 M1b 新增**（现无）；**置位/解除落新码、形状锚既有 form(d)**。放行的 LOCAL 命令经与正常命令**同一执行路径**（不另造分派），只在"是否此刻执行"上延迟。

## 5.3 【修订】§5.2 放行执行点：**决策/执行分离**（opc-27 2026-11-23 指正）

§5.2 原"放行在区 k **tick 顶**、经同一 LOCAL 路径派发"**有缺陷**：那是在 `INBOUND_LOCAL` 段**之外**执行命令 ⇒
① `RAN_SEGMENTS` 不记 `INBOUND_LOCAL`（命令"看起来"没经入站段）；② `host_prof` 的 `HostInbound` 计时不含它们（段成本口径破）；
③ 将来"本 tick 跑了 `INBOUND_LOCAL`"的推断会漏这批。**改为**：

- **tick 顶只做决策、不执行**：`control_in_flight == None` 或超时（`ticks - t0 > 2`）⇒ 把该玩家
  `deferred_local` **整体 `mem::take` 进 `pending_local`**（清空 `deferred_local`）；超时/溢出另清标记 + WRN + 计数。
- **执行留在 `INBOUND_LOCAL` 段内**：该段排水时**先按序消费 `pending_local`**（它们比本 tick rx 新到命令更早）→
  再处理 rx 新命令 ⇒ 顺序保持"旧的先"，且**段记账（`RAN_SEGMENTS |= INBOUND_LOCAL`）与 `host_prof` `HostInbound` 计时不变**。
- **字段**：加 `pending_local: VecDeque<PendingLocalCmd>`（释放就绪缓冲；与 `deferred_local` 同 per-player；tick 顶 `mem::take`、`INBOUND_LOCAL` 段先消费）。
- **用例**：被延后的命令执行时，`RAN_SEGMENTS` **必含 `INBOUND_LOCAL` 位**（§1.2 两位方案）；**负例**：把放行挪回 tick 顶（段外执行）⇒ 该断言红。
- **其余点位不变**（`control_in_flight` 字段、上限 8、溢出策略、置位 `handle_zone_command` PROCESS 支、解除区 0 持区 k 锁、超时用 `HostLoop.ticks`）。
