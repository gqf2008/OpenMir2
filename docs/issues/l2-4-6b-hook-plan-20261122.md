# L2-4 段 6b 挂点与对拍计划：`AoIFrameLedger` 接线 + N=2 进程内对拍

## 0. Leader 裁决（6b 的唯一口径，2026-11-22）

1. **③-1 选 (c)+(a)：v1 生产不启 ledger**（`zone_host` 下传 `None`），账本只在 **N=2 进程内
   用例**里开；`owner_zone` 在 v1 定义为「**持有该 World 的区**」（按坐标归属的检查只在 N=2
   用例里成立——那里每个 `World` 只装自己的 rect）。
   理由：v1 只有一个 `World` 模拟全部地图，`RegionLayout::require_owned` 目前**零生产调用点**，
   「区界移动拒绝」与 MonGen 按区过滤都没做 ⇒ 此刻若按坐标判 owner，任何落在非 0 区 rect 的
   实体都会被自己判 `NotOwner`。
   **提交信息与卡必须写死这句**：「ledger 生产启用 = L2-5 前置（需先有 per-zone session/host
   切片 + 边界拒绝 + MonGen 过滤）」。
2. **③-2 tick 号单源**：tick 头存一个 `tick_no`，账本/快照/屏障**全用它**；不得在账本里用
   `ticks - 1` 之类的偏移——偏移靠记忆修最容易再错。
3. **③-3 `kind` = 每帧头 ident**（12B 头的 ident 字段，u16 LE）；一次 appearance 是多帧
   （`turn_pair` 两帧 / 骑乘 +1 / 死亡 1 帧），用常量作 kind 会让同一 appearance 的两帧被账本
   自判 `Duplicate`。`seq` 每账本单调，排序键 `(src, seq)`。
4. **② N=2 对拍范围收窄**：只做「每区本地帧 + 账本不变式（`dup=0` / `sent==recv` / `never=0`）
   + 可见集合（halo 合成）对拍」；**帧流等价（跨区出现/消失帧）留给 L2-5**（需要 halo 合成帧、
   `disappear` 顺序、`SearchTime` 扫描门一起对齐）。提交信息写明此边界。
5. **① 挂点**：新参插在 `walk_seen` **之前**（避开源码牙钉死的「末尾两实参 + `);`」）；
   **不在** `drain_aoi_downlink` 增加第二处记账点（`bodies` 循环已覆盖死亡/骑乘）。

## 1. 挂点清单

### 1.1 函数与唯一生产发射点

- `drain_aoi_downlink`：逐观察者把本 tick 的 `Show` 目标编码成出现帧，唯一发射点是
  `for body in bodies { tx.send(SimToGate::SendFrame { socket, body }) }` 循环。
- 记账字段（在该循环内逐 body）：
  - `owner` = 被看见实体的 `target.id`，`owner_map` = `target.map_id`，`owner_x`/`owner_y` =
    `target.x`/`target.y`（产生方 = 实体所属区）；
  - `recipient` = `(entry.gate_idx, entry.socket)`（`OnlineEntry` 的帧路由键）；
  - `kind` = 该 body 帧头的 ident（u16 LE，口径同 `CommandMessage::from_bytes` 的字段布局）。
- 死亡支（单帧）与骑乘追加帧都走同一个 `bodies` 循环 ⇒ 无需第二个记账点。

### 1.2 参数穿透

| 函数 | 现状 | 变化 | 调用点 |
| --- | --- | --- | --- |
| `drain_aoi_downlink` | 6 参 | +`Option<&mut AoIFrameLedger<'_>>` | 生产 1（`drain_run_downlinks_with_magic` 内）+ lib 测试 15 |
| `drain_run_downlinks_with_magic` | 15 参（已带 `too_many_arguments` allow） | + 第 16 参 | 生产 1（`sim_loop` 的 HostAoiDownlink 段）+ lib 测试 2 + bench 1（`host_aoi_bench`） |

另有源码扫描牙（见 1.3）钉位置与实参。

### 1.3 源码牙约束（写代码前必须满足）

- **生产调用的末尾形状被钉死**：有一条接线牙断言源码包含「`Some(&mut login_tails),` +
  `Some(&mut monster_walk_seen),` + `);`」三行连续文本 ⇒ 新参只能插在 `walk_seen` 之前
  （建议紧跟 `prof`）。
- AOI 调用锚只钉「生产赋值行的绑定名」与「实参里必须出现的 `world`/`displays`/`online`/
  `gates`/`login_tails.as_deref()`」⇒ 加参本身安全，但**不得**丢掉这些实参。
- `disappear` 先于 `downlink`、且二者在帧面函数体内**各恰一处**的顺序牙不受新增记账影响
  （只要不复制/移动调用）。

### 1.4 生命周期（提案）

- `CrossZoneOutbox::new(zone_count)` 与区 0 同线程；HostAoiDownlink 段前 `begin_tick(tick_no)`、
  段后 `seal_tick()` + `TickLedger::check()`；`Err` ⇒ abort 整机（同「任一片失败整机 Abort」）。
- **账本 tick 与屏障/快照 tick 同源**（裁决 2）：在 tick 头取一次 `tick_no`，全 tick 复用。
- 只记**出现帧**；`drain_aoi_disappear` / `drain_aoi_events` / NPC 转身等其它帧源不记账
  （段 5 的 `AoIFrameLedger` 文档已写 v1 边界）。
- **生产接线在 6b 仍传 `None`**（裁决 1）；`Some(..)` 只出现在 N=2 进程内用例。

## 2. N=2 进程内对拍草案（按裁决 4 收窄）

- **夹具**：沿用 `tests/l2_two_zone.rs` 的 20×10 几何（RECT_A = x0..9，RECT_B = x10..19）：
  玩家观察者 O 在 A、`E_A` 在 A、`E_B` 在 B、移动者 `M_B` 在 B；第 K tick `M_B` 走到 A 的边界带内。
  bots = 固定 tick 位置/朝向表；纯进程内，**不穿 `sim_loop`**。
- **结构**：2 个 `World`（同一张图、各自 `with_maps`）+ `HaloExchange` / `TickBarriers` /
  `CrossZoneOutbox` / `AoIFrameLedger`；每区调用 `run_zone_tick`（或等价的
  `tick_phase1 → after_phase1 → tick_phase2 → after_phase2` 切面），AOI 帧经
  `drain_run_downlinks_with_magic` + ledger 落到 fake `gates`（按线收帧）。
- **基线**：同一实体集合放进单 `World`、单线程 `world.tick()` + 同一 drains；**基线跑两遍
  逐字节相同**作为确定性前置（拆区同样跑两遍）。
- **比较口径**：① 可见集合（halo 合成后）== 基线；② `dup=0 / sent==recv / never=0`（账本
  `check()` 自动判）；③ 每区本地帧集合在本区收件人上 == 其基线子集；④ 探针开时记
  `region_barrier_us` p50/p99（只记录、不设门）。
- **不在本段**：跨区出现/消失帧流与基线逐字节等价（留 L2-5）；真栈/登录归属（另开卡）。

## 3. 三个易错点（按裁决收口）

1. **`owner_zone` 语义**：v1 按裁决 1 定义为「持有该 World 的区」，坐标归属检查只在 N=2
   用例成立。若在 6b 里让生产侧按坐标判 owner，会与「单 World 持有全部实体」的现实冲突。
2. **tick 号偏移**：`sim_loop` 的 tick 计数器在 HostAoiDownlink **之前**已自增 ⇒ 必须按裁决 2
   在 tick 头取单源 `tick_no`，不要在账本里做减法。
3. **`kind` 与「同 owner 同 recipient 多帧」**：按裁决 3 逐帧取 ident；`seq` 单调；排序
   `(src, seq)`。
