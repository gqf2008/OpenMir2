## 0. 结论摘要（先给判决）

1. **入站并行是硬前提**：2000 档实测入站 **287 enq/s vs 237 drained/s**、`budget_hit 100%`、
   `wall 50.1ms` ⇒ 单队列已饱和（净增 ~50/s），p99 201ms 的红主要是**入站/总工作量**，不是
   单事件重（单事件 p95 仅 2.48ms）。⇒ 拆区必须**每区自己的入站队列 + 独立排水线程**，
   否则把 World 拆成 N 个但共用一条队列，墙不会消失。
2. **N 的硬下限由入站定**：每玩家入站 ≈ `287/1973 = 0.1455 事件/s`；10k ⇒ ≈ **1455/s**；
   单线程排水实测 ≈ 237/s ⇒ `N ≥ ⌈1455/237⌉ = 7`；留 20% 余量 ⇒ **N ≥ 8**；
   与 v1 的 tick 推算取并集 ⇒ **建议 N=10，最低 8**。每区玩家上限 **≤1000**、实体 ≤4000
   （v1 Q6）。**tick 侧用区间口径**（986 档 `refmsg_targets` 两轮 16k–26k/tick）：每区 ≤1000
   人时工作≈986 点（p99 47ms），只约束 N≥3；**入站的 N≥8 是主导约束**，N=10 是余量 + 屏障口径。
3. **为什么不是地图组级归属**：P0-3 实测（`shard-map-group-closure`）表明封闭划分只能沿
   弱连通分量边界成立，最大分量 **159 图不可再拆**，且**无在线人流数据** ⇒ 按地图组无法给热点
   分担负载（主大陆仍落一片）。⇒ 本计划转向 L2（单图切区）+ 每区入站并行。
4. **可行性判决（不顺着写）**：
   - **空间分散的 10k**：有机会（N=10，每区 ≤1000 人）。**986 档实测**
     `refmsg_targets = **16k–26k/tick**`（同档两轮差 1.6×，场景相关，按区间用）⇒ 每玩家
     16–26 目标；2000 档 8.8 万/tick（≈45/人）⇒ **每玩家扇出随密度上升**（2× 人 → ~2–3×
     每玩家目标）。因此 N=10 成立的前提是**每区密度被 1000 人上限钉住**，使每区扇出落回
     986 档的 16k–26k 区间；若 10k 仍集中在少数区，扇出按密度继续上升，`tick p99` 会重现
     2000 档的饱和。
   - **空间聚集的 10k（攻城/主城）**：**按现有 AOI/扇出设计物理不可行**。反例：2000 档
     实测 `refmsg_targets = 8.8 万/tick`（≈44/人）；10k 聚集在单区 ⇒ ≈**44 万目标/tick**
     （5×），若成本随目标数线性，等价于把已红的 201ms 再乘 5 ⇒ **~1s/tick**，拆区救不了
     （热点永远在**一个**区里）。必须配**每区/每子格人数上限或 AOI 降频**（会改可见性/帧面，
     需登记 D-*），否则「单图 1 万」= 「单区 1 万」。
5. **方法警告**：986 档 p99 47ms 与 2000 档 p50 31ms 来自**不同地图分布**，不能横向比。
   所有 N/上限结论必须绑定同一地图分布与同一 `view_range`/`SendRefMsgRange`。

## 2. `region_loop` 接口边界

### 2.1 一个区是什么

- **一个区 = 一个 `World` + 一条（普通, 优先）入站队列 + 一个固定 owner 线程**；
  线程命名 `m2-zone-<map_id>-<rx>_<ry>`；`TickOwnerThread` / `World.owner_thread` 逐 World
  不变（不迁移、不共享 `&mut World`）。
- 区配置（静态）：`(map_id, rect[x0..x1, y0..y1], halo = view_range 全局上界)`；布局文件在启动
  时校验：同图区互不重叠、并集 = 全图、每区非空、边界不落在唯一高流量走廊（v1 Q1）。
- 归属原语从「地图级 bool」升级为**区级**：`is_region_owned(map_id, x, y)`；所有换图/落格/
  刷怪入口的 fail-closed 从 `MapNotInShard` 升级为 `OutsideOwnedRegion`（可区分错误）。

### 2.2 区与区**什么时候必须同步**（本文件的核心增补）

v1 只写了「halo 镜像 + 单一发射者」，没写相位。按 A 口径 §3.1（**同一时刻同屏可见集合**），
**上一 tick 的 halo 不够**（会在边界抖动一拍）。必须显式定义**两阶段 tick + 一道屏障**：

```text
阶段 1（并行）：每区推进本区实体（移动/AI/buff/命中判定准备）；
屏障：      交换**本 tick** 的边界增量（位置/外形/HP 等出帧字段）+ 跨区命中意图；
阶段 2（并行）：每区做 AOI/出帧（本区实体 + 邻区 halo 镜像）与跨区消息合并排序。
```

- **必须有屏障的三件事**：① 边界观察者的可见集合（halo 必须是本 tick 的）；② 跨区命中
  （目标区权威，见 2.3）；③ 跨区移动（handoff 在屏障处搬，v1 Q4）。
- **不共享**：RNG（每区私有）、`SlotTable`、会话表、展示表；跨区只传**消息**与**只读快照**。
- **代价（必须承认）**：屏障让 `每 tick 墙钟 ≥ 最慢区`（Amdahl）。⇒ 区之间负载必须均衡，
  否则 N 的收益被最慢区吃掉；这也是「每区上限」比「N 越大越好」更重要的原因。

### 2.3 跨区交互的边界（沿用 v1 Q3，补一处）

- 远程命中邻区实体：攻击意图发**目标所属区**，由目标区算伤害/HP/RNG 并出帧（1 tick 延迟，
  v1 Q3/Q5）。⇒ **跨区战斗不是同 tick 语义**；建议 v1 只允许「边界低流量/非战斗区」跨区，
  或把战斗热区整体放在一个区内，跨区命中登记 D-*。
- 掉落：落点区拥有；聊天/组队/行会/城堡：协调器（P2-4），不进区。
- 同一收件人帧序：跨区帧带 `(tick, region_id, seq)`，收件人侧有序合并（v1 Q3）。

## 3. 与现有 `sim_loop` / 多 World 的关系（哪些直接复用）

| 现有件（P2-3b） | L2 用法 |
| --- | --- |
| `m2-sim-<id>` 线程 + `ShutdownSignal` | **直接复用**：改成 `m2-zone-*`，关服旗标同构 |
| `shard_router`（目录 + 单播/广播 + 兜底） | 复用骨架；目录键从 `chr→shard` 换成 `chr→zone`；`RegisterGate` 广播照旧 |

## 4. 分步落地（每步独立可验；第一步必须恒等）

1. **Step L2-1：区模型 + 每区队列，N=1 恒等**。引入 `RegionLayout`（缺省 = 整图单区）与
   `zone_loop` 外壳：每区一条队列，但 N=1 时事件路径与现有 `sim_loop`**逐字节相同**（不建额外
   线程、不加日志）。验证：五门 + `-Mode Both` 150/50 + N=1 stdout 归一化比对（方法沿用
   P2-3b Step 4：剥时间戳 + 明确剔除墙钟噪声类）。
2. **Step L2-2：区级归属 + 入口 fail-closed**。`owned_regions`（map + rect）替代地图级
   `owned_maps`；换图/落格/刷怪/拾取入口全部 `OutsideOwnedRegion`；tick 尾不变式升级为
   「已落格实体必须在本区 rect」。N=1（全区）恒等。
3. **Step L2-3：halo + 两阶段屏障（单图双区）**。两个区共享同一张图的只读基础层（见 R2），
   交换本 tick 边界增量；构造级断言：边界可见集合逐 tick 与 1 区相同、`dup=0`、`never=0`。
   仍未开生产流量（合成场景）。
4. **Step L2-4：多区生产运行 + 入站 demux + 区界 handoff**。N 个 `m2-zone-*` 线程；
   登录/会话按 `(map, x, y)` 钉区；区界移动走 v1 Q4 的 tick 边界 handoff；跨区命中消息；
   每区指标（`zone_tick_ms`/`inbound_enq`/`inbound_drain`/`budget_hit`/`xreg_*`/`handoff_refused`）。
5. **Step L2-5：容量证据（分散 vs 聚集）**。同地图分布下 986/2000/目标档的每区 p99/入站表；
   证明「切区后 2000 档那种饱和不再出现」（见 §5）；聚集场景按上限退化，出结论不回避。

## 5. 验收断言（含「如何证明不再饱和」）

1. **N=1 逐字节**：五门 + `-Mode Both` 150/50 + 归一化 stdout（方法同 P2-3b Step 4；明确
   覆盖边界与剔除类）。
2. **A 口径三面**：同屏可见集合（逐 tick，边界场景）、帧内容/数值、同收件人帧序（合并键）。
3. **无重复/无丢失**：`xreg_frame_sent == xreg_frame_recv`（按事件 key）、`dup=0`、`never=0`。
4. **入站不再饱和（可测指标）**：
   - 每区 `inbound_drain ≥ inbound_enq × 1.25`（留 25% 余量），且 `budget_hit < 5%`；
   - 每区 `drain_wall_ms p99 < 50ms`（预算不被打满）；
   - 每区 `zone_tick_ms p99 ≤ 200ms`，且**最慢区**满足（屏障口径）；
   - 同收件人跨区偏差 ≤ 1 tick（200ms）。
   红检：把每区队列合并成一条（模拟不拆队列）⇒ 2000 档应重现 `budget_hit 100%`/p99 红 ⇒
   说明该判据真的在测入站并行，而不是只测了 World 拆分。
5. **可重放**：同 N/种子/输入两次运行帧字节相同（L1 多线程若开启，另过重放确定性门）。

## 6. 风险与不可行之处（含反例与数字）

- **R1 扇出是 O(密度) 而不是 O(区)**：扇出目标数取决于观察者半径内的实体数；若 10k 均匀
  铺满同一张图，**每玩家扇出随全局密度上升**，拆区只摊薄「处理」不摊薄「每个观察者的目标
  数」。⇒ 必须先测 986 档的 `refmsg_targets` 与地图面积；若每玩家扇出随密度线性上升，
  10k 分散档的每区扇出也不是 44k，而可能高数倍 ⇒ **v1 Q6 的线性推算作废**，以实测为准。
- **R2 同图多区共享地图基础层**：`MapGrid` 现在由每个 `World` 独占且可写（城门/墙）。L2 需要
  「只读基础层（`Arc`）+ 每区可变覆盖层（城门）」，否则 N 份整图副本内存不可接受（1000×1000
  × N）。城门状态必须全图一致 ⇒ 需要协调器权威或跨区同步；**v1 先排除含城堡的地图**。
- **R3 DB/全局服务**：现有多 World 的 gate 表把 DB/IDS/guild/castle 限在宿主。L2 每区都要
  取档/存档；v1 若不先做 P2-4 协调器，只能「每区自带 DbWiring」——连接数 ×N、存档汇总需
  聚合；`item_number`/IDS 在线数仍是全局量。⇒ L2 与 P2-4 有强耦合，建议 L2-4 前先定协调器
  最小面（DB 队列 + item_number + 在线索引）。
- **R4 屏障的 Amdahl 上限**：每 tick 墙钟 ≥ 最慢区；区负载不均时 N 的收益被吃掉。⇒ 必须
  每区上限 + 布局按密度切，而不是按面积均分。
- **R5 聚集 10k 不可行（反例）**：见 §0.3；拆区对「同区热点」零收益，必须密度上限/AOI 降频
  （改可见性语义，需 Owner 口径）。
- **R6 区界 handoff 频率**：区界是**格子矩形**，玩家过界远多于跨图；每过一次一拍不可见
  （v1 Q4）在高流量边界会非常显眼。⇒ 布局必须把边界放在低流量/不可走格（v1 Q1），并把
  `cross_region_moves/s` 作为布局合格判据；否则需要「无缝边界」研究（超出本计划）。
