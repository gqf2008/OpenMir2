## 0. 结论（可直接用于排期）

1. **现状不能安全开启会话归属**：今天只有**地图组**归属，而「地图组对玩家移动是否封闭」
   （组内连通、跨组无必经边）**没有测量**（P0-3 未做）。未证明封闭前，任何 2 片划分都会在
   组边界产生「看不见的墙」——跨片连接点在**注册阶段**就被拒绝（P2-2）。
2. **归属单位正在被新设计下探**：`docs/map-zone-split-design-20261122.md`（Owner 2026-11-21
   授权拆图）把原子从「整张地图」下探到「区（`map_id` + 矩形）」，并明确 **handoff 是 P0 依赖**。
   ⇒ 按**区**归属必须先有 handoff；按**地图组**归属不需要 handoff，但需要 P0-3 的封闭性证明。
3. **建议顺序**：① 先做 P0-3（连通分量 + 每图密度 + 热点，只读分析）；② 若存在「封闭且
   负载可接受」的地图组 ⇒ 做地图级归属（本设计）；③ 若不存在（207 图大概率是一个大连通
   分量）⇒ **不要做会话归属**，停在测量/容量优化，等 P2-5 handoff 与 L2 区划。
4. **若开启地图级归属，有两个硬前置**：u16 截断（非 0 片玩家第一次会出现，骑乘帧尾丢高
   16 位，见 u16 follow-up 卡）必须先闭环或在该片禁用骑乘；跨组换图必须继续 fail-closed，
   内容侧必须保证地图组封闭。

## 1. 现状事实（代码锚）

- **事件键不唯一**：`GateEvent::Opened/Command.index` 是**本网关连接的 `UserList` 槽位号**，
  `socket` 跨网关线会重复 ⇒ `(index, socket)` **不唯一**。而 `Closed.index` 是**网关线号
  `service_id`**（与 `OnlineEntry.gate_idx` 同源，G3/T-102）——同一枚举里两种语义并存。
- **登录事件已有唯一键**：`LoadDbInfo` 带 `gate_idx`（网关线号）/`socket_id`/
  `gate_socket_idx`。缺键的只是 pre-login 的 `Opened`/`Command`/`CertificationPending`。
- **目标片只能在读完角色记录后确定**：登录分支的 `world.enter_map_at(final_map_name, map_id)`
  在 DB 应答之后（角色记录含地图/坐标）。
- **归属与守卫已就绪**：`ShardLayout::shard_of_map` + `is_map_owned` + 所有换图/落格入口
  `MapNotInShard` fail-closed（P2-3a）；`sim_loop` 按 `local_shard` 判归属（P2-3b）。
- **路由目录**：`shard_router::ShardDirectory`（chr→片）在进/离世界维护；未知一律片 0。

## 2. Q1 路由唯一键：`(index, socket)` 不唯一，需引入 `line`

- 结论：**不能用** `(index, socket)` 做会话身份；用 `(service_id, socket)`——这正是现有
  `OnlineEntry.gate_idx + socket` 的**帧路由键**（`route_to_gate`）。
- 最小改法：给 `Opened` / `Command` / `CertificationPending` 增加 `line: u8`
  （`Closed` 现在把线号塞在 `index` 里，需加字段或改名消除歧义；`LoadDbInfo` 无需改）。
- 唯一性论证：同一网关线内 socket 在会话存活期唯一；跨线由 line 区分；槽位复用/重连由
  `LoadDbInfo.session_id` / `gate_socket_idx` 与 chr_name 兜底。
- 判定：**可做**，纯事件结构改动，不动 world 语义。

## 3. Q2 归属策略：按「角色记录里的地图（L2 后为区）」钉片，不用 hash

- **规则（确定性、可复现）**：读完角色记录后
  `target = layout.shard_of_map(rec.map_id)`（L2 后为 `region_of(rec.map_id, rec.x, rec.y)`）。
  同一角色 + 同一布局 ⇒ 永远是同一片；不依赖运行期负载、不依赖哈希。
- **为什么不是 `hash(account) % N`**：
  1. 角色的地图是持久事实，hash 可能把它放到**不拥有该图**的片 ⇒ 进世界必然
     `MapNotInShard`（硬失败）；
  2. hash 无视热点（城堡/主城/新手村仍会集中到一个片）；
  3. 「一张图只归一个 World」（L2 后：一个区只归一个 World）是 AOI 一致性的前提；按玩家
     哈希会把同图玩家拆散到多个 World。
- **负载均衡**：靠**静态地图组**（P0-3 产出）+ 运行期观测告警；不做动态迁移（无 handoff）。
- **换图**：
  - 地图级：组内正常；跨组连接点未注册 ⇒ 走到边界是普通格（fail-closed，已实现）；脚本/
    传送指向外组 ⇒ 被 guard 拒绝。
  - L2 区级：跨区即 handoff（P2-5），不在本设计范围。
- **登录落点流程（两阶段，新增「进世界前移交」）**：
  1. 片 0 作为**登录片**：认证 + DB 读角色（现有链）；
  2. 计算 `target`；`target == 0` ⇒ 就地进世界（现状）；
  3. `target != 0` ⇒ 把「角色记录 + `(line, socket)` + 登录输入」作为**新控制消息**交给
     target 片的 sim；target 执行 `open_session`/`enter_map` 并产出登录批次帧；源片**不建
     实体、不建会话**。
  - 这不是 handoff：此刻还没有世界实体/AOI/战斗状态，只是记录搬迁 ⇒ 比 P2-5 小一个数量级；
    但仍需**有界跨片通道 + 同会话帧序保证**（登录批次帧只能由 target 发）。
  - 一个会话的帧序：gate 的 per-session 队列保序即可；源片在移交后不得再发该会话任何世界帧。

## 4. Q3 重连：不需要目录持久化，重算即可

- 归属是 `(角色存档地图, 静态布局)` 的**纯函数** ⇒ 断线重连同片；进程重启后同样成立。
- 内存目录（`ShardDirectory`）只是热路径提示，断开即清，丢失可重建。
- 唯一会改变归属的是**布局变更**（运维改 `MIR2_SHARD_MAP_GROUPS` 或 L2 区划）：角色登录到
  新片，坐标仍在其地图上；布局校验保证 100% 覆盖，不存在「无片拥有」。
- 同角色重复登录（顶号）：由既有 IDS/踢人链处理；目录以最后一次 `set` 为准（覆盖）。

## 5. Q4 失败模式：沿用「整机 Abort」，不做排队/换片重试

- 现有 `WorldStartGate`：任一片装载失败 ⇒ 共享闸 Aborted ⇒ 整机拒连（P2-3b 文档 §6.2-8 已
  声明为**设计意图**，不是副作用）。
- target 片仍在 Booting：登录按网关准入的既有**有界等待**（`admitted_until`）；超时拒绝登录
  （明确 SysMsg），不投无界队列。
- **不得**在 target 不可用时把会话「改投」到别的片：那片不拥有角色的地图，进去也必然
  `MapNotInShard`，只会把错误推迟到更难诊断的位置。
- 登录片（片 0）不可用 = 整机不可用（认证与 DB 都在那里）。

## 6. Q5 与 handoff（P2-5）的边界：本设计**只改出生片**

不解决：
- 出生后的跨片移动（走路/传送/脚本）：无 handoff 一律 fail-closed；
- 跨片 AOI/战斗/聊天/组队/行会/城堡（协调器 P2-4）；
- L2 区级拆分的边界穿越（map-zone 设计明确 handoff 是 P0）；
- 运行期再平衡/迁移；
- **u16 截断**：本设计会让非 0 片第一次拥有玩家 ⇒ `SM_MOUNTRIDE` 尾字段截断从「不可达」
  变成「可达」。开启前必须解决（推荐 P2-4 全局分配器）或在该片禁用骑乘（临时）；
- 登录片 0 的 DB/认证仍是单点（分片不摊薄它）。

## 7. 决策建议（能直接决定要不要做）

- **先做 P0-3（只读）**：207 图的连通分量、每图在线/实体密度、城堡/主城/新手村热点、
  跨组边数。
- 判据：存在 ≥2 个「封闭（跨组可走边 = 0，或只有可拒绝的传送边）且负载可接受」的组
  ⇒ 地图级归属可做（本设计 + 两个硬前置）；否则**停在测量与容量优化**，等 handoff/L2。
- 不做的代价：N 片仍只有 1 片有会话（P2-3b 文档 §6.2-1），多 World 与每区入站并行在真实
  负载下没有并行度。
- 做的代价：一次事件结构改动（line）+ 登录两阶段移交 + u16 前置 + 内容侧「地图组封闭」约束。
