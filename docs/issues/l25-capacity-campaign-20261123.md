## 1. 201 归因：三臂交叉表（2k、420s、满员后稳态）

| 臂 | 稳态起点 | p50/p90/p99 (ms) | 稳态 work (ms/tick) | 每线 max_depth（上限 4096） | overflow / degrade | 线条 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 线 7200 | in_world=2000 @256s | **201 / 201 / 201** | 80.12 | 3,643 | 0 / 0 | 1 |
| 2 线 7200,7201（**旧二进制**） | in_world=2000 | **63 / 109 / 156** | 122.16 | 3,976 / 2,147 | 0 / 0 | 2 |
| 3 线 7200,7201,7202 | in_world=2000 @276s | **78 / 125 / 188** | 113.24 | 436 / 422 / 408 | 0 / 0 | 3 |

**结论（三臂交叉，非单一推断）**：201ms 桶来自**单条网关线的发送/排队延迟**——同负载加到 2/3 线即消除 201 桶（p50 63/78 均 <100），而这三种情况下服务端 tick work 都远小于 200ms（80–122ms）。201 不是服务端 tick、不是邮箱、不是诊断尖峰（见 §3 HostDiag）。
**但 p99 未进 <100**（2 线 156、3 线 188），且 3 线阶段每线 max_depth 仅 408–436、overflow/degrade 全 0 ⇒ **残余延迟不是队列积压**，与闭环/端到端 ack 路径相关。
2 线臂是旧二进制（`ec5b7b18`），不能与 3 线臂做逐项归因；只作"消 201 桶"的交叉证据。

## 2. 闭环口径与"最接近未抑制"的读数

- 假人动作探针是闭环：`CM_TURN` 回执到达后才发下一步；单线高延迟 ⇒ 需求被抑制 ⇒ 单线臂的 work（80.12）与 4k 单线臂 work（169.47）都是**低估**。
- **3 线臂是迄今最接近"需求不被抑制"的读数**：延迟降下来、三线各承载约 1/3 尝试（97.80M / 95.24M / 97.27M），稳态 work 113.24。
- 合成负载实验（`-ActionProbeMs 500`，**非标准口径、不进验收数字**）只用于判"需求侧 vs 供给侧"：500ms 臂 flushed 中位由 844.2 升到 1,104.2（+30.8%，超过 930 阈值）⇒ 抬高需求确实抬高关键帧放行（需求侧是共同限制之一）；但 `probe_sent` 仅 +21.4%（非 2×），说明假人自身循环在 201ms 下也发不快。该实验同时出现 overflow 33,679→59,472，提高频率恶化拥塞、不改善时延。

## 3. 服务端成本：1k / 2k(3 线) / 4k 的 work 与 p95/p99

逐 tick work 分位数取各臂窗口内的"逐 tick 分位数"行（跨窗口取中位）；HostDiag 为顶层 Host 段。

| 臂 | in_world | work 均值 | 逐 tick work p50 / p95 / p99 | 单窗 max 的最大值 | HostDiag | 端到端 p99 |
| --- | --- | ---: | --- | ---: | ---: | ---: |
| 1k（120s） | 1000/1000 | 42.32 | 29.8 / 39.8 / **41.8** | 61.2 | 0.000 | 94 |
| 2k + 3 线（420s 稳态 ≥276s） | 2000/2000 | 113.24 | 119.1 / 140.5 / **148.7** | 379.2 | 0.000 | 188 |
| 4k（420s，末 4 窗，in_world 3739） | 3739/4000 | 169.47 | 157.9 / 210.9 / **514.2** | 551.0 | 0.000 | 201 |

- **HostDiag 修复前后**：4k 旧臂（`ec5b7b18`）HostDiag = 7.30 ms/tick（占 work 4.3%）；HostDiag 计算闸后（`a16a7dbc`）1k/2k/2k-steady/3 线全部 **0.000**。诊断尖峰已移出被测路径。
- 2k 稳态的逐 tick work 峰值近似（1 线臂，需求自抑下测）：p50 中位 65.25、p95 中位 113.48、**p99 中位 123.69**（p90 137.81，max 474.00）、mean 中位 74.18；SLOW 逐 tick：中位 71.4 / p90 117.8 / p99 129.5 / max 474.0。稳态 1,053 个 SLOW tick 中只有 2 个 work ≥200ms（tick#1830 = 474.0、#1831 = 315.8）。⇒ **2k 真实成本近似 p99 124–130ms**（比均值 80.12 高），此为上界近似而不是 open-loop 真值。
- 4k 的 p99 work 已达 **514.2ms**（单窗最大 551.0），说明 4k 规模下 tick 已出现超 200ms 的 stall 型 tick（该臂 `world_ok=3739/4000`，见 §7）。

## 4. 入站 burst 结构（2k、1 线、稳态 tick≥1300，n=1,077）

- **42.1%（453/1,077）的 tick 打满 50ms 入站预算**（`inbound_wall_us`≥49ms）；`inbound_carry=1` 占 42.9%（462 tick），其余 tick wall≈1µs、carry=0。
- 打满 tick 不是均匀分布：形成 **12 段连续 burst**，最长 **63 个连续 tick**（另有 55 / 24 / 15 / 6 / 3 …），burst 之间是长空闲段（最大间隔 239 tick）。
- 非零 wall tick 的中位为 **50.1ms**（预算耗尽型）。
⇒ **入站需求是长块 bursty，预算在 burst 内是限制项**；容量口径必须把 burst 期的截断与稳态分开，不能把 burst 截断当作稳态成本。

## 5. 网关线数作为验收条件

- 依据：单线 flushed 中位 **767–844 帧/s**（本批稳态臂 767.0；早前单线长臂 844.2）；3 线各 **146–175 帧/s**（gate0 173.5 / gate1 146.0 / gate2 171.9）。
- 依据：同负载（2k）单线 max_depth 3,643、p50/p90/p99 全 201 桶；3 线每线 max_depth 408–436、overflow/degrade 0、p99 188。
- **表述（进验收条件）**："**每 N 个在线玩家至少一条 game-gate 线**；N 待定。" 现有数据只支持 **N < 2000/线**（2k 单线已饱和，2k 三线未饱和）；N 的最终值需按 1 万目标与单线稳态放行数（767–844 帧/s）另行标定，**本报告不替 N 取值**。

## 6. 对 1 万的推算（**推算，不是实测**）

- 2k（3 线，接近未抑制）work 113.24 → 4k（单线，in_world 3739）work 169.47，约 **1.50×**；若按同斜率外推 1 万 ≈ **280ms/tick 量级**（p99 更高），单线程 tick 在 200ms 周期内无法完成。
- 结论：**单 tick 线程不够，分区（多区/多进程）是必须的**；或者把每 tick 成本砍到 1/1.5–1/2。该结论建立在 §3 的 work 读数和 2k→4k 的 1.5× 斜率上，属推算。
- 4k 臂未满员（3739/4000）、1 线；4k 的 p99 work 514.2ms 提示 4k 已进入 stall 型 tick 区，外推只宜作量级判断。
