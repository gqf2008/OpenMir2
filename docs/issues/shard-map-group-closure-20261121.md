## 1. 数据源与格式

- **地图清单 + 出口都在** `E:\MirServer\Mir200\Envir\MapInfo.txt`（**GBK 编码**；UTF-8 读会乱码）。
- 两种行：
  - **地图声明**：`[名字|文件名 描述] FLAGS`（例：`[M100A|M100 演武长房] NORECONNECT(G002) NORANDOMMOVE …`）。
  - **出口（跨图传送点）**：`源图 x,y -> 目标图 x,y`
    （原文例：`M100A 29,81 -> M100B 287,282`）。
- **判定"图 A 出口到图 B"的字段 = 出口行的源图名与目标图名**（第一列与 `->` 后的列）。
- 解析口径（脚本）：行首匹配 `^(\S+)\s+\d+,\d+\s*->\s*(\S+)\s+\d+,\d+$` 即为出口边；`[` 开头为地图声明。
- `NORECONNECT(x)` 等 Flag **不是出口**（是断线/回城落点），未计入边。

## 3. 切分实验

### 3.1 候选 P1：「按弱连通分量并组」（推荐）

- **跨组边 = 0**（集合论上恒成立：分量之间本来就没有边）。
- 可实现的**独立封闭组上限 = 331 组**；要达到 N≈10–12 组，只需把若干小分量并入大分量组。
- 两片示例（最大分量 vs 其余）：`g0 = 159 图`、`g1 = 447 图`、**跨组边 0**。
- **组内玩家负载估算：无数据**（无在线人流/顶点负载数据；只能按图数近似，159 vs 447 明显不均）。
- 结论：**封闭性完全满足**；代价是**负载不均**——需要按负载再平衡，而再平衡只能在分量级别做（见 §4）。

### 3.2 候选 P2：按地图名前缀切（≤M / >M）

- **跨组边 = 11 条 / 591 条**（1.9%）。
- 前 20 条跨组边：
```
4 -> T218          D402 -> Q004        0 -> T339          1 -> T219
D717 -> R001       H007 -> T2061       H008 -> T3063      T3063 -> H008
1 -> T315          T1343 -> 0123A      11 -> T232
```
（共 11 条，上列为全部。）
- 负载：**无数据**。
- 结论：**不封闭**；11 条边就是 11 个"看不见的墙"或 11 处必须走跨片消息的通道。

### 3.3 载负未知的前提

"组内玩家负载"需要在线玩家按图分布（或至少历史热区统计）。本次输入里**没有**该类数据，
因此 §3.1/§3.2 都只能给**结构封闭性**，不能给"负载可接受"的判定。

## 4. 结论

1. **存在封闭划分**，条件是：**任一组的成员必须是若干完整弱连通分量的并集**。
2. 现实约束：最大分量 159 图**不可再拆**（拆了必产生跨组边）；因此若要求 N≥10 的均衡分组，
   只能把大量小分量（含 318 个孤立图）并进 10–12 组，**最大组仍会包含那 159 图的分量**。
3. **最小跨组边数 = 0**（按分量切）。最近似的"均衡但非分量"划分（如前缀）差 **11 条边**（P2）。
4. 若接受"换图请求拒绝 + 提示"（即允许少量不封闭）：前缀划分的 11 条边可作为候选；
   但要注意这 11 条里有明显单向/双向混杂（`H008 ↔ T3063` 成对），拒绝策略会让玩家在该处"卡住"，
   比"看不见的墙"更糟（玩家会反复重试）。

## 6. 未覆盖 / 风险（必须写进任何后续划分决策）

1. **MapInfo 出口不是全部换图路径**：脚本/事件/NPC 传送（`MAPMOVE`、`MapEvent.txt`、任务脚本、
   `NORECONNECT` 回城、GM 命令）都可能跨图。本卡只统计 `MapInfo.txt` 的出口行，
   **如果这些隐藏通道跨组，封闭性会破**。要彻底证明需要再扫 `Envir` 的脚本/事件表。
2. **口径差异**：606 个名字 vs opc 的 207 张图，需先确认注册表口径再定 N。
3. **负载无数据**：无法判定"负载可接受"。
