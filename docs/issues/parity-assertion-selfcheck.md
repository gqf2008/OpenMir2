# 对拍断言自查清单（一页）

> 更新于 2026-11-21（依据四批牙审计，新增判据 8）。
> 来源：2026-11-21 的两个反向案例——**"golden 有、断言没比"**（`docs/issues/magic-52-clientxy-explicit-case.md` §3b）
> 与 **"断言写了但永远为真"**（同卡 §3b 的死断言修正）。每个新增/修改对拍断言提交前逐条过。

## 八条判据

1. **它会在什么情况下红？**
   写出至少一个**产品侧变异**（不是改测试），实测一次红；把"变异点 → 哪条断言红 → left/right"写进卡。
   写不出变异 ⇒ 这条断言没有判别力，不能计入覆盖面。

2. **观测值从哪来：golden 记录的字段，还是夹具硬编码？**
   夹具里写死的输入（等级/HP/魔表/种子）**不是覆盖面，是死数据**——golden 改了输入，Rust 不会跟随。
   影响面范式见 `docs/issues/openmir2-warrskill-harness-input-hardcode.md`。
   **同一功能里，"名字最像结果"的字段可能不可见，而"看起来是中间量"的字段才是判据面**
   （实例：50 `SKILL_MABE`，`src/M2Server/Magic/MagicManager.cs:530-536`——`msd_power` +1/+3 全绿，
   `success_gate` 恒 false 全绿，真正承载 `TargetHp`/`SM_STRUCK` 的是**第一条 `RM_DELAYMAGIC` 的
   `power/3`**，+1 即双红）。验证方法是**在同一功能上试多个字段**，看哪个能红——**不是猜名字**。

3. **调用参数是否真的把被测对象传进去了？**
   例：`CM_SPELL` 的目标只在 `nParam3 = MakeLong(Param, Series)`（`src/GameSrv/Word/WorldServer.cs:783-790`）；
   传 0 ⇒ `target_actor_id=0` ⇒ 目标面观测为空、断言**恒真**。

4. **两侧都断了吗？**
   "Rust 没抽"不够，还要断 "golden 的 `Rng` 为空"；"Rust 没发 53"不够，要断目标血/MP 的实际值。
   只断一侧 ⇒ golden 未来变化时断言静默继续绿。

5. **状态快照类断言的失效条件写了吗？**
   依赖 `Debug`/序列化字符串的断言，一旦有人自定义输出就会**变盲**；注释里写明"届时改用显式计数（如 `draws()`）"。
   优先用显式计数器/返回码，其次状态比较，最后文本比较。

6. **"门绿"≠"这条断言跑过"。**
   静态 golden 比较器、`#[ignore]` 之外的普通 `#[test]` 不在 `-Mode Both` 的 Driver/Comparator 集合内；
   门只作回归。新测试"跑过"的证据只有它自己的 `N passed` 原文——交付时贴。

7. **升格笔的 `scope` 必须写清证据来源与牙**（`opc-19` 2026-11-21 定）：
   - 有行为牙 ⇒ 写"牙：<变异点> ⇒ <断言> 红（`left/right`）"；
   - 无牙 ⇒ **明写"无牙（理由）"**，不得留空；
   - 门不覆盖本叶 ⇒ 追加一句 **"门不覆盖本叶，证据来自 `<测试名>` N passed"**，
     其中 **N 必须写死具体数字**（如 "`warr_43_behavior_side_effects` **1** passed"）——
     只写测试名可以换，数字换了就得解释（范式：`src/M2Server/Player/PlayObject.Attack.cs:1253-1266` 的 43 显式 case）。
   反例：`MG-42`（`src/M2Server/Magic/MagicManager.cs:462-473` 的 `case SKILL_ANGEL`）升格时 scope 未声明无牙（见 `docs/issues/mg42-angel-behavior-teeth.md`）。

8. **"有牙"的最低门槛：MG 专属产品牙，不是 `tooth_*` 机制牙**（`opc-19` 2026-11-21，四批牙审计归纳）：
   - **两类牙要分开**：比较器 `magic_fireball_parity.rs` 里的 `tooth_*`（如 `tooth_rm_field_changed_red`、`tooth_poison_657_series_compared_red`）是**机制牙**——只证明 `verify()` 对字段/RNG/deliver 变化会红，**对所有条目不特异**；它**不等于**某条 MG 有"改坏该 MG 产品行为 ⇒ 该 MG 自己断言红"的**产品牙**。
   - **"有牙"的最低门槛（三条齐）**：① **MG 专属**的产品侧变异（改该 MG 的算法/分支，不是改测试）；② 红的 `left/right` 原文；③ 还原证明（文件 hash 相等 + 复跑绿）。
   - **"计划里写了刀" ≠ "刀跑过"**：反例 `MG-57`（`SKILL_ENERGYREPULSOR`）的四刀只存在于 `docs/issues/magic-push-batch-wiring-plan.md` §4 的**计划**里、从未实跑（其 oracle 锚仍是 `src/M2Server/Magic/MagicManager.cs:601-606` `MagPushArround`，冻结面未动）；`MG-65`（`Shape=2@MagGroupAmyounsul`）的四刀跑的是 48 主叶、**不覆盖 Shape=2 叶**。⇒ 审计必须落到"实跑记录"，不能因卡里出现"变异/刀"字样就记有牙。
   - **"绿"的两种含义**：golden **非退化**时的绿只是 **no-regression** 证据（错误实现也可能同样绿）；**只有配上 MG 专属产品牙**，绿才 = **算对**的证据。
   - **幅度三档**：从 **+1 起** → 不可见则**加大到可见** → 仍不红则记**"最小可观测幅度"**或**"该维度不进任何比较面"**；**不许**把"加大到夸张仍不绿"写成"无牙"糊过去。
   - **⑤b 判"不可观测"必须先算下界**：写"该维度不进任何比较面 / 构造不出对照"之前，**用公式推导出"至少多大幅度才可能翻转"**（本例：`draw+(L−1) > 200`，`draw` 最大 3 ⇒ 至少 `L+172`）。（`draw=3` 时 +169 即够；**"必翻"取最坏情形 ⇒ +172**）**算不出下界就不许写"不可观测"**——"我试到 +50 都不红"只是**数据**，不是结论；反过来，**如果下界远大于合理变异范围，那要写的也是"需要 N 级才可观测（本牙采用决定性变异）"，不是"无牙"**。（本例 `MG-23`（`SKILL_HOLYSHIELD`）oracle 锚：`src/M2Server/Magic/MagicManager.cs:318`）

## 三条常见形态（今天都出现过）

| 形态 | 症状 | 修法 |
| --- | --- | --- |
| 压根没写断言 | golden 有字段，比较器从不读 | 补断言并配牙（判据 1） |
| 断言恒真 | 参数传空/目标 id=0/比较对象同源 | 修输入传递或换观测面（判据 3） |
| 死数据当覆盖 | 夹具硬编码输入，golden 改了也不跟 | 从 golden 读输入（判据 2，改共享夹具需单独批） |

## 30 秒自查

- 删掉产品侧对应行为，这条断言会红吗？（判据 1）
- 把 golden 里这个字段改成别的值，测试会红吗？（判据 2/4）
- 调用参数里有没有"恒 0/恒空"的占位？（判据 3）
- 断言里有没有比较同一来源的两个值？（恒真信号）
- 这条测试在门的两集合里吗？（判据 6；不在就自带 `N passed` 证据）
- 升格 scope 写了"牙 / 无牙（理由）/ 门不覆盖+证据来源"三项吗？（判据 7）
- **这条 verified 的牙是 MG 专属产品牙，还是仅 `tooth_*` 机制牙？**（机制牙对所有条目不特异、不给这条背书；见判据 8）
