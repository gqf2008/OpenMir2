# 对拍断言自查清单（一页）

> 来源：2026-11-21 的两个反向案例——**"golden 有、断言没比"**（`docs/issues/magic-52-clientxy-explicit-case.md` §3b）
> 与 **"断言写了但永远为真"**（同卡 §3b 的死断言修正）。每个新增/修改对拍断言提交前逐条过。

## 七条判据

1. **它会在什么情况下红？**
   写出至少一个**产品侧变异**（不是改测试），实测一次红；把"变异点 → 哪条断言红 → left/right"写进卡。
   写不出变异 ⇒ 这条断言没有判别力，不能计入覆盖面。

2. **观测值从哪来：golden 记录的字段，还是夹具硬编码？**
   夹具里写死的输入（等级/HP/魔表/种子）**不是覆盖面，是死数据**——golden 改了输入，Rust 不会跟随。
   影响面范式见 `docs/issues/openmir2-warrskill-harness-input-hardcode.md`。

3. **调用参数是否真的把被测对象传进去了？**
   例：`CM_SPELL` 的目标只在 `nParam3 = MakeLong(Param, Series)`（`src/GameSrv/Word/WorldServer.cs:783-790`）；
   传 0 ⇒ `target_actor_id=0` ⇒ 目标面观测为空、断言**恒真**。

4. **两侧都断了吗？**
   "Rust 没抽"不够，还要断 "golden 的 `Rng` 为空"；"Rust 没发 53"不够，要断目标血/MP 的实际值。
   只断一侧 ⇒ golden 未来变化时断言静默继续绿。

5. **状态快照类断言的失效条件写了吗？**
   依赖 `Debug`/序列化字符串的断言，一旦有人自定义输出就会**变盲**；注释里写明"届时改用显式计数（如 `draws()`）"。
   优先用显式计数器/返回码，其次状态比较，最后文本比较。

6. **"门绿"≠"这条断言跑过"。**
   静态 golden 比较器、`#[ignore]` 之外的普通 `#[test]` 不在 `-Mode Both` 的 Driver/Comparator 集合内；
   门只作回归。新测试"跑过"的证据只有它自己的 `N passed` 原文——交付时贴。

7. **升格笔的 `scope` 必须写清证据来源与牙**（`opc-19` 2026-11-21 定）：
   - 有行为牙 ⇒ 写"牙：<变异点> ⇒ <断言> 红（`left/right`）"；
   - 无牙 ⇒ **明写"无牙（理由）"**，不得留空；
   - 门不覆盖本叶 ⇒ 追加一句 **"门不覆盖本叶，证据来自 `<测试名>` N passed"**，
     其中 **N 必须写死具体数字**（如 "`warr_43_behavior_side_effects` **1** passed"）——
     只写测试名可以换，数字换了就得解释（范式：`src/M2Server/Player/PlayObject.Attack.cs:1253-1266` 的 43 显式 case）。
   反例：`MG-42`（`src/M2Server/Magic/MagicManager.cs:462-473` 的 `case SKILL_ANGEL`）升格时 scope 未声明无牙（见 `docs/issues/mg42-angel-behavior-teeth.md`）。

## 三条常见形态（今天都出现过）

| 形态 | 症状 | 修法 |
| --- | --- | --- |
| 压根没写断言 | golden 有字段，比较器从不读 | 补断言并配牙（判据 1） |
| 断言恒真 | 参数传空/目标 id=0/比较对象同源 | 修输入传递或换观测面（判据 3） |
| 死数据当覆盖 | 夹具硬编码输入，golden 改了也不跟 | 从 golden 读输入（判据 2，改共享夹具需单独批） |

## 30 秒自查

- 删掉产品侧对应行为，这条断言会红吗？（判据 1）
- 把 golden 里这个字段改成别的值，测试会红吗？（判据 2/4）
- 调用参数里有没有"恒 0/恒空"的占位？（判据 3）
- 断言里有没有比较同一来源的两个值？（恒真信号）
- 这条测试在门的两集合里吗？（判据 6；不在就自带 `N passed` 证据）
- 升格 scope 写了"牙 / 无牙（理由）/ 门不覆盖+证据来源"三项吗？（判据 7）
