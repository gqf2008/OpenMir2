### 3.2 缺陷 A（本片修）：`bins/game-svr` 网关线号恒 0 ⇒ 进世界帧静默丢弃

首跑 game-svr 日志（`evidence/.../game-svr-entry-frames.log`）：

```
07:32:25.952 [INF] 进世界帧下发：socket=324 共 1 条（输入齐备的）
07:32:25.953 [WRN] 下发 SM_* 帧时 socket=324 的槽不存在，丢弃 14 字节
```

根因：三条 GameGate 连接在 `main.rs` 里都用 `let active_service_id: u8 = 0;` 注册到线号 0 ⇒
sim 的 `gates: HashMap<u8, tx>` 只剩**最后一条**连接；进世界帧按该用户的 `gate_idx` 路由时打到别的连接上，
那条连接的 `UserList` 里没有这个 socket ⇒ 丢弃。

oracle 口径（`src/M2Server/Net/TCP/TCPNetChannel.cs`）：线号由 `AllocGateSlot()` **按连接分配、复用最小空闲槽**，
且源码注释明确写了同一坑的后果——「世界下发的数据就打到已断开的旧槽位上——表现为客户端进世界黑屏」。

修法（`bins/game-svr/src/main.rs`）：新增 `GateSlots`（`alloc` 最小空闲、`free` 断线释放、上限 20），
accept 循环按连接分配，连接结束发 `GateEvent::UnregisterGate` 并释放槽位。
单测 `gate_slots_are_unique_per_connection_and_reusable`；红检：把 `alloc` 改回恒 `Some(0)`
⇒ 该用例 **FAILED**（第二个连接拿到 0 而非 1），还原后全绿。

修后同一场景（`07:48:50`）：`进世界帧下发 … 共 1 条` 之后出现 `进世界标记：socket=312`，**不再有「槽不存在」**。

### 3.3 缺陷 B（本片修）：`portclassify.ps1` 把配置参数误当 C# 入口（验收①假红）

首跑 `check_ports.ps1` 把 7000/7100/7200 判成 `csharp`——探针是 `$Exe + " " + $CommandLine`，
而 Rust 入口正常用现网 `E:\MirServer\LoginGate\config.conf` 等作参数 ⇒ 整条命令行里含 `E:\MirServer\`。

修法：C# 根只认**可执行体路径**（`$Exe`；取不到时才回落命令行首 token）。
`selftest.ps1` 补两条回归：`impl/Rust 入口带现网配置参数仍=rust`、`impl/C# 入口（Exe 在 MirServer）=csharp`；
红检：改回 `$probe -like "*E:\MirServer\*"` ⇒ 前者 **FAILED**（`expect=rust actual=csharp`），还原后 **33/33**。

### 4.1 「重复进世界」的 oracle 口径（owner 侧 gap ① 的结论）

Rust 侧 `crates/world/src/session.rs` 的 `enter_map` 在同一 `chr_name` 已 `InWorld` 时返回
`SessionError::AlreadyInWorld`（拒绝新会话、不动旧会话）。

C# oracle 不是这个语义（`src/GameSrv/Word/WorldServer.cs`）：取档循环里
`if (!IsFull() && !ProcessHumansIsLogined(chrName))` 才正常进世界；否则走 **else 分支**：

```csharp
else {
    KickOnlineUser(userOpenInfo.ChrName);            // :535 旧对象置 BoKickFlag=true
    ListOfGateIdx.Add(userOpenInfo.LoadUser.GateIdx); // :536-537 旧会话加入待清列表
    ListOfSocket.Add(userOpenInfo.LoadUser.SocketId);
}
```

`KickOnlineUser`（`:1052-1064`）对同名的已在线 `PlayObject` 置 `BoKickFlag = true`（tick 侧随后下发
`SM_OUTOFCONNECTION`/清槽）；即 **重复进世界 = 顶号踢旧会话，新会话照常进世界**，而不是拒绝新会话。
Rust 侧当前是「拒绝新会话、旧会话留着」——**方向相反**，且导致验收不能连着跑（必须重启 game-svr 清世界）。
判据建议：拿真夹具跑「同角色二次登录」：oracle 应观察到旧连接 `SM_OUTOFCONNECTION` + 新角色进图成功；
Rust 应同为。修点在 `crates/world`/`bins/game-svr`，属下一片（本片写集不含 `crates/world`）。

> 黑屏的因果口径（与 owner `b7f45d91` 一致）：`shots3` 那轮（角色 `aaa`）黑屏直接原因是
> **AlreadyInWorld 根本没进世界**；`shots4` 那轮（角色 `bbb`）确实进了世界，但洪峰只发 1 条 ⇒ 仍黑屏。
> 两个是独立缺口。

> 抓包落盘（owner 侧 gap ③）：本片成功的 `conn-0002` 实测有字节（c2s 110B / s2c 20B，`chunks.ndjson` 1185B），
> **代理是落了盘的**；`conn-0001` 的 s2c 0 字节是因为那一轮被 `AlreadyInWorld` 拒掉、服务端没下发。

④ 三路径 DB diff 未采：②未成立（进不了世界就做不了小退/掉线/服务关闭动作）。
