# Agent 开发团队（2026-10-24 组建，v2：worker→dev，比例 2:2:1）

## 组织（5 条车道）

| 角色 | principal | worktree | 职责 |
|---|---|---|---|
| **Leader** | `openmir2-orchestrator` | 主检出 | 接任务、拆卡、派工、**复审审查结果**、合并、清理分支 |
| 开发 1 | `openmir2-dev-1` | `.worktrees/dev-1` | 领卡实现、门禁、牙、patch |
| 开发 2 | `openmir2-dev-2` | `.worktrees/dev-2` | 同上（两 dev 只并行写集不重叠的卡） |
| 审查 1 | `openmir2-reviewer-20` | `.worktrees/reviewer-20` | 独立复核（钉 head、自跑门禁、作者牙重放 + 自造牙） |
| 审查 2 | `openmir2-reviewer-21` | `.worktrees/reviewer-21` | 同上；两份交付可并行复审 |
| 测试 | `openmir2-tester-1` | `.worktrees/tester-1` | 集成层：合入门禁复核、18 场景 sweep、环境完整性巡检、真机窗口批次执行（按需派工，不做常驻轮询） |

**比例 2:2:1 的依据**：审查通常比开发更慢（全量门禁 + oracle 重推 + 牙重放+自造牙），1:1 配平才不堵队列；
tester 是爆发式负载（窗口/合并批次），1 个按需即可。同时最多 4 条并行（≤ 历史并发上限），Leader 串行合并。

## 规则

1. **一 worktree = 一身份 = 一把 Ed25519 私钥**。worktree 一律由 Leader 建在 `.worktrees/<角色>/`（仓库内、.gitignore）。
   **绝不删除成员 worktree**（身份在 `.git/worktrees/<name>/walgit/`）。密钥备份：`E:/wt-backup-20261024/team-20261024/`。
2. **一卡一 owner**：卡片线程的签名 `status` 是唯一认领账本；Leader 建卡即钉 owner，防抢卡。
3. **审查与作者必须不同 principal**；两位 reviewer 互不复核同一张卡（除非前一轮 request_changes 的 delta 复审由原 reviewer 做）。
4. Leader 复审审查结论后才合并：approve ⇒ `merge --no-ff` + 完整门禁 + push + `merge_result`（L 卡 closed / R 卡 in-progress 待窗口）。
5. 日常 fetch/push 只对 `walgit`（主源）；GitHub `origin` 仅人工同步。
6. 每张卡必须有：goal / write_set / oracle 行号或证据来源 / acceptance（含牙）/ forbidden / tier；
   交付 = 先签 status → commit → push → `patch` → `needs-review`；不自行 merge、不自签 review。
7. 合并后清理卡片分支（本地+远端）；worktree 保留。
8. 分级：R = 触 RNG/时序/持久化/战斗数值 ⇒ 需真机窗口证据；L = 等价 + 抽样冒烟即可；判不准按 R。
9. 三角独立：开发（写）/ 审查（读 + 复核）/ 测试（集成 + 环境）互不代签。
10. **`merge_tree` 一律由脚本生成、不手算**：`python -I -B tools/hygiene/merge_tree_helper.py --base <base> --head <head> --json`；patch body 附输出（vs_base / vs_master 两个 tree oid+rc），评审按同一命令复算。故障期 remote-tracking 可能陈旧：工具会取后代并 WARN，也可显式 `--master master`。
11. **「先造失效状态，再跑判据」**（2026-10-26 夜，一晚 12 张 L 卡的主线）：审「修某个失效模式」的卡时，
    先**造出它要消灭的那个失效状态**，再跑判据本身。实例：`tool-selftest-registry-sync` 的 `牙12` 用并集
    discover ⇒ 仓库多一个未分类工具时门**自己先红**；两次被 approve 后又被实测推翻。
    ⇒ 门禁全绿**不等于**卡面验收达成：合并前逐条问「这一条刚才哪个命令证明了？」。
12. **接线要有牙**：「把 X 接进 Y」的卡，必须钉 **X 与 Y 之间那行接线**。当晚三例（`run()` 的 `inv_rc`
    接线、第 8 项 `append` 的位置、`Get-RcAggregate` 的优先级）都是「单项牙齐、组装没牙」。
    验法用**整行删除**与**位置移动**两种变异，都必须红。
13. **开窗冻结的是行为面**：`tools/conformance/card_window.py`、`tools/client/mir_flow.ps1` 在窗口期禁改；
    docs-only 提交允许，但**必须立刻** `pwsh -File tools/window/rebuild-server.ps1 -SyncStartRust`
    （cargo 复用，0.25s）再跑 `bash tools/window/run_batch.sh --dry-run` 确认 `rc=0`
    —— `binary_stamp` 是严格 head 相等，一笔文档提交就会打漂。
14. **walgit 故障期的判据**（2026-10-26 实测两次抖动）：**`ls-remote` / UI 200 不算「通道好了」**——
    失败的是取对象/清单那条路（`upload-pack` 的 `manifest.pb`），refs 广告那条一直通。
    现象：同一时刻 `info/refs` **200**、`ls-remote` **rc=0**，而 `git fetch` **rc=128 + 500**。
    ⇒ ① **恢复判据 = fetch（或 push）真的成功**，不是 `ls-remote` 绿；
    ② 车道遇到 `--push` 失败**先原样重试一次**（多能过），仍失败再报障；
    ③ 故障期改为**本地签（`entry` 不带 `--push`）**，恢复后统一推，并逐个核 `unpushed: 0`
    ——「本地有机上有效、远端没有」是真实会发生的。
15. **变异脚本的安全**（2026-10-26 一晚三起事故的收敛）：变异工具**本身**必须安全，否则「工具把靶子弄坏」事后极难归因。
    - **先算内容、再开文件**：`open(P,"w").write(mutate(kind))` 会**先截断**再求值 `mutate`（当晚把 `lib.rs` 清成 0 字节）。
    - **变异前后都断言 blob**：`git hash-object <file>` 前后相等；还原不一致即判该轮作废，**不得继续用其结论**。
    - **搬别人的 WIP 前先 `grep -n MUTATION`**：当晚把带变异残留的补丁从主检出搬进他人 worktree。
    - **破坏性牙必须以假根为靶**：当晚夹具 selftest 拿真实生产根当靶，把刷怪行写进生产 `EnGen`。
    三起的共同点：**破坏由「工具」造成，而结论看起来仍然成立**。

16. **自测只允许断言合成夹具上的行为**（2026-10-26 一晚三次的收敛）：
    - **夹具必须先自证不变式**（如「`side` 必须是 HEAD 的非祖先」），**不符 ⇒ 判不了（NEED/rc=2），不判红**；
    - 禁止让自测断言**真实仓库状态**（「当前没有未分类工具」「本仓有/没有某分支」「本仓的祖先关系」）——仓库一变，门就先红；
    - **判据要造出被检查的状态**（注入污染再断言清洗结果），不许只断言「结果长什么样」（否则清空实现仍绿）。
    三次实例：`dbsnap` 连不上库报 10061（当红）、`selftest_build_*` 断言真实仓库、`docs_delivery_gate` 的 HEX/N1 依赖**夹具祖先关系**。
    > **订正（2026-10-27）**：本条最初把第三个实例归因成「并行 cargo 下 25 次里 3 次误红」，**归因错了**。
    > 真根因是**夹具生成的 hex 前缀可能全是数字**（约 0.8%/个；9 位时约 1.5%）⇒ 整组 hex 用例**静默不触发** ⇒ 表现为随机假红，
    > 与负载无关。修法是 `_hexref()`（保证前缀含 a–f，取不到则 `GitUnavailable`），修复后 60 次连跑 0 失败。
    > **教训**：把概率性夹具缺陷说成「并发/慢盘」，会让人去查一个不存在的竞态。

17. **oid 一律脚本取、签后回读**（2026-10-27 实证）：条目 body 里的 `head` / `base` / `refs.*` / `reviewed_head`
    **三视图零校验**（与 `--parent` 孤儿同族）—— 写错了没有任何东西会报。
    当晚 reviewer-20 签 `request_changes` 时只掌握 10 位短号，**手补了后 30 位**，于是 `head` 指向一个
    **不存在的对象**（真实提交与它前 9 位相同）。因为是 `request_changes`，写错只会加强结论、没造成误放；
    **若发生在 `approve` 上，合并记录会指向空气而全绿。**
    ⇒ 凡 body 里要写 commit oid：`git rev-parse <short>` 取全号 + `git cat-file -t` 验类型，**禁止手补/截断拼写**；
    签完**回读**一次自己的条目。短号本身不是问题（能解析就该过），**空串与臆造的长号**才是。

18. **修一个判据时，先问「这次修法本身能不能被用来绕过判据」**：修法引入的新原语往往就是新的假绿入口。
    实例：为让「无 PowerShell 的机器不判红」而给自测框架加 `skip()` —— 作者证明的是「无 PS ⇒ 走 SKIP 且 rc=0」，
    但**没证明「SKIP 不掩盖真 FAIL」**；若不补这条反向牙，F1 的修法就是**新的绕过口**而不是修复。
    ⇒ 卡面验收里必须有一条「新原语的反向用例」，由审查者自造，不采信作者自述。

19. **每颗新牙必须回答「退化输入时还能不能红」**（2026-10-27 一晚五起的收敛）：
    统一判据 —— **把被保护的那一层换成等价劣化实现，若测试仍全绿 ⇒ 牙附着的不是那条链路**。
    - **空集合 / 0 次调用 / 输入退化 ⇒ 必须红或判不了，不能空过**。实例：T2 的垫片断言写成
      `len(lines) <= 1`（只有上限）⇒ 垫片 0 次调用时三条断言全空过；`discover` 扫到 0 个工具仍绿；
      `startswith('')` 恒真；`mir_flow.selftest.ps1` 153 条断言无人跑。
    - **「位置移动」的正解不是钉行号**：契约是「守卫在路径上**被执行**」。上移一行、语义不变 ⇒ **不该红**
      （钉行号是坏牙，与 HIGH_CHURN 禁行号锚同理）。要红的是「挪离路径」：`if False:` 包住、`try/except: pass` 吞掉。
    - 交付时**逐颗列出「劣化实现 → 红/绿」**，不许合成一句「均已验证」。

20. **软化通道自己也是判据面**：为了「不判红」而开的口子，必须有反向牙，否则它自己就是空集过口。
    `legacy: true`（登记豁免）、`--skip`（跳项）、`allow-unclassified`（白名单）、`state=NEED`（判不了）
    都算。判据：**只标不写理由 / 全部跳过 / 该判红却只写 state ⇒ rc=2 或红**。
    实例（正面）：`blocked-token-rot` 里 `legacy: true` 但没有非空 `legacy_why` ⇒ **rc=2**。
    实例（反面）：`whitelist-card-link-debt` 的 `LEGACY_MARK_RE = r"\blegacy\b"` 太松 ——
    正文里写一句「本行描述 legacy 减法行为，没有卡号」就让盲区消失（`unowned=[]`、条件② pass）。
    - 推论：**红必须机器可见**。判红却只写 `state`/`detail`、不进 `fail_items` ⇒ `--json` 消费者与
      缺口明细表都看不到它 —— 一条机器看不见的红等于半条红。

21. **签条目时 body 一律走文件，不在命令行内联**：`--body "…`…`…"` 里的反引号会被 shell 当命令替换
    （2026-10-27 一晚两起：dev-2 的第一个键被吃掉、tester-1 的 patch 正文反引号被吃）。
    做法：JSON 写进临时文件，`--body "$(cat <file>)"`；签完**回读**条目确认字段没缺。
    与规则 17（oid 一律脚本取、签后回读）同源：**条目的可复算性建立在「写进去的就是我以为写的」之上**。

22. **报告状态前先 fetch + 读线程尾**（2026-10-27 一晚三次）：凡「我已交付 / 待你合 / 卡已关 / 分支还在」这类陈述，
    必须基于**刚 `git fetch` 过的线程尾**，不许凭上一轮记忆。
    - 实例：dev-2 报「两张都待你合」，其中 `runbatch` 早已合并关账、分支已删；我自己漏看 dev-1 已退出车道，
      仍按它「待认领」去派卡；按旧 tip 判「锚漂移」把已修的东西又判一次。
    - 同源：**同一份看板/线程在不同 principal 眼里会不同步**，而 `walgit` 不会替你合并这些视图。
    写进交付或汇报前，先 `git fetch walgit '+refs/collab/inbox/*:refs/collab/inbox/*'` 再读尾条。

23. **collab 条目的 base/head 在 `entry.refs`，不在 `entry.body`**（卡 `openmir2-refs-head-guard`）。
    thread 视图每条 = `{entry:{actor, body, id, kind, parent, sig, ts, version, refs}, oid, principal, verified}`，
    **只有 patch 有 `refs`**，形如 `refs={"base":"<40-hex>","head":"<40-hex>"}`。

    **为什么必须写死这条**：读错字段不会报错——`entry["body"].get("head", "")` 取到**空串**，
    而 `"任何 head".startswith("")` **恒真** ⇒ 「钉住 commit」的守卫**恒通过且看不出异常**
    （reviewer-21 2026-10-26 自曝）。这是「恒真谓词」最纯的原型。

    **取值一律走工具，不手写**：`tools/collab/entryrefs.py`
    ```python
    from entryrefs import require_head, require_base, head_matches
    head = require_head(item)              # 缺 refs.head / 空串 / 非 40-hex ⇒ EntryRefError
    if not head_matches(item, current):    # 相等比较；current 也必须是 40-hex
        ...
    ```
    **可直接跑的自检**（确认某条 patch 的 head 真的可读）：
    ```sh
    walgit collab thread <thread-id> | python -I -c 'import sys,json; d=json.load(sys.stdin); print(d[-1]["entry"]["refs"]["head"])'
    ```
    反模式扫描：`python -I -B tools/collab/entryrefs.py --lint <thread.json>`（列出 body 里出现 base/head 的条目）。

24. **签 review 前先看「patch 之后有没有 merge_result」**（2026-10-27，reviewer-21 自曝）：
    只查「patch → review」这一条路径是不够的——主检出可能在你的 review 签出**之前**就合并了，
    于是你的 approve 变成对已合并头的确认，而不是合并前置。
    ⇒ 签之前 `git fetch` + 读线程尾：有 `merge_result` 就按 **`post_merge` 口径**写（注明「对已合并 head 的确认」），
    不要让它看起来像是你为合并开了门。与规则 22 同源：**视图不同步，walgit 不会替你合并**。

25. **先写清前提，再造一个「跨前提」的负例**（2026-10-27，tester-1 的两步自查）：
    ① 把结论成立的**前提**写出来（单锚/多锚、计数只增/可减、有 PS/无 PS）；
    ② 造一个**跨过该前提**的负例去撞它。
    实例：`EXCLUDED < 现值` 的判据在「单锚」下成立（排除后该类为空 ⇒ rc=2），
    但**多锚**下不成立（还剩一处活锚 ⇒ 错的数字被「历史」藏起来仍 rc=0）。
    ⇒ 「证明了一个方向，就把同一结论套到相邻情形」是当晚最贵的错误，成本是一次 complete 返工。

26. **凡「用文本特征跳过」的判据，被跳过的值必须落在可证区间**（2026-10-27）：
    只保证「不许清零」不够 —— 要保证「被跳过的值本身可信」。
    实例：`**历史**：` 前缀能让机器不看那处数字 ⇒ 伪造者把错的当前值挂上去就过关；
    修法是「排除项必须严格小于现值」（计数只增的前提下零误伤），并**要求判定与数字同行**
    （否则「假锚放上一行、真数字放下一行」照样绕）。
    同族：`LEGACY_MARK_RE` 被一句散文穿过、`BLOCKED_TOKENS` 只朝一个方向看。

27. **卡面上写「唯一处 / 只在」之前先普查**（2026-10-27 一晚三例）：
    「`sell_off_sessions.remove` 全仓只在 `close_cleanup_residue`」（实际另有交易路径 3 处）、
    「`BLOCKED_TOKENS` 只校验缺 absent/source」的反方向从没被查、
    「T-50 行内引用的卡就是它的 owner」（那是承接卡，且实体卡号还不在看板上）。
    ⇒ 写卡时把「我看到的那一处」当成「唯一的一处」，会让后来的实施者**按错的一半推理**。
    要求：写这类断言时给出**普查命令与输出**（`grep -n` 全文），而不是一句「只有」。

28. **「变异不红」必须先证明「那次跑真的跑了用例」**（2026-10-27，dev-2 的 M-12 假绿）：
    选错包（`-p mir2-world` 而用例在 game-svr）时输出是 `test result: ok. 0 passed; 0 failed` ——
    看起来「牙不承重」，其实是**一个用例都没跑**。
    ⇒ 判据：**只有断言出 `passed + failed >= 1`，才能把「没红」解释成「牙没咬」**。
    与 `cargo test --bins 假绿` 同族，但更一般：**任何「不红」的结论，先证「跑了」**。

29. **改共享文档必须 `newline=""`，提交前跑 `git diff --check <base> <head>`**（2026-10-27，tester-1 实测）：
    `io.open(p, "w")` 在 Windows 上会把整份文档转成 **CRLF** ⇒ `git diff --check` 把 128 行判成
    trailing whitespace，整棵树看起来像被改烂。与「Write 工具可能写 CRLF」是同一形状、不同触发点
    （Python 文本模式）。⇒ 写文件一律 `newline="\n"`；**提交前**跑一次带范围的 `git diff --check`
    （无参数只查未提交改动，会伪绿）。

30. **变异必须在「交付的那个 head」上重放**（2026-10-27，dev-2 的 F2 自述）：
    作者的 M5 变异是在**交付前那棵树**上跑红的；改完补丁后没在交付 head 上重放，就把「red=True」写进了 patch body。
    复审在交付 head 上重放 ⇒ **0 红**（`mir2-world 711` + `game-svr 1548` 全绿），那条分支实际上**完全没有牙**。
    ⇒ **写「变异红」而实际不红，比不写更糟** —— 它让后来者以为那里有守。
    与规则 15（变异脚本自身安全）、规则 28（不红先证跑了）同族：**证据必须属于它所声称的那个对象**。
    落地动作：签 patch 前，把每条变异的 head 显式写成「在 `<sha>` 上重放」；改了任何一行就重放一次。

31. **不许「为了变绿而改前提交互」**（2026-10-27，M-3 的 F6）：
    某用例删掉 `assert_ne!`、并把「重进」改成「先 disconnect 再重进」—— **恰好绕开**了当时正在修的泄漏路径（软关后不 disconnect 直接重进）。
    断言看起来还在、覆盖却没了。这比「放松断言」更隐蔽，因为 review 里的 diff 只显示「测试改了」。
    ⇒ 审「修 bug 的卡」时，凡见到**测试的交互/前置被改动**，都要问一句：**它绕开的是不是正在修的那条路径？**
    正确做法：交互改回去，让用例覆盖真实路径；确实无法构造时，显式登记「该路径无用例 + 理由」。

32. **Leader / reviewer 给的「更好理由」也是假设，不是证据**（2026-10-27，一晚两次）：
    采纳前必须在**具体那份实现**上核一遍，就像核作者的自述一样。
    - 实例一：我要求给 `add_to_mapped` 补一条「`enter_map` 落格失败但保留的角色，C# 同样不列」——
      作者去读了 golden harness，发现 `ApplyEnter`（`Program.cs:536-543`）**无条件** `RegisterActor`、
      不看 `AddMapObject` 的返回值 ⇒ 那句话对**这份 harness** 不成立，被挡在 patch 之外。
    - 实例二：reviewer 把 `UserProcessor` 的定时器间隔记成 `:6`，实际 `:7`。
    - 共同点：两条在 oracle 语义上都「说得通」，难的是**对具体实现成立**。
    ⇒ 没有证据的「更硬的理由」比没有理由更危险 —— 它让 patch 看起来更强，实际是把假设写成了事实。

33. **读入接缝比逻辑更脆：先看同类工具怎么读同一份数据，再给接缝一颗「真数据形态」的牙**（2026-10-27）：
    - 实例：新门 `scenario_manifest_gate` 按 `{"entry": {...}}` 嵌套读 collab blob，
      而 **blob 是扁平的**（顶层 `actor/body/id/kind/...`，`entry` 包层只存在于 `walgit collab thread` 的输出里）
      ⇒ 11,519 条全是 `kind=None / body={}` ⇒ **主判据在真实树上一次都没运行**，而门看起来是 GREEN。
    - **仓库里本来就有正确写法**：`board_coverage_gate._entry_of()` 的注释写着
      「Inbox blobs are the signed entry itself; `collab thread` wraps them … **Accept both shapes**」。
      ⇒ **写新工具前先 `grep` 同类工具怎么读同一份数据**，别各自重踩。
    - 牙的形态：**用真形态的数据喂真路径** —— 临时 git 仓库 `hash-object -w --stdin` 造扁平静态 blob、
      `update-ref` 到 `refs/collab/inbox/…`，再走真正的 `read_collab()`，断言「条数对 / kind 非空 / 取到的名字对」。
      只喂 `(tid, kind, body)` 元组是**绕过接缝**，对这类 bug 零覆盖。
    - 作者自述：「我三次把『工具在我手上跑绿了』当成『判据在真实树上成立』。」——**接缝牙 > 逻辑牙**。
