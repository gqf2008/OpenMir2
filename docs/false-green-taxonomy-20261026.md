## 二、五条正面规则

1. **修失效模式的卡，验收必须复现原失效场景**——不是「新代码看起来对」。实例：并集 discover、`run()` 接线、第 8 项位置。
2. **每个关键谓词都要有负例**——没负例时删掉它测试仍全绿。逐分支、逐档位各一颗，一颗不许覆盖两支。
3. **汇总层要单独钉**——单项 state 对，不代表 `overall` 汇总对（`judge_gate_checks` 的 NEED 分支变异）。
4. **任何「0」必须附扫描对象数与时间窗**——「0 个问题」在空集上恒真。
5. **写命令前先读用法**——`--help`/`param` 块。凭印象写 flag 得到的是「看起来能跑」。

## 三、当晚代价最高的两次误判（我的）

- **两次宣布「开窗前置全绿」都早了一步**：第一次只核了门禁，漏了判据可执行性（P1/P2/P4）；第二次没跑 `run_batch --dry-run`，漏了 `binary_stamp`/`start_rust_exe`/`pin_smoke` 三项 FAIL。
- 教训：**「我核过的」不等于「该核的」**。宣布就绪前，必须问「开跑那一刻按什么顺序发生什么」。
