## 0. 总判断：纪律好、盲区系统

计划的**纪律层是好的**：§6.0 五条 DoD（可测/可证伪/白名单/证据四件套/不夹带，`docs/Rust重写设计文档.md:245-264`）、R/L 判据分级（§17.1:701-707）、白名单制、双轨记账（§17 状态表 + 看板 closed）。

但有**三个系统性盲区**：

1. **内容加载面从未对账**：设计文档全文对 Envir 内容文件零承诺（MiniMap/MakeItem/GuardList/Npcs/MapEvent grep 0 命中）；oracle `GameApp.cs` 有 11 处 Load\* 调用点（:105/108/118/147/162/166/174/182/204/227/229/231/233/241）。
2. **协议覆盖面只对账过「八阶段抓包」**：M0 判据③的口径是「抓到的包号未实现=0」（§6:272），**不是 oracle case 全集对账**。
3. **判据自身从未被验证**：§6.0-2 只要求判据「能证伪（红检）」，未要求判据「读的方向/对象正确」——RED-1（`check_attack_observability.py` 把入站受击读成出站伤害，片68 修）与本次审计实锤的掉落采集降格是同一模式。

## 2. 判据加固清单（RED-1 教训普遍化）

1. **阳性对照条款**：enter-gaps 的 `SM_STRUCK` 判据至今**没有任何 victim=怪 的阳性样本**——「无阳性对照的判据 = 未校准的判据」；W0 先由 C# 侧打出样本，此前两侧 GREEN 结论不得引用。
2. **掉落判据隐式降格（实锤）**：比对器本体健康（`drop-exp/drop_exp_diff.py:129-178` 真跨侧按 k 对齐 + 逐槽位 + Counter；fail-closed；i32 截断必红），但真机采集器 `src/BotSrv/MShare.cs:851-863` 每件只写 `{name,count:1}` ⇒ `drop_key` 的 **index/dura/dura_max 真机永不采集**，「100 杀掉落逐项相同」实跑口径 = 名称多重集 + 槽位顺序。二选一显式裁决：(a) BotSrv 扩采 `SM_ITEMSHOW` 字段（走 T-50 式白名单）；(b) 判据文档显式降格声明。**不许维持隐式降格**。
3. **quest 判据链三重阻断**：markers 前缀已修（`350cb923b`）；仍未修：② C# k=0 frame 事件 JSON 截断（采集器写坏 JSON）；③ `quest_state.jsonl` 无生产者（全仓 grep=0）⇒ 不修则 quest 窗口必 PREREQ 空转。
4. **跨侧判据通用规约**：帧类断言必须带方向字段（who→whom）；同序列对齐键 + 断号/缺件即红；selftest 必含「构造反向样本必红」牙。
5. **时钟源声明**：`scoped_diff --canonical` 的已知 RED `characters_ablity.Hp` 根因 = 系统计时器量子差（两侧攻击间隔同为 503.7ms，但体力回收 C# ≈47.9/s vs Rust 40.0/s；探针 `PeriodicTimer` 实测 ≈44/s 落在两者之间）⇒ 任何含时间语义的判据必须声明时钟源；须 owner 裁决（时钟注入接夹具 vs §6.0-3 白名单，卡 `openmir2-m3-scoped-diff-ability`）。

## 4. 「完成」定义修订建议（§6.0 增补六条）

1. **内容文件对账门**：oracle `GameApp.cs` 全部 Load\* 调用点 × 部署 `E:/MirServer/M2GameSvr/Envir` 文件 × Rust 实现三方对账表；「oracle 加载 ∧ 部署有文件 ∧ Rust 无 ∧ 无卡」= **自动红**。本报告 §1-R0 即该门第一批输出。
2. **协议派发对账门**：`msgcodegen --check` 增「派发覆盖率」报表——oracle `PlayObject.Message.cs` case 全集 vs `bins/game-svr` match 臂，双向（入站派发 + 出站 RM→SM 编码器）；缺口要么实现要么有卡，**不许「客户端发来只记日志即丢」**。
3. **判据自身验证条款**：每个跨侧判据必须 (a) 有阳性对照样本；(b) 帧类断言带方向字段；(c) selftest 含反向样本必红牙。
4. **采集面完整性条款**：「字段级 diff=0」类判据须登记**采集字段清单**并与比对器字段表对账；采集不到的字段要么补采、要么显式降格声明。
5. **时钟源条款**：含时间语义的判据必须声明时钟源与实测分辨率。
6. **项目级终点定义**：原文**没有**「项目何时算完」的条款（M5 是最后里程碑但无终验条目）——建议补：「M0–M5 全部按 §6.0 验收 + §4-1/2 对账门全绿 + 全部 R 级卡以真机对拍收口转 closed」。
