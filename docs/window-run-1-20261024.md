## 6. RNG 流位类差异归因规则（owner 2026-11-02 裁决「丙」）

> 适用对象：真机窗口对拍里**只由随机转身/随机分支帧**造成的差异。本节是**判读口径**，不是通过判据：
> 不得据此把任何未对拍项写成通过，也不得把真实行为差异洗成 flaky。

### 6.1 判定条件（必须全部满足；缺一条即不得归入本类）

1. **差异形状只能是有限个完整的「10 紧随 41」对**（可机判；任一形状不成立 ⇒ **FAIL**）：
   - 对齐两侧帧序列后，差异块只能由 `m`（m ≥ 1）个完整的 `(SM_TURN(10), SM_FEATURECHANGED(41))`
     对构成：这 2m 帧只在**同一侧**成对出现，且每个 `10` 的**紧邻下一帧必须是 `41`**；
   - 对齐后的其余帧（公共前缀 + 公共后缀，例如末帧 `SM_MERCHANTSAY(643)`）必须**逐字节相同**；
   - 两侧帧数差必须**恰为 2m**（一侧多 2m、另一侧 0），且所有对齐块位移必须能被这 m 个对**完全解释**；
   - 不允许其它 ident 的多出/缺失、非成对的单帧（只有 `10` 没有 `41`，或反之）、或非随机帧的相对次序差。
2. **两侧机制同构，且能给出可复核的路径/符号锚**：
   - 随机转身/随机分支的**抽数次数、顺序、模数**在两侧完全一致，且随机源都是进程级共享 RNG
     （Rust 固定种子；oracle 墙钟播种）。
   - Merchant 有两条同构实现，须按本案例实际执行路径取证：
     - `MerchantList` 路径（run1 的〖庄〗）：oracle `src/GameSrv/Npc/Merchant.cs:132-135`
       （`Random(50)==0 ⇒ TurnTo(RandomByte(8))`；否则 `Random(50)==0 ⇒ RM_HIT`）；
       Rust 对应 `mir2-rs/crates/world/src/merchant.rs` 的 `merchant_run`
       （`random_below(MERCHANT_TURN_RANDOM_MOD)==0` 分支）。
     - 固定 NPC 路径（Npcs.txt）：Rust 对应 `mir2-rs/crates/world/src/npc.rs` 的 `merchant_body_run`
       （oracle 同为 `Merchant.Run`）。
   - GuildOfficial：oracle `src/GameSrv/Npc/GuildOfficial.cs:41-49`
     （`Random(40)==0 ⇒ TurnTo(RandomByte(8))`；否则 `Random(30)==0 ⇒ RM_HIT`）；
     Rust 对应 `mir2-rs/crates/world/src/npc.rs` 的 `guild_official_run_body`。
   - HIGH_CHURN 文件（`mir2-rs/crates/world/**`、`mir2-rs/bins/game-svr/**`）**不写行号锚**；
     以上述**路径 + 符号名 + 代码原文**复核，避免行号随文件增长漂走。
3. **差异必须能归因到会话起点的 RNG 流位偏移（必要条件）**：
   - **必须**给出 RNG 账本/流水层面的同流位证据：两侧 `rng-stream.tsv` 的对齐/偏移量，或
     `site + Next(max)` 序列的公共后缀，且能显示两侧执行的是**同一抽数序列**、只是起点偏移；
     本仓 rng_trace 的 site 只到文件级，须附**静态唯一性牙**（该 site 在文件内唯一），否则判 **UNDECIDABLE**。
   - 或给出**受控同流位重放**：把两侧会话起点校准到同一流位后重放，结果 `diff=0`。
   - 「同类场景在另一时刻 `diff=0`」只能作为**补充旁证**，不能单独支撑归因：它只证明该轮结果不确定，
     一个只在特定抽数/批次暴露的真实实现差异同样满足它。
4. **证据完整**：原始 RNG 流水与两侧 `frames.ndjson` / `run.json` 全部保留（见 6.2），不得只留结论。

形状不满足条件 1 ⇒ 判 **FAIL**；机制或归因证据不足（条件 2、3）⇒ 判 **UNDECIDABLE**；两者都不得归入本类。
