# 内存段报告模板（A8-trend / A8-conclusion，2026-11-15）

用途：凡是压测报告里出现 **LOH / GC / 内存健康** 字样，必须从本文件拷对应模板段，不得自创口径。
判据定义见 `docs/capacity-model-20261114.md`「内存判据两档」；窗口项（前置/命令/判据六字段）的模板是 `docs/window-criteria-template.md`，与本文件不同；归因示例见
`docs/botsrv-loh-attribution-20261115.md`。

三件事先写在最前面：

1. **`A8-trend` 是趋势，不作结论。** 日常轮次只能报趋势三件套。
2. **LOH 数字必须来自连续 counters 流**（全部 samples），不能拿端点两次差当速率。
3. **单轮 360s 判内存健康不可靠。** 要下结论必须用 `A8-conclusion`（爬坡后 ≥2 个 Gen2 after-GC 点）。

---

## 模板 1：`A8-trend`（日常轮次，复制即用）

```markdown
### A8-trend（趋势，不作结论）

- 数据：`<counters.csv>`；样本 **n=<N>**（每个计数器）；跨度 **<S>s**；t0=`<ISO 时间>`。
  采集目标：`process=<进程名> pid=<PID> start=<ISO>`（采集时记录；缺此字段 = 口径不可证）。
- LOH Size（MB=10^6）：爬坡末端(60s) 单点 **<X>MB** → 末 **<Y>MB**；
  **爬坡后端点变化 <±D>MB / <T>s = <±R>MB/s**。
- WS 尾段斜率（BotSrv，末 60s）：**<±W>MB/s**（取 `mem.ndjson` 的 `proc=BotSrv` 段）。
- OLS 斜率（供交叉核对）：稳态前 240s(60–300s) **<r1>MB/s**；后段(60–末) **<r2>MB/s**。
- Gen 2 GC 时刻（rate>0，共 **<K>** 次）：`<t1>s / <t2>s / ...`（若 0 次写「无」）。
- Allocation Rate：mean **<A>** / median **<M>** / p95 **<P95>** / max **<MX>MB/s @ <t>s**。
- **判读：趋势，不作结论（A8-trend）。** 不下「内存健康/恶化/修复」结论；
  不得用本段替代泄漏结论。
```

落地要求：

- 三件套缺一不可：**LOH 端点变化 + 稳态单点值 + WS 尾段斜率**。
- 「斜率」必须写窗口（例：60–300s、60–末、末 60s），不能只写一个数。
- 若 counters 没有采集目标（pid），在段落后追加：
  `> 口径缺口：counters 未在采集时记录目标进程；以上数字的实例归属未证。`

可复算命令：

```bash
python -I -B tools/botload/counters_series.py <counters.csv> [<counters.csv> ...]
```

工具输出与本模板同字段；`--json` 便于自动拼装。

## 模板 2：LOH 数字的取数声明（必须随任何 LOH 数字出现）

```markdown
> LOH 取数口径：来自 `dotnet-counters` 连续流（`LOH Size (B)` 每计数器 **n=<N>** 个采样，
> 跨度 **<S>s**，刷新 1s），不是端点两次差；Gen2 时刻表：`<t1>s / <t2>s / ...`。
> 端点值只作展示，**速率一律用窗口 OLS 或「端点变化 ÷ 窗口跨度」并写明窗口**。
```

禁止写法（会被判为口径错误）：

- 只写「LOH 从 A 涨到 B」而不给样本数/跨度/窗口；
- 用两次采样相减当「速率」，不说明 GC 时刻（端点是 GC 时机的函数）；
- 把 `LOH Size` 的绝对值当「分配量」（它是当前 LOH 大小，含存活对象与未回收垃圾）。

---

## 模板 3：单轮 360s 的结论边界（必须原样写）

```markdown
> **单轮 360s 判内存健康不可靠。** LOH 是否有稳态回收点取决于 Gen2 时机，而 GC 时机不受窗口控制；
> 本轮爬坡后 Gen2 点数 = **<K>**（A8-conclusion 要求 ≥2）。因此本报告只给 A8-trend；
> 任何「内存健康/改善/已修复」结论必须另开 `A8-conclusion` 窗口（预计 700–800s 起，实际可能更长）并报批。
```

补充（按需）：

- 若本轮恰好有 1 个爬坡后 Gen2 点：写明「有 1 个稳态 after-GC 点，**不足以**判斜率」。
- 若本轮 0 个：写明「爬坡后无 Gen2，LOH 只增不减是 GC 时机的必然结果，不是分配速率变化」。
- 泄漏与 LOH 是两个问题：泄漏结论用 WS 尾段/存活对象，LOH 结论用分配速率/GC 时机，
  **不得互相替代**（见 `docs/capacity-model-20261114.md`「泄漏结论与 LOH 是两个问题」）。

---

## 模板 4：`A8-conclusion`（只有报批的诊断窗口才能用）

```markdown
### A8-conclusion（内存健康结论）

- 窗口：`<S>s`；爬坡后 Gen2 after-GC 点：**<K> 个**（时刻 `<t1>s / <t2>s ...`）。
- 每点 after-GC LOH：`<v1>MB / <v2>MB ...`；after-GC 序列 OLS 斜率 **<r>MB/s**。
- 判据：K ≥ 2 才判斜率；K < 2 ⇒ **不可判**（写「A8-conclusion 未取得」，不得降级用 trend 代替）。
- 诊断采集（gcdump/trace）是否在本窗口内：`<是/否>`；若是，列出被污染的 tick 样本区间并剔除。
```
