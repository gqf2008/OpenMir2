## 1. 结论（一句话）

真机里客户端**进世界后**发来的命令帧（走路/攻击/说话）在 GameSvr 侧全被丢——根因**不在 GameSvr**，
而是 Rust `GameGate` 重建 `GM_DATA` 时把 20B 头的 `Socket` 硬编码成 `0`；oracle 的 `Socket` 是
**该客户端连接的 socket handle**（`SendMsg.Socket = _session.SckHandle`）。修掉后 GameSvr 的
`FindUser`（`SessionIndex-1` 命中且要求 `Socket` 相同，否则线性扫 `Socket`）才能命中该槽。

## 2. 判据链（oracle 行号，不是猜）

| 事实 | 证据 |
| --- | --- |
| GameGate 给 GameSvr 的所有命令帧共用一个 `SendMsg`，构造时就把 `Socket` 定为客户端句柄 | `src/GameGate/Services/ClientSession.cs:65-70`：`SendMsg = new ServerMessage { PacketCode, Socket = _session.SckHandle, Ident = GM_DATA, SessionIndex = SvrListIdx }` |
| 该句柄就是 `GM_OPEN` 的 `socketId` | `src/GameGate/Services/ClientThread.cs:378` `SendServerMsg(GM_OPEN, sessionId, socketId, 0, …)`；句柄来源 `src/GameGate/Services/ServerService.cs:141` `SckHandle = e.Socket.Handle.ToInt32()` |
| GameSvr 收 `GM_DATA` 时**按 [SessionIndex, Socket] 双键**找槽 | `src/M2Server/Net/ChannelMessageHandler.cs:170-198`：先 `UserList[SessionIndex-1]` 且 `gateUser.Socket != msgPacket.Socket ⇒ null`，再线性扫 `Socket` |
| 命中后才谈「已进世界」 | 同上 `:201`：`gateUser.PlayObject != null && gateUser.WorldEngine != null` |

⇒ `Socket=0` 时，Rust GameSvr 的 `UserList::find(session_index, 0)` 在任何**已进世界**会话上都落空
（槽里存的是 `GM_OPEN` 的 handle，非 0），每个客户端命令都撞「用户不存在」→ 丢弃。
客户端靠本地预测仍能移动，但服务端收不到任何指令；「看见别人 / 后续出包」因此不可能。

## 3. 改动（一片一逻辑：`bins/game-gate/**`，最小分片）

- `mir2-rs/bins/game-gate/src/main.rs`
  - `rebuild_command_frame(decoded, payload, handle, sid, session_index)`：`Socket` 由 `0` 改为 `handle`；
    `handle_frame` 把已有的 `handle` 传入（该函数签名里本来就有 `handle`，`GM_OPEN`/`GM_CLOSE` 也一直用它）。
  - 函数文档补上 oracle 行号与「送 0 会全丢」的后果，供复审直接对照。
- `mir2-rs/bins/game-gate/tests/relay.rs`
  - 进程级用例 `relays_open_data_heartbeat_and_close` 增断言：
    `datas[0].0.socket == open.socket`（命令 `GM_DATA` 的 `Socket` 必须与 `GM_OPEN` 的 handle 一致）。

**未改**：`crates/**`、`src/**`（C# oracle）、`MirClient`、表结构/脚本/数据格式、现网配置；GameSvr 侧 `UserList`
的口径本来就是 oracle 的（有 `Socket` 兜底扫），无需改。

> 写集说明：本缺陷的实现位置在 `bins/game-gate/**`（另一张卡 `openmir2-m2-gamegate` 的面）。
> 按 §16 的指派（「照 ChannelMessageHandler/TCPNetChannel 的会话→socket 绑定口径修」）由本线做这一处
> **最小分片**；已在卡内 comment 声明分片，未动 `game-gate` 的其它任何逻辑。

## 6. 观察到的间歇性失败（如实登记，未归到本片）

原始（单次）输出：`tools/m2-acceptance/evidence/s3-routing-20261011/gg-observed-flake-once.txt`。

- **与本次改动无关**：这两条用例分别断言「登录期剔除时不得出现 `GM_DATA`」与「超限帧被丢、会话存活」，
  都不触碰 `rebuild_command_frame` 的 `Socket` 字段（前者根本不会有 `GM_DATA`）；本次只改该字段的取值，不改条数。
- **疑似根因（登记，未修，超出本片）**：`game-gate` 的进程级用例用 `free_port()`（bind:0 后立即释放）
  取端口，存在 TOCTOU——并行用例可能拿到同一端口，先启动的网关占住后，另一条用例的客户端连到了对方的
  fake GameSvr。判据同 `~/.agents/rules/LESSON_并行测试临时路径须pid加原子计数构造_时钟粒度不足` 一族。
  处置建议：单开一条「测试端口分配去竞态」小卡（把监听句柄交给子进程、或让网关支持 `GatePort=0` 回报实端口）。
