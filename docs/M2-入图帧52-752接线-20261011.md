## 4. `10 SM_TURN` 的复核结论（登记，不接线）

brief §18 第 2 条曾要求「把 `10 SM_TURN` 接上」。复核金标准与 oracle 后**定案：它不是自身入图帧**：

- 金标准 #16（`port=7200 && dir=s2c` 第 16 条）的 `Recog = 0x7AC11879`，**≠** 本会话
  `ActorId = 0x7C303998` ⇒ 展示的是**同屏另一个 actor**（`msg` = `稻草人/255`）。
- oracle 里 `SM_TURN` 的唯一发帧点在 `PlayObject.Message.cs:1542`（`RM_TURN` 支），驱动来自
  `PlayObject.cs:3240` 的 `if (baseObject != this)` 可见对象循环、`BaseObject.cs:1375/1585/2742` 与
  `PlayCloneObject.cs:19` 的 `SendRefMsg(RM_TURN,…)`——**自身 `SendLogon()` 不发 `10`**。
- 金标准把它排在自身入图序尾部，是因为该 actor 恰好同屏出现。⇒ 本帧归**世界侧 AOI/同屏 actor
  同步**（S3 后半段，`GateEvent::Command` 回帧链），不在「自身进世界」链上。

`EnterWorldInputs::frames()` 已支持 `turn` 字段（编码层判据用它复现金标准 #16）；待世界侧 AOI
喂入即可，无需（也不应）在登录路径伪造一条自身 `10`。台账 `docs/M2顺序判据②-对账台账.md` §3/§4.9
